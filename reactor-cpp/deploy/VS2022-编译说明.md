# 用 Visual Studio 2022 编译（Windows 上操作，在板子上编）

程序要跑在板子（Ubuntu 20.04 aarch64）上，代码用到 Linux 的串口、socket 和 X11，所以不在 Windows 本机编，
而是用 VS2022 的「远程 Linux」功能：VS 把源码同步到板子上，调用板子上的 GCC / CMake 编译，在 VS 里看报错、下断点。
这和现在 C# 版「Windows 上发布、拷到板子」的流程一样，只是编译这一步发生在板子上。

## 一次性准备

1. VS2022 安装器里勾上工作负载 **「使用 C++ 的 Linux 和嵌入式开发」**。
2. 板子上装编译依赖（联网一次）：

   ```bash
   sudo apt install -y build-essential cmake pkg-config rsync zip gdb libsdl2-dev libfreetype6-dev psmisc
   ```

   字体已经放在工程里（`assets/fonts/`），不用装系统字体。
3. VS2022 → 工具 → 选项 → 跨平台 → 连接管理器 → 添加：板子 IP、端口 22、用户 teamhd、密码或密钥。

## 编译

1. VS2022 → 文件 → 打开 → 文件夹，选 `reactor-cpp`。VS 会读 `CMakeSettings.json`。
2. 工具栏的配置选 **「板子-Release」**（全屏、FreeType），目标机器选刚加的板子。
3. 生成 → 全部生成。第一次会把源码（含 LVGL、字体，约 60 MB）同步到板子，之后只同步改过的文件。
4. 产物在板子上：`~/.vs/reactor-cpp/<哈希>/out/build/板子-Release/`
   - `reactord`（后台服务：设备层、控制核心、程序 / 泄漏 / 标定、存储、HTTP + WS 接口）
   - `reactor-hmi`（触屏界面，旁边自动带 `fonts/`）
   - `rtu-probe`（串口只读探测）
   - `run_tests`（全部单测，一个程序）

「板子-Debug」是窗口模式、带调试信息，用来在 VS 里单步调试。

## 在板子上跑单测

```bash
B=$(ls -d ~/.vs/reactor-cpp/*/out/build/板子-Release | head -1)
$B/run_tests            # 最后一行应是「N 个用例，0 个失败，0 处断言失败」
$B/run_tests hw_        # 只跑名字里带 hw_ 的（store_ / api_ / ctl_ … 同理）
```

## 安装到运行目录

用工程自带的安装脚本（不要用「生成 → 安装」或 `cmake --install`：那样不装服务文件、配置和 `run_tests`）：

```bash
cd ~/.vs/reactor-cpp/*/src/deploy          # VS 同步过去的源码里的 deploy/
sudo ./install.sh "$B"
```

装成 `/opt/reactor/bin/{reactord, reactor-hmi, rtu-probe, run_tests, fonts/}`，配置在 `/etc/reactord/`，数据在 `/var/lib/reactord/`，
并装好 `reactord.service`、`reactord-hmi.service`。**脚本不启动、不重启任何服务。**

第一次从旧 C# 程序切换、以及之后每次升级的步骤（含安全注意事项）见 [板子联调指南.md](板子联调指南.md)：
- 第一次：§4 安装 → §5 串口核对 → §6 模拟 → §7 `switch-to-cpp.sh` 切换；
- 以后升级：§11（没有实验时才能重启 reactord；只改界面时只重启 `reactord-hmi`）。
