# 板子联调指南（C++ 新程序替换旧 C# 程序）

板子：Ubuntu 20.04.6 aarch64，带桌面（X11），用户 `teamhd`。
旧程序：`/home/teamhd/ParallelReactorProject`，服务 `reactor-hmi.service`（`run.sh` 启动）。
新程序：`reactord`（后台服务，唯一碰串口的进程）+ `reactor-hmi`（LVGL 触屏界面，服务名 `reactord-hmi`）。

按顺序做。每一节最后都有「看什么 / 记下什么」，结果按 §12 的模板发回来。

---

## 0. 安全总则（先读）

1. **实验进行中不要停止 / 重启 `reactord`，也不要重启板子。** `reactord` 收到停止信号（`systemctl stop / restart`、关机）时会**停全部加热、关全部阀门、停搅拌**（和旧程序退出一样）。只重启触屏 `reactord-hmi` 不影响控制。
2. 新程序启动时会给 8 路温控写「At=4（停输出）」——所以**切换、回退、改配置后重启，都只能在没有实验时做**。脚本 `switch-to-cpp.sh` / `rollback.sh` 会先查状态，查到有东西在动就拒绝。
3. 每次停止（单路停止、全部停止、中止程序）界面都会弹确认框，**看清楚再点确认**。「全部停止」的确认框里有「同时停搅拌」开关，默认不停搅拌。全部停止**不放空**，釜里的压力要另外放。
4. 标了 **【安全】** 的步骤会让硬件动作（加热、开阀、搅拌、充压）。做之前：釜装好并拧紧、人在旁边、知道怎么在界面上「全部停止」、知道气瓶总阀在哪。
5. 气体：本指南只用**惰性气体**（以现场接在「惰性」那一路上的为准，N₂ 或 Ar）。不要用反应气体（H₂ 等）做联调。不确定哪一路接的是什么气，先问清楚，不要猜。
6. 任何一步结果和描述不符，**停下来**，记下现象发回来，不要继续往下做。
7. 新程序**没有急停按钮**（硬件上也没有），停止只有「全部停止」和单路停止。

## 1. 前提

| 项目 | 要求 |
|---|---|
| 板子 | 能 ssh（`ssh teamhd@板子IP`）；能联网装包（只第一次需要） |
| 旧程序 | 照常能跑（回退要用）；`/home/teamhd/ParallelReactorProject` 不要动 |

## 4. 安装（不启动任何东西）

```bash
cd ~/reactor-cpp/deploy
sudo ./install.sh "$B"
```

它做的事（可以重复运行）：
- 程序装到 `/opt/reactor/bin/`（`reactord`、`reactor-hmi`、`rtu-probe`、`run_tests`、`fonts/`），上一版留在 `/opt/reactor/bin.prev/`；
- 部署脚本拷到 `/opt/reactor/deploy/`（以后从这里运行 `switch-to-cpp.sh`、`rollback.sh`、`gen-token.sh`）；
- 建 `/etc/reactord/`（配置）、`/var/lib/reactord/`（数据），属主 teamhd；
- 放默认 `hardware.json`、`api.json`（**已有的不覆盖**），写 `reactord.env`（teamhd 的 uid，用于本机入口的身份核对）；
- 装 `reactord.service`、`reactord-hmi.service`、`/etc/logrotate.d/reactord`，**不启用、不启动**。旧的 `reactor-hmi.service` 不动。

### 4.1 配置文件说明

**`/etc/reactord/hardware.json`**（JSON 不能写注释，说明放这里）：

| 模块 | 端口 | 站号 | 波特率 | 说明 |
|---|---|---|---|---|
| `temp` 温控 AI-8 | `/dev/ttyS5` | 1 | **19200** | `dpt: 1`（一位小数） |
| `stir` 搅拌 DM2C | `/dev/ttyS4` | 1 | **38400** | `trace` = `/var/lib/reactord/stir-trace.log`（每笔事务记一行，现场 run.sh 的 `PR_STIR_TRACE=1`；每天轮转，留 7 天） |
| `press` 压力 8AI | `/dev/ttyS6` | 1 | 9600 | `signal: "4-20"`，`fullScalePsi: 600`（= 4.137 MPa，变送器铭牌量程不同要改） |
| `io` 阀门 IO16R | `/dev/ttyS8` | 1 | 9600 | `energize: "open"`（通电 = 开；若点「开」反而关，改 `"close"`） |

**波特率为什么是 19200 / 38400**：`run.sh` 注释写「全部 9600」，但脚本里没有设温控和搅拌的波特率，旧程序实际用的是代码默认值 19200 / 38400。§5 先用 `rtu-probe` 核对一次；如果实际不同，改 `hardware.json` 里的 `baud`，重启 reactord（没有实验时）。

其他：全部 8N1、超时 300 ms。`"sim": true` 只有在四个 `port` 全空时才会真正进模拟；配了端口又写 `sim: true` 时 reactord 拒绝模拟、按真机跑（防止停止帧只写进内存）。

**`/etc/reactord/api.json`**（给 PC 端的 TCP 入口，格式和旧程序完全相同）：默认 `enabled: true`、端口 8080、`allowedCidrs: []`（= **只允许本机回环**，PC 连不上）、`tokens: []`（没有令牌，除 `/health` 外都 401）。开放给 PC 见 §9。触屏走 Unix socket，不受 api.json 影响。

**数据目录为什么是 `/var/lib/reactord`，不直接用旧的 `~/ParallelReactor-data`**：两个程序各写各的，回退时旧程序的数据原封不动；切换时 `migrate-from-csharp.sh` 把旧数据**复制**一份过来（文件格式相同，新程序直接接着用：事件序号接着走、当天的遥测 CSV 接着写），旧目录不删。代价：回退后旧程序看不到新程序期间产生的数据（在 `/var/lib/reactord`，可以用 U 盘拷）。

## 5. 串口逐个核对（rtu-probe，只读）

`rtu-probe` 只发「读寄存器」，不写任何东西。但它和旧程序**不能同时用同一条串口**，所以要先停旧程序。

**【安全】** 停旧程序 = 旧程序停加热、关阀、停搅拌。先在旧界面上确认 8 路都没在跑、没有程序、各釜已放空。

```bash
sudo systemctl stop reactor-hmi          # 旧程序
groups | grep -q dialout || echo "teamhd 不在 dialout 组：sudo usermod -aG dialout teamhd 后重新登录"
P=/opt/reactor/bin/rtu-probe
```

### 5.1 温控 AI-8（/dev/ttyS5，期望 19200）

```bash
$P --preset temp --repeat 3                 # 19200
$P --preset temp --baud 9600 --repeat 2     # 对照：这个应该「没有回包」
```

**看什么**：19200 那次每次都是 `OK`，8 路 PV 合理（室温附近，和温度计 / 旧屏幕一致）；9600 那次没有回包。如果反过来（19200 不通、9600 通），说明仪表是 9600：记下来，把 `hardware.json` 的 `temp.baud` 改成 9600。两个都不通：检查接线 / 站号，再试 4800、38400。

### 5.2 压力 8AI（/dev/ttyS6，期望 9600）

```bash
$P --preset press --repeat 3
$P --preset press --baud 19200 --repeat 2   # 对照：应不通
```

**看什么**：8 路读数在 0 附近（都放空的情况下 4-20 mA 原码约 3200，换算 ≈ 0 psi）。和机械压力表对一下。某路读数是负几十 psi（原码远小于 3200）= 该路变送器没接 / 断线，记下是哪几路。

### 5.3 搅拌 DM2C（/dev/ttyS4，期望 38400）

```bash
$P --preset stir --repeat 3                 # 读状态字 0x1003
$P --preset stir --baud 9600 --repeat 2     # 对照：应不通
$P --preset stir --addr 0x2203 --repeat 1   # 报警码（0 = 无报警）
$P --preset stir --addr 0x0177 --repeat 1   # 母线电压，单位 0.1 V
```

**看什么**：38400 通、9600 不通；报警码 0；母线电压合理（例如 24 V 供电读到约 240）。

### 5.4 阀门 IO16R（/dev/ttyS8）

`rtu-probe` 只支持功能码 3 / 4，读不了 IO16R 的线圈（功能码 1），这一路放到 §7 用 reactord 核对（reactord 开机时会读回阀态）。

### 5.5 收尾

如果今天不往下做，恢复旧程序：`sudo systemctl start reactor-hmi`。往下做就保持停着（§6 的模拟和旧程序同时跑也没关系）。

**记下来**：四个模块各自实际通的波特率，是否和 `hardware.json` 一致。不一致的改掉：

```bash
sudo -u teamhd nano /etc/reactord/hardware.json
python3 -m json.tool /etc/reactord/hardware.json >/dev/null && echo 格式正确
```

## 6. 在板子上跑模拟（不碰硬件）

`--sim` 用内存模拟的硬件，**不打开任何串口**，旧程序在跑也不冲突（模拟的接口配置默认不开 TCP，不占 8080）。

在板子桌面上开一个终端（或 ssh 后先 `export DISPLAY=:0`），以 teamhd 身份：

```bash
mkdir -p ~/reactor-sim && cd ~/reactor-sim
/opt/reactor/bin/reactord --sim > reactord-sim.log 2>&1 &
sleep 2
/opt/reactor/bin/reactor-hmi --server unix:$HOME/reactor-sim/reactord-run/hmi.sock
```

模拟的配置 / 数据写在 `~/reactor-sim/reactord-config-sim/`、`~/reactor-sim/reactord-data-sim/`，和真机数据分开。

**界面检查**：
- 全屏 1280×800：没有窗口边框，没被桌面顶栏 / 任务栏挡住，四边没有黑边或被裁掉的内容；
- 字体：中文是简体字形（不是方框、不是日文 / 繁体字形），数字是等宽清晰的 Inter；切到英文（语言弹窗）再切回来；
- 触摸：点按钮有反应、没有明显延迟；拖动曲线页 / 列表能滚动；点输入框会弹出屏幕键盘（数字键盘、文字键盘各试一次）；手指点的位置和响应的位置一致（不偏移）；
- 界面上能看出是模拟数据（顶栏「模拟」标识或开机事件「模拟模式」）；
- 8 路卡片、气路图、曲线页、记录页、设置页、报警页都能打开；
- 在模拟里试一次「全部停止」：会弹确认框，取消后什么都不发生，确认后 8 路停；
- 拔掉后台看断线提示：另一个终端 `pkill -f 'reactord --sim'`，界面应盖上「正在连接后台服务…」；再在 `~/reactor-sim` 里重启 `reactord --sim &`，界面自动恢复。

退出：界面终端里 `Ctrl+C`；`pkill -f 'reactord --sim'`。

**记下来**：照片或截图（`gnome-screenshot -f ~/shot.png`）、哪个页面显示不对、触摸偏不偏。

## 7. 切换到新程序 + 真机只读观察（不加热、不开阀、不搅拌）

### 7.1 切换

```bash
sudo /opt/reactor/deploy/switch-to-cpp.sh
```

脚本会：
1. 旧程序在跑时，通过旧程序的接口读状态，**有加热 / 程序 / 气路 / 搅拌 / 带压就拒绝**。旧接口没开或要令牌时读不到，会让你到屏幕上亲眼确认后加 `--force`（旧接口令牌可以 `sudo REACTOR_TOKEN=令牌 /opt/reactor/deploy/switch-to-cpp.sh` 给）；
2. 让你输入 `YES` 确认；
3. 停止并禁用旧服务 `reactor-hmi`；
4. 复制旧设置 / 旧接口配置 / 旧数据（`migrate-from-csharp.sh`：`~/.config/ParallelReactor/settings.json`、`api.json` → `/etc/reactord/`，`~/ParallelReactor-data/` → `/var/lib/reactord/`，**旧文件都不删**）；
5. 启用并启动 `reactord`、`reactord-hmi`。

`reactord` 启动时对硬件的写只有两类：温控 Ctn 自愈（Ctn < 8 时写 8）和 8 路 At=4（停输出）。阀门和搅拌只读。

**回退**（随时，没有实验时）：`sudo /opt/reactor/deploy/rollback.sh`。

### 7.2 只读观察（至少 10 分钟，什么都不按）

```bash
journalctl -u reactord -f                 # 另开一个终端一直看着
```

**看什么**：
- 日志里 `已启动（真机）`，之后每 50 帧一条「快照 #… · 温控在线 压力在线 阀门在线 搅拌在线」。四个都应是「在线」；
- 触屏顶栏**没有**「模拟」标识；
- 8 路温度和旧程序 / 温度计一致（差 1 ℃ 以内），每 1.2 s 刷新；
- 8 路压力和机械表一致（放空状态应接近 0）；
- 气路图：开机读回的阀态和实际一致（正常应全关）。事件里有一条「开机读回阀态 · 全关」；有阀门开着时屏幕会提示；
- 搅拌显示「停」，无报警；
- 报警页 / 铃铛：没有通讯失败类报警。有的话记下标题和详情；
- 10 分钟内 `journalctl -u reactord` 里没有「控制循环超时」「通讯失败」反复出现；
- 遥测在写：`ls -l /var/lib/reactord/telemetry-$(date +%Y%m%d)*.csv`，文件大小在涨；
- 看门狗：`systemctl show reactord -p WatchdogUSec -p NRestarts`，`NRestarts=0`。

**记下来**：四个模块在线情况、温度 / 压力和参照仪表的差值、任何报警原文。

## 8. 受控测试（会动硬件）

每一项做完都回到「全部空闲」再做下一项。每一项开始前在纸上记下要改的设置的**原值**，做完改回去。

### 8.1 单路加热到 40 ℃

**【安全】** 加热。釜里是空釜或允许加热到 40 ℃ 的液体；釜盖拧紧或按现场惯例敞开；人不离开。

1. 主页点 1 号釜 → 启用 → 加热，设定 40 ℃ → 开始；
2. 观察到温：升温过程中加热输出 % 有变化、温度单调上升，接近 40 ℃ 时不明显超调（< 2 ℃），稳定在 40 ± 到位范围内；
3. 1 号停止加热：**点停止 → 弹确认框 → 确认**；加热输出回到 0，温度开始下降。

**看什么**：其他 7 路没有被动到；曲线页 1 号的温度曲线连续；事件里有「开始加热」「停止加热」，来源是「触屏」。

### 8.2 阀门点动（手动阀控，无压）

**【安全】** 开阀。**先关气瓶总阀，减压阀出口压力调到 0**，放空管路通畅。这一步只听阀门动作声、看气路图，不走气。

1. 主页「手动阀控」→ 打开手动阀控模式；
2. 逐个点：惰性气源、气源 A、气源 B、排空、SV1…SV8。每点一个，听到对应电磁阀「咔」一声，气路图上那个阀变成开，再点一次关；
3. 验证规则（应被拒绝或自动处理）：
   - 气源同时只能开一路：开着惰性时再点 A，应先全关一拍再开 A（或提示），不会两路气源同时开；
   - 气源和排空不能同时开；
4. 关掉手动阀控模式，气路图应全关。

**看什么**：每个阀「点开 = 实际开」（如果反了 → `hardware.json` 的 `io.energize` 改 `"close"`）；阀号和气路图对得上（点 SV3 响的是 3 号釜的阀）；没有通讯失败提示。**记下**每个阀是否对应正确。

### 8.3 搅拌 100 rpm

**【安全】** 电机转动。釜里放好搅拌子，手离开转动部件。

1. 搅拌 → 设定 100 rpm（釜转速；电机转速 = 釜转速 × 85/38 ≈ 224 rpm）→ 开始；
2. 观察 2 分钟：转速稳定，没有异响、丢步、报警；
3. 停止：**点停止 → 确认**，电机减速停下。

**看什么**：界面显示的设定 / 状态；`/var/lib/reactord/stir-trace.log` 有新行（每笔事务一行，排查转速波动用）；搅拌驱动器报警码仍为 0。

### 8.4 全部停止

**【安全】** 加热 + 搅拌。

1. 1 号、2 号设 40 ℃ 开始加热，搅拌 100 rpm 开始；
2. 主页「全部停止」→ 弹确认框，**先点取消**：什么都不应该停；
3. 再点「全部停止」→ 确认框里「同时停搅拌」保持**关** → 确认：两路加热停（输出 0），**搅拌继续转**；
4. 再点「全部停止」→ 打开「同时停搅拌」→ 确认：搅拌也停。

**看什么**：停止后能正常重新开始加热（全部停止不锁存）；事件里有 `全部停止`；从点确认到加热输出变 0 的大概时间（应在 1–2 个周期内，约 2 s）。

### 8.5 超温切断

**【安全】** 加热到 60 ℃。

设置里有两条交叉规则：「温度 SP 上限」必须低于「超温报警」，两者最低分别是 50 ℃、55 ℃。所以测试方法是**先加热到 60 ℃，再把限值降下来**：

1. 记下原值：设置 →「温度 SP 上限」「超温报警」；
2. 1 号加热到 60 ℃ 并稳定；
3. 设置：「温度 SP 上限」改成 50 ℃，「超温报警」改成 55 ℃（先改 SP 上限，否则交叉检查会拒绝）；
4. 此时 1 号 PV ≈ 60 ≥ 55 → 应立即：弹一级报警（超温）、1 号加热输出变 0（At=4）、1 号状态「超温」；
5. 等 1 号降到 53 ℃（= 55 − 2）以下，看报警是否解除、通道怎样恢复（记下实际行为）；
6. 把两个设置改回原值（先改超温报警，再改 SP 上限）。

**看什么**：报警弹窗的文字；从改设置到输出变 0 的时间；切断期间 5 s 一次的「重发停止」是否出现在日志里；其他通道不受影响。如果第 3 步界面不让把 SP 上限降到正在用的 60 ℃ 以下，记下提示原文发回来（测试方法要改）。

### 8.6 超压联锁（低压做法）

**【安全】** 充压。只用惰性气体，减压阀出口不超过 **0.25 MPa**；釜和管路的额定压力要远高于此；人站在侧面。不确定能不能安全充压就**跳过这一项**，在报告里写「未做」。

超压报警值最低只能设到约 0.69 MPa（100 psi），实际充到这么高没必要。做法是**临时把「变送器满量程」放大 4 倍**，让读数变成实际的 4 倍，这样实际约 0.17 MPa 时读数就到 0.69 MPa：

1. 记下原值：设置 →「超压报警」「变送器满量程」（应为 4.137 MPa = 600 psi）；
2. 「超压报警」改成允许的最小值（约 0.69 MPa，界面会提示范围）；
3. 「变送器满量程」改成 16.5 MPa。此时放空状态下读数仍接近 0；
4. 减压阀调到 0.25 MPa，开气瓶总阀；
5. 手动阀控：开「惰性」气源，再开 SV1；看 1 号压力读数上升；
6. 读数到超压值时应立即：关 SV1 和三路气源（**不放空**，保持压力）、弹一级报警（超压）、1 号状态「超压」、正在进行的气路任务中止；
7. 关气瓶总阀；手动阀控开「排空」+ SV1 放空，压力回到 0；按界面提示人工复位 1 号；
8. **恢复**：「超压报警」改回原值；「变送器满量程」以 `hardware.json` 为准——**没有实验时重启一次 reactord**（`sudo systemctl restart reactord`），满量程回到 600 psi；确认放空状态下 8 路读数接近 0、和机械表一致。

**看什么**：联锁时实际压力（机械表）≈ 联锁值 ÷ 4；阀门实际关上（机械表压力不再上升）；联锁解除条件（P < 上限 × 0.98）和人工复位的实际行为。

### 8.7 泄漏测试

**【安全】** 充压到测试压力（设置 →「测试压力」，默认值须低于超压报警的 90%）。惰性气体，减压阀调到略高于测试压力。

1. 1 号（可以多路）→ 泄漏测试 → 开始；
2. 程序自动：充压 → 平衡（默认若干分钟）→ 测量 → 判定 → 结束（是否放空看结果页说明）；
3. 等结果页：通过 / 不通过、泄漏率 psi/hr。

**看什么**：充压过程阀门动作合理（只开惰性 + 对应 SV）；结果页数值；`/var/lib/reactord/leak/` 下有本次的逐点数据；中途试一次「中止」（**弹确认 → 确认**）也可以。

### 8.8 一个短程序

**【安全】** 加热 + 搅拌（不含充压步骤）。

1. 程序页新建一个程序：加热 40 ℃ → 保持 3 分钟 → 搅拌 100 rpm → 结束（不要放充压 / 换气 / 反应步骤）；
2. 下发到 1 号，开始；
3. 跑程序期间试着手动改 1 号加热：应被拒绝（「通道被程序占用」类提示）；
4. 等程序跑完，看记录页：这次运行的记录、曲线、事件；
5. 再跑一次，中途中止（**弹确认 → 确认**），看中止原因是否记下。

如果前面 8.6 / 8.7 都做了且没问题，可以再做一个带「换气」（惰性，低压）步骤的程序，同样的安全要求。

## 9. PC 端连接测试

1. 在板子上生成令牌（明文只显示一次，抄到 PC 端；**不要发给我、不要写进报告**）：

   ```bash
   sudo /opt/reactor/deploy/gen-token.sh PC-1 operator --apply
   ```

   `--apply` 会把 `{name, sha256, role}` 加进 `/etc/reactord/api.json`（先备份）。不加 `--apply` 只打印，手工加。
   如果切换时迁过来的是旧程序的 `api.json`，原来 PC 端用的令牌继续有效，可以不生成新的。
2. 打开 PC 所在网段：编辑 `/etc/reactord/api.json`，`allowedCidrs` 写 PC 的网段或单个地址，例如：

   ```json
   "allowedCidrs": ["192.168.1.0/24"],
   ```

   确认 `"enabled": true`、`"httpPort": 8080`。检查格式：`python3 -m json.tool /etc/reactord/api.json >/dev/null && echo 格式正确`。
3. **没有实验时**重启 reactord 生效：`sudo systemctl restart reactord`（改 api.json 不会自动生效）。
4. 防火墙：`sudo ufw status`，如果是 active：`sudo ufw allow from 192.168.1.0/24 to any port 8080 proto tcp`。
5. 在 PC 上先测通：`curl http://板子IP:8080/api/v1/health` → `{"ok":true,...,"simulated":false}`；
   PC 端程序里填地址 `http://板子IP:8080` 和令牌，连上后应看到 8 路实时数据。
6. PC 端「申请控制」→ 触屏弹出允许 / 拒绝框 → 点允许 → PC 端做一个无害操作（例如启用 / 停用一个空闲通道）→ PC 端释放控制，触屏回到本地控制。
7. 拔掉 PC 网线（或关掉 PC 程序）：触屏上控制权在心跳超时后回到本地（`onRemoteLost: keep` = 不停任何东西）。

**看什么**：401（令牌错）/ 403（不在白名单）的提示是否清楚；PC 上的数据和触屏一致；PC 端下载遥测 CSV 能打开。

## 10. 日志和数据在哪

| 内容 | 位置 / 命令 |
|---|---|
| reactord 日志 | `journalctl -u reactord -b --no-pager`（本次开机）；`-f` 实时；`--since "10 min ago"` |
| 触屏日志 | `journalctl -u reactord-hmi -b --no-pager` |
| 服务状态 | `systemctl status reactord reactord-hmi`；重启次数 `systemctl show reactord -p NRestarts` |
| 遥测 CSV | `/var/lib/reactord/telemetry-YYYYMMDD.csv`（每 1.2 s 一行，UTF-8 BOM，表头变了另起 `-1` 文件） |
| 事件 | `/var/lib/reactord/events/*.jsonl`（+ `.seq`）、`events-YYYYMMDD.csv` |
| 会话 / 泄漏 / 程序库 | `/var/lib/reactord/sessions/`、`leak/`、`library/` |
| 搅拌追踪 | `/var/lib/reactord/stir-trace.log`（每天轮转，留 7 天） |
| 设置 | `/etc/reactord/settings.json`（reactord 自己写，不要在它运行时手改） |
| 旧程序（回退用，原样保留） | `~/.config/ParallelReactor/`、`~/ParallelReactor-data/`、`/home/teamhd/ParallelReactorProject/` |

打包日志发回来：

```bash
d=~/reactor-report-$(date +%Y%m%d-%H%M); mkdir -p "$d"
journalctl -u reactord -b --no-pager > "$d/reactord.log"
journalctl -u reactord-hmi -b --no-pager > "$d/reactor-hmi.log"
systemctl status reactord reactord-hmi --no-pager > "$d/status.txt" 2>&1
cp /etc/reactord/hardware.json "$d/"
cp /var/lib/reactord/telemetry-$(date +%Y%m%d)*.csv "$d/" 2>/dev/null
cp /var/lib/reactord/events-$(date +%Y%m%d)*.csv "$d/" 2>/dev/null
tar czf "$d.tar.gz" -C "$(dirname "$d")" "$(basename "$d")" && echo "$d.tar.gz"
```

**不要**打包 `api.json`（里面有令牌的哈希）和任何明文令牌。

常见问题：
- 触屏服务起不来，日志里有「无法打开显示 / cannot open display」：图形会话还没起来时会自动重试；一直不行就在 `/etc/systemd/system/reactord-hmi.service` 的 `[Service]` 里加一行 `Environment=XAUTHORITY=/home/teamhd/.Xauthority`，然后 `sudo systemctl daemon-reload && sudo systemctl restart reactord-hmi`（只重启界面，不影响控制）。
- 触屏一直「正在连接后台服务…」：`systemctl status reactord`；`ls -l /run/reactord/`（应有 `hmi.sock`，属主 teamhd）；`cat /etc/reactord/reactord.env` 里的 uid 是否等于 `id -u teamhd`。
- 某个模块一直离线：`hardware.json` 的端口 / 波特率；先 `sudo systemctl stop reactord`（**没有实验时**）再用 §5 的 `rtu-probe` 单独读。
- 新旧程序都不想要了 / 要换回旧程序：`sudo /opt/reactor/deploy/rollback.sh`。

## 11. 升级新版本（以后每次）

1. 编译（§2）→ 板子上 `$B/run_tests` 全过；
2. `sudo /opt/reactor/deploy/install.sh "$B"`（只换程序，配置不动，不重启）；
3. **没有实验时**：`sudo systemctl restart reactord reactord-hmi`；
4. 新版有问题：`/opt/reactor/bin.prev/` 是上一版，`sudo /opt/reactor/deploy/install.sh /opt/reactor/bin.prev` 装回去再重启（同样要在没有实验时）。

只改了界面时，只重启 `reactord-hmi` 就够了，实验进行中也可以。
