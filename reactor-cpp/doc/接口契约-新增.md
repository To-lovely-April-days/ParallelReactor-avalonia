# 接口契约 · 触屏新界面要的新增部分（2026-11-26）

给 api 阶段照着实现。只写**现有 C# `/api/v1` 里没有、触屏 reactor-hmi 要调**的东西；现有端点照旧逐字兼容（设计文档 §5.3），这里只列名字。
客户端实现在 `apps/reactor-hmi/net/`（`binding.cpp` 是解析，`backend.cpp` 的 `NetActions` 是「动作 → 端点」），自检 `reactor-hmi --selftest-net` 里的假服务器按本文回数据。

## 0. 约定（全部沿用现有的）

| 项 | 规则 |
|---|---|
| 前缀 | `/api/v1`；路径参数、查询参数按 RFC 3986 编码（SSID、运行 id 可能有空格 / 中文） |
| 入口 | **本地** = 只在 Unix socket `/run/reactord/hmi.sock` 上开放，TCP 上一律 404「没有这个端点」（`RouteOptions.local_only`）；**两边** = TCP 和 Unix 都开。Unix 上身份 = 本地，不要令牌、不要租约、不限流 |
| 类别 | 写命令沿用 C / S / R 三类（控制 / 停止 / 记录，附录 §1.3）。本地入口不查租约；**TCP 上**「两边」的 C 类照旧要租约 |
| 正文 | JSON，camelCase；时间 = UTC ISO-8601（`2026-11-26T06:00:00.000Z`）；可空字段给 `null` 或省略都行，客户端两种都认 |
| 单位 | **线上压力一律 psi（表压）**，和现有接口一样；压降 psi/h；温度 °C；时长按字段名（`…Sec` 秒、`…Min` 分钟、`…Ms` 毫秒）。唯一例外：程序库条目是 PC 端文件形状，压力存 MPa（§3.7，store 的格式，不另造） |
| 成功 | 写命令外层 `{ok:true, opId, status:"confirmed"\|"accepted", result, warnings[], opEventSeq}`；`accepted` = HTTP 202，结果后到（事件） |
| 失败 | `{ok:false, opId, error:{code, message, detail?}, opEventSeq}`；**`message` 是给操作员看的中文**，触屏原样弹 toast，所以要写成一句完整的话 |
| 幂等 | 触屏给**每一条**写命令都带 `Idempotency-Key`（uuid，= opId），断线重发靠它；新端点标「必填」的缺键返回 428 `PRECONDITION_REQUIRED`，其余可选 |
| 读端点 | GET 不包外层（和现有 GET 一样直接是数据）；错误同上 `{ok:false, error}` |
| 码 → HTTP | 沿用 `ApiErrorStatus`：新码除了下表注明的，一律 409 |

新错误码（§4 汇总）：`REVISION_CONFLICT`、`NAME_CONFLICT`、`READ_ONLY`、`LIBRARY_FULL`、`USB_NOT_PRESENT`、`EXPORT_BUSY`、`CALIB_RUNNING`、`CALIB_NOT_WAITING`、`NETWORK_BUSY`。

## 2. WebSocket 和快照的扩展

### 2.1 遥测快照（WS `telemetry` 和 `GET /snapshot`）加的字段

只加不改，PC 端（System.Text.Json 默认忽略未知字段）不受影响。

```jsonc
{
  "type": "telemetry", "seq": 905512, "ts": "…",            // 原有字段不变
  "channels": [
    { "id": 1, …原有…,
      "bandC": 2.0,              // number，°C：手动定值加热的到位范围 ±（§3.3 PUT …/temperature/band）
      "antiOvershoot": true,     // bool：防超调（逼近）开关（§3.3）
      "heatOn": true             // bool：这一路的加热输出开着（定值 / 曲线 / 程序的升温都算；At=4 即 false）
    } ],
  "system": {
    "languageCode": "zh",        // string：界面语言（PUT /system/language 保存的值），zh/en/ja/ko/de/fr/es/ru
    "bootAt": "2026-11-26T00:00:00Z"   // reactord 启动时刻
  },
  "revs": {                      // 各份数据的修订号（int64，单调增；重启后可以从 0 重来，客户端只比「变没变」）
    "settings": 12,  "programs": 3, "library": 7, "runs": 40, "files": 2, "leak": 5,
    "calib": 0, "network": 9, "usb": 1, "users": 0, "device": 0, "pid": 4
  }
}
```

`revs` 每个键对应触屏要重取的数据（变了就重取，没变就不取，避免轮询）：

| 键 | 什么时候 +1 | 触屏重取 |
|---|---|---|
| `settings` | 设置 revision 变了（PATCH、档位边界、标定结果、泄漏测试时间） | `GET /settings`（revision 变了再取 `/program-schema`） |
| `programs` | 任一路的程序被 PUT / 开始运行 / 结束 | `GET /channels/{1..8}/program` |
| `library` | 程序库或模板增删改、导入 | `GET /library/programs`、`/library/templates` |
| `runs` | 运行记录新增 / 结束 / 改备注 | `GET /runs`（+ 前 20 条的 `/runs/{id}`） |
| `files` | 当天文件另起 / 新的一天 / 清理过期 | `GET /files?type=telemetry`、`…=events` |
| `leak` | 泄漏测试开始 / 每采一个测量点 / 结束 | `GET /leak-tests`、`GET /leak-tests/current/samples` |
| `calib` | 标定开始 / 每次读数 / 结束 | `GET /calib` |
| `network` | WiFi 开关、扫描完成、连上 / 断开、IP 方式变 | `GET /network` |
| `usb` | U 盘插拔、导出完成 | `GET /usb` |
| `users` | 用户与权限变 | `GET /users` |
| `device` | 设备信息 / 接线变（基本不变） | `GET /device` |
| `pid` | PID 值、来历、档位、整定开始 / 结束 | `GET /pid` |

后端暂时没给 `revs` 时，触屏退回定时刷新（30–60 s），能用但慢。

**「停用」的说明**：触屏把 `state == "idle"` 的路当作「停用」，启用 / 停用调现有的 `POST /channels/{id}/enable|disable`；`installed`（硬件装没装）照旧。

### 2.2 新消息 `progress`（S→C，两边）

订阅主题加 `progress`（`subscribe.topics` 里带它才推）。每个 Tick（1.2 s）推一次，或者有变化时推；**整份替换**：`channels` 里没有的路 = 没有程序（触屏清空那一路的进度）。

```jsonc
{
  "type": "progress",
  "ts": "2026-11-26T06:00:01.200Z",
  "channels": [
    {
      "id": 1,
      "programName": "加氢筛选-A",
      "sourceId": "P2611141620123",            // 来自程序库哪一条（没有 = null）
      "steps": [ { "type": "leak", "name": "气密检查" }, { "type": "exchange", "name": "置换" } ],  // 全部步骤；name = 中文短名
      "stepIndex": 4,                           // 0 起，同 channels[i].program.stepIndex
      "stepTarget": { "quantity": "temp", "value": 80 },   // 当前步的目标：quantity ∈ temp(°C) / pressure(psi) / time(min) / rpm / mmol；没有 = null
      "stepFraction": 0.42,                     // 当前步完成比例 0..1（不知道 = 0）
      "elapsedSec": 3600,                       // 程序已运行
      "remainingSec": 7200,                     // 约剩（反应步按「最长」估）；不知道 = null
      "gasQueueRank": 2,                        // 排队等气路时排第几（1 起）；不排队 = null
      "waitingFor": [3],                        // 在等哪几路放开气路
      "waitedSec": 95,                          // 已经等了多久
      "draft": { "editedNotSent": false, "stepCount": 0, "totalSec": 0 },  // 这一路 PUT 过新程序、还没开始运行
      "plan": {                                 // 方案甘特图 + 计划曲线；时间都是相对 t0 的秒
        "t0": "2026-11-26T05:00:00Z",           // = 程序开始时刻（未下发的草稿 = 现在）
        "segs": [ { "kind": "heat", "name": "升温", "startSec": 0, "endSec": 1800,
                    "openEnded": false, "earliestEndSec": 1800 } ],      // 反应步 openEnded = true，endSec = 最长，earliestEndSec = 最短
        "temp":  [[0, 25], [1800, 80]],         // 计划温度拐点 [秒, °C]
        "press": [[0, 0], [1800, 290.1]]        // 计划压力拐点 [秒, psi]
      }
    }
  ],
  "autotune": [ { "id": 3, "cycle": 2, "cycles": 3, "leftSec": 300, "fraction": 0.4 } ]   // 正在自整定的路
}
```

- 「已走过的实测」不用后端给：触屏从 `/trend` 自己取。
- 没有程序、也没有草稿的路不要出现在 `channels` 里。

### 2.3 报警（WS `alarm` 和 `GET /alarms` 的每一项）加的字段

```jsonc
{ "id": "A17", "level": "err", "rv": "", "channel": 7, "title": "7 号超压", "message": "…", "raisedAt": "…", "state": "active", "clearedAt": null,  // 原有
  "tier": 1,                       // 1 安全联锁（全屏）/ 2 错误（弹窗）/ 3 警告（铃铛气泡）/ 0 只是事件。缺省时触屏按 level 猜（err→2、warn→3、info→0），所以联锁类必须给 1
  "source": "channel",             // channel / comm / system
  "quantity": "pressure",          // pressure / temp / ""（没有量值）
  "value": 377.1, "setpoint": 290.1, "limit": 377.1, "rangeLo": 0, "rangeHi": 580.2,   // 量值；quantity = pressure 时 psi，temp 时 °C；没有 = null
  "did":  ["关闭 7 号进气阀和三路气源", "停止 7 号加热"],   // 系统已经做了（中文，每条一句）
  "next": ["等压力降到 2.53 MPa 以下自动解除", "确认后到主页手动复位"],   // 接下来
  "context": "程序「加氢筛选-B」第 6 步 反应",
  "downSince": null,               // 通讯类：从什么时候断开（ISO）
  "hint": "",                      // 二级弹窗的处理建议
  "highlight": ""                  // 二级弹窗里浅红底的那一行
}
```

### 2.4 触屏关心的事件 kind

触屏按事件 kind 的前缀刷新数据（有 `revs` 时只是多一层保险）并弹提示。后端要保证这几类事件的 `title` / `message` 是中文整句：

| kind | 用途 |
|---|---|
| `export.done`（info）/ `export.failed`（warn） | 导出到 U 盘的结果（`POST /export` 是 202），触屏弹 toast：`title：message` |
| `network.wifiConnected`（info）/ `network.wifiFailed`（warn） | WiFi 连接结果（`POST /network/wifi/connect` 是 202） |
| `settings.*`、`library.*`、`program.*`、`leak.*`、`calib.*`、`network.*`、`usb.*`、`pid.*`、`autotune.*`、`session.*` | 刷新对应数据 |

## 3. 新增端点

下面「类」= 写命令类别（C 控制 / S 停止 / R 记录）；「幂等」= `Idempotency-Key` 是否必填。

### 3.1 设置：`GET /settings` 扩展 + `PATCH /settings`

**`GET /settings`（两边）加三个对象**（原有 `limits / alarms / leakTest / approach / stir / pressure / tempBands / volume / revision` 不变）：

```jsonc
"ui":      { "pressureUnit": "MPa", "tempUnit": "C", "theme": "light", "keyboard": "num", "preflightChecklist": true },
"program": { "gasWaitMaxMin": 60 },      // = SettingKey ProgramGasWaitMin（C# 已有的设置项，以前没进 SettingsDto）
"storage": { "retentionDays": 90 }       // 运行记录 / 每日文件保留天数（新设置项，后端按它清理）
```

**`PATCH /settings`** — 本地；类 R（改设置不动设备，本地不受严格守卫）；幂等可选。

请求：
```json
{ "revision": 12, "values": { "alarms.overTempC": 180, "ui.theme": "dark" } }
```
- `revision`：必填，int64，客户端读到的 `settings.revision`。不一致 → 409 `REVISION_CONFLICT`，`detail.currentRevision`。
- `values`：一项或几项，**全有或全无**（一项不合格就都不改）。键 = `GET /settings` 里的 JSON 路径：

| 键 | 类型 | store 的 SettingKey |
|---|---|---|
| `limits.tempSpMaxC` / `limits.pressureSpMaxPsi` / `limits.rpmMax` / `limits.volumeMaxMl` | number | TMaxSp / PMaxSp / RpmMax / VolMax |
| `alarms.overTempC` / `alarms.overPressurePsi` / `alarms.heatTimeoutMin` / `alarms.pressDeviationPsi` | number | OverTemp / OverPressure / HeatTimeout / PressDeviation |
| `alarms.stopHeatOnOverPressure` | **bool** | （AppSettings.StopHeatOnOverPressure） |
| `leakTest.testPsi` / `leakTest.settleMin` / `leakTest.measureMin` / `leakTest.rateLimitPsiPerHr` / `leakTest.reminderDays` | number | LeakTestPsi / LeakSettleMin / LeakMeasureMin / LeakRate / LeakReminderDays |
| `approach.deltaC` / `approach.fastRateCPerMin` / `approach.rateCPerMin` / `approach.settleBandC` / `approach.settleSec` | number | ApproachDelta / ApproachFastRate / ApproachRate / ApproachSettleBand / ApproachSettleSec |
| `stir.peakCurrentA` / `stir.standbyPct` | number | StirCurrent / StirStandbyPct |
| `program.gasWaitMaxMin` | number | ProgramGasWaitMin |
| `storage.retentionDays` | number，7–3650 | 新 |
| `ui.pressureUnit` | string：`MPa` / `bar` / `psi` | 新 |
| `ui.tempUnit` | string：`C` / `F` | 新 |
| `ui.theme` | string：`light` / `dark` | 新 |
| `ui.keyboard` | string：`num` / `full` | 新 |
| `ui.preflightChecklist` | **bool** | 新 |

响应 200：`result { "revision": 13, "changed": ["alarms.overTempC"] }`（值没变的不算 changed）。

错误：400 `BAD_REQUEST`（不认识的键、类型不对，`detail.key`）；422 `PARAM_OUT_OF_RANGE` / `PARAM_CROSS_CHECK`（`detail{key, min, max, value}`，message 用 store 的 `RuleViolation.message`）；409 `REVISION_CONFLICT`。
触屏遇到 `REVISION_CONFLICT` 会重新 `GET /settings` 再发一次（只重发一次）。

### 3.2 温控 PID：`GET /pid` 扩展 + `PUT /pid/bands`

**`GET /pid`（两边）加**：顶层 `"controller": "宇电 AI-8"`；`channels[i]` 加 `tuneCycle`（int，第几次振荡）、`tuneCycles`（int，共几次）、`tuneLeftSec`（number|null，约剩）、`tuneFraction`（0..1）。整定中这四项也在 `progress.autotune` 里每 Tick 推。
`channels[i].bands[j]` 的 P/I/D 键名：触屏 `p/i/d` 和 `P/I/D` 都认（以 C# `PidBandValueSnap` 序列化结果为准）。

**`PUT /pid/bands`** — 本地；类 C（本地不要租约）；幂等可选。

请求 `{ "lowMidC": 100, "midHighC": 200, "revision": 12 }`（`revision` = 设置 revision，可省略 = 不查）。
响应 200：`result { "bands": [ {"index":0,"name":"低温","loC":0,"hiC":100}, … ], "revision": 13 }`。
错误：422 `PARAM_OUT_OF_RANGE`（store `rules::band_bound`）；409 `REVISION_CONFLICT`；409 `AUTOTUNE_ACTIVE`（有通道在整定）。

### 3.3 单路：到位范围、防超调、单路程序

| 方法 路径 | 入口 | 类 | 请求 | 响应 `result` | 错误 |
|---|---|---|---|---|---|
| `PUT /channels/{id}/temperature/band` | 两边 | C | `{ "bandC": 2.0 }`（0.5–10，同程序 `heat.band`） | `{ "channel": 1, "bandC": 2.0 }` | 422 `PARAM_OUT_OF_RANGE`；409 `CHANNEL_PROGRAM_OWNED` |
| `PUT /channels/{id}/temperature/anti-overshoot` | 两边 | C | `{ "on": true }` | `{ "channel": 1, "antiOvershoot": true }` | 409 `CHANNEL_PROGRAM_OWNED`；400 缺 `on` |
| `GET /channels/{id}/program` | 两边 | — | — | 见下 | 404 `CHANNEL_NOT_FOUND` |

两个值存进这一路的手动设定（和 TSp 一起持久化），并在快照 `channels[i].bandC / antiOvershoot` 里返回；`POST /channels/copy-config` 复制时一起带上（确认框文案「目标温度、升温方式、到位范围、防超调一起复制」）。

**`GET /channels/{id}/program`（新，C# 设计稿 §7.9 有、实现里没有）**：这一路当前的程序（运行中 = 下发时的副本）。
```jsonc
{ "seq": 905512, "ts": "…", "channel": 2, "revision": 7,
  "name": "加氢筛选-A", "sourceId": "P2611141620123",   // 下发时客户端给的；没有 = null
  "modified": "2026-11-26T05:59:00Z",
  "steps": [ { "type": "heat", "params": { "mode": "fixed", "temp": 80, … } } ] }   // §6.9 格式，压力 psi；没有程序 = []
```

**`PUT /channels/{id}/program` 加两个可选字段**：`name`（string ≤ 40，程序名，进 `progress.programName` 和运行记录）、`sourceId`（string，程序库条目 id，触屏算「正用在」）。其他不变。

### 3.4 手动阀控开关：`PUT /gas/manual`

本地；开 = C、关 = S；幂等可选。请求 `{ "on": true }`；响应 `result { "manualValve": true }`；快照 `gas.manualValve` 跟着变。
错误：409 `GAS_BUSY`（气路被程序 / 泄漏测试 / 标定占用，message 用现有 `GasBlockReason` 的中文）。关的时候顺手把手动开着的阀全关（照 C# 关手动阀控的行为）。

### 3.5 全部确认：`POST /alarms/ack-all`

两边；类 R；幂等可选。请求 `{}`；响应 `result { "acked": 3 }`（这次确认的条数）。每条照 `POST /alarms/{id}/ack` 推 WS `alarm`。

### 3.6 界面语言：`PUT /system/language`

本地；类 R。请求 `{ "code": "en" }`（`zh / en / ja / ko / de / fr / es / ru`）；响应 `result { "code": "en" }`。
存进 settings（store `AppSettings.language`，**存的就是这个短码**），快照 `system.languageCode` 带回；触屏看到变了才整页换语言。错误：422 `PARAM_OUT_OF_RANGE`（不认识的码）。

### 3.7 程序库：`/library/programs`、`/library/templates`（两边）

条目形状 = store `ProgramLibrary` 的 PC 端形状（`library/programs/<id>.json`），**压力字段存 MPa、压降 MPa/h**（schema 里 `unit` 是 `psi` / `psi/h` 的字段；触屏收发时自己换算：MPa→psi 保留 1 位、psi/h 保留 2 位，同 PC 端 `StepDefaults.ToWire`）。

程序条目：
```jsonc
{ "id": "P2611141620123", "name": "加氢筛选", "model": "PR8", "modified": "2026-11-14T16:20:00", "by": "触屏", "draft": false,
  "steps": [ { "type": "leak", "name": "气密检查", "params": { "pres": 3.0, "maxDrop": 0.0138, "onFail": "stop", … } } ],
  "revision": 3,
  "usedBy": [1, 2] }        // 只在 GET 里：现在哪几路的程序来自这一条（按 sourceId 算）；不给的话触屏自己算
```
模板条目：`{ "note", "from", "builtIn": false, "revision", "usedBy", "program": { 程序条目，不含 revision } }`，模板 id = `program.id`。

| 方法 路径 | 类 | 幂等 | 请求 | 响应 |
|---|---|---|---|---|
| `GET /library/programs` | — | — | — | `{ "count": 12, "max": 50, "items": [程序条目] }`，按 modified 倒序 |
| `GET /library/templates` | — | — | — | `{ "count": 5, "items": [模板条目] }`（内置模板 `builtIn: true` 在前） |

### 3.9 趋势：`GET /trend`（两边）

### 3.18 程序暂停 / 继续：`POST /channels/{id}/program/pause`、`POST /channels/{id}/program/resume`（两边，2026-11-29）

正文 `{}`（可省），建议带 `Idempotency-Key`。决定记录 2026-11-29：**暂停时全部停下**。

- **暂停**（停止类，同中止：远程没有控制权也放行）：本路加热停（At=4，同手动停止）、稳压停、本路进气 SV 关；
  正在用气路的步骤（气密 / 置换 / 充压 / 放空）或正在排队等气路、吹总管、跑升温曲线时，这一段安全中止（全关阀含排空、
  只释放自己的租约，同中止收尾），**继续时这一步从头重做**。例外（2026-11-29）：**气密已判定（通过 / 不通过）、正在放空**时暂停，
  继续时只补做放空，结论不变（不通过 → 放空后停止这一路），绝不重测；气密**静置 / 保压中**暂停，继续时重新静置并重取 P0
  （暂停期间的压降不算进保压）。程序持有的搅拌释放（别的程序还在用就保留并恢复其转速，
  没有了才停；操作员手动开的搅拌不碰）。步骤计时冻结。干活中的通道 `state` 显示 `wait`（报警保持报警）。
  记事件「RVn 程序暂停」（kind `program.paused`，详情带来源 触屏 / 远程（…））。
- **继续**（控制类，远程要持有控制权）：按暂停前的目标重开加热、按暂停前的转速重新请求搅拌、按原参数重开稳压，
  本步从停下的地方接着走（定时等待按剩余时间；「到温 / 到压」等条件重新判断）。报警（超温 / 超压未解除）→ `409 CHANNEL_ALARM`。
  釜还凉着（低于加热目标 − 带宽）时**先升温，到温后再重开稳压 / 再重做充压步骤**（凉的时候补满气，升温后会冲过目标），
  记事件「RVn 到温 · 稳压重开」/「RVn 到温 · 重做充压」；结果里 `waitHeat = true`。
  要重做气路步骤或重开稳压时先查气路（同下发）：泄漏测试 / 标定占着 → `409 GAS_BUSY`，气源不可用 → 对应错误码，都保持暂停。
- **暂停中出报警**（进过超温 / 超压报警，哪怕已自动恢复）→ 程序按失败结束（记「RVn 暂停中报警 · 程序失败」，kind `program.pausedAlarm`），
  不能再继续。
  记事件「RVn 程序继续」（kind `program.resumed`，详情带暂停时长、是否从头重做）。
- 结果：`200`，`result = { "rv": 1, "paused": true|false, "restartStep": bool, "waitHeat": bool }`（`restartStep` 只在真的从头重做时为 true；
  气密补做放空不算）；已经暂停再暂停 / 没暂停时继续 = 什么也不做（`200`，幂等）。
  没有程序在跑 → `409 CHANNEL_STATE_INVALID`；通道号不对 → `404 CHANNEL_NOT_FOUND`。
- 快照：`channels[i].program` 与 `GET /channels/{id}/program/run` 的 `run`：暂停中 `state = "paused"`（新值；`running` 仍为 true，
  仍算 `programOwned` / `hasActivity`，全部停止照样把它标成手动停止），新字段 `paused`（bool）、`pausedAt`（UTC，没暂停为 null）、
  `pausedBy`（来源，没暂停为 null）。`stepElapsedMin` / `remaining` 不计暂停的时间。遥测 CSV「程序步」列为 `3/paused`。

### 3.19 PC 连接加密：HTTPS / WSS + 证书指纹固定（2026-11-29）

**传输**：TCP 入口（PC 端，`api.json` 的 `httpPort`，缺省 8080）**缺省就是 TLS**：`https://板子IP:8080/api/v1/…`、`wss://板子IP:8080/api/v1/ws`。同一个端口，不另开 HTTPS 端口。Unix socket（触屏）照旧明文。
- 协议 TLS 1.2 / 1.3；证书 ECDSA P-256 自签（mbedTLS 3.6 生成），CN = `HT-PR8 <主机名>`，有效期 20 年。套件只有 AEAD：TLS 1.3 的 AES-128/256-GCM、ChaCha20-Poly1305；TLS 1.2 的 ECDHE-ECDSA + AES-GCM / ChaCha20-Poly1305。
- 证书在 `<配置目录>/tls/cert.pem` + `key.pem`（部署 = `/etc/reactord/tls/`，私钥 0600）。启动时读；缺了 / 坏了 / 不配对就自动生成新的并记事件 `system.tlsCreated`。
- **指纹** = 证书 DER 的 SHA-256，大写十六进制两位一组、冒号隔开（95 个字符），和 `openssl x509 -noout -fingerprint -sha256` 的输出一样。
- 对加密端口说明文 HTTP（老 PC 端）：回明文 `400 {"ok":false,"error":{"code":"TLS_REQUIRED",…}}` 后断开，并记一条 warn（同一地址 10 分钟一条）。握手 10 s 没完成断开。
- **退路**：`api.json` 写 `"tls": false` → TCP 入口回到明文 HTTP / WS（给还不会 TLS 的老 Avalonia PC 端临时用），启动时记 warn「PC 连接未加密」。

**`GET /system/tls`**（两边；TCP 上任何角色的令牌都能读）：
```jsonc
{ "tls": true,                                   // TCP 入口是否加密（false 时下面全是 null）
  "fingerprintSha256": "A7:8D:AA:03:…:CA:0A",
  "subject": "CN=HT-PR8 htlab-pr8, O=HT-PR8 reactord",
  "notBefore": "2026-11-28T13:32:54Z", "notAfter": "2046-11-28T13:33:54Z",
  "createdAt": "2026-11-28T13:33:54.219Z" }      // 证书文件写入时间
```

**`GET /health`**（免令牌）多两个字段：`"tls": true, "fingerprintSha256": "A7:8D:…"`——PC 第一次连接、还没令牌时就能拿到，用来和握手里看到的证书互相印证（指纹本来就在证书里，不是秘密）。

**`POST /system/tls/regenerate`**（**只本地**，触屏「设置 → 网络 → 连接加密 → 重新生成证书」，类 R，幂等可选）：`{}` → 生成新证书 + 私钥、写盘、**之后新建的 TCP 连接立刻用新证书**；已经连着的 PC 不断（它们握手时用的是旧证书），下次重连时会看到指纹变了。`result` = 新的 `GET /system/tls` 内容；记 warn 事件 `system.tlsRegenerated`「证书已重新生成」，message 带新旧指纹前 4 组。错误：409 `TLS_DISABLED`（`"tls": false` 时）；502 `HARDWARE_WRITE_FAILED`（证书写不进去，旧证书照常用）。TCP 上这个路径是 404。

**PC 端的做法（trust-on-first-use，PC 是另一个工程，这里是约定）**：
1. 连 `https://IP:端口`，**不按 CA 验证**（自签），握手后取服务器证书 DER 算 SHA-256 → 指纹。
2. 这台设备（按 IP / 序列号）**第一次连**：弹窗显示这串指纹（按 8 段、每段 4 组排，和触屏一样），请操作员走到触屏「设置 → 网络 → 连接加密」逐段核对；对上了点「确认，信任这台设备」→ 把指纹存在本机（按设备记）。对不上 / 点取消 → 断开，不发令牌。`/health` 回的 `fingerprintSha256` 只作参考，**以握手里拿到的证书为准**。
3. **以后每次连**：握手拿到的指纹和存的一样 → 照常；**不一样 → 拒绝连接、不发令牌**，提示「设备证书变了：如果刚在触屏上重新生成过证书，请重新核对；否则可能有人冒充这台设备」，让操作员选择重新核对（回到第 2 步）。
4. WSS 用同一个证书、同一套校验。令牌只在指纹核对过的连接上发。
5. 调试：`curl -k https://板子IP:8080/api/v1/health`；打印指纹：`openssl s_client -connect 板子IP:8080 </dev/null 2>/dev/null | openssl x509 -noout -fingerprint -sha256`。

## 4. 新错误码汇总

| 码 | HTTP | 什么时候 |
|---|---|---|
| `REVISION_CONFLICT` | 409 | 设置 / 程序库 / 档位的 revision 对不上；`detail.currentRevision` |
| `NAME_CONFLICT` | 409 | 程序库 / 模板重名（决定记录 2026-11-26） |
| `READ_ONLY` | 409 | 改 / 删内置模板 |
| `LIBRARY_FULL` | 409 | 程序库满了 |
| `USB_NOT_PRESENT` | 409 | 导出 / 导入时没插 U 盘 |
| `EXPORT_BUSY` | 409 | 上一个导出还没完 |
| `CALIB_RUNNING` | 409 | 已经在标定 |
| `CALIB_NOT_WAITING` | 409 | 没在等加水时调 `/calib/continue` |
| `NETWORK_BUSY` | 409 | WiFi 正在扫描 / 连接 |
| `TLS_DISABLED` | 409 | `"tls": false` 时调 `/system/tls/regenerate` |
| `TLS_REQUIRED` | 400 | 用明文 HTTP 连了加密端口（明文回一句后断开，不是 JSON 外层的命令结果） |

其余沿用现有码（`BAD_REQUEST`、`NOT_FOUND`、`PRECONDITION_REQUIRED`、`PARAM_OUT_OF_RANGE`、`PARAM_CROSS_CHECK`、`GAS_BUSY`、`CHANNEL_BUSY`、`CHANNEL_PROGRAM_OWNED`、`AUTOTUNE_ACTIVE`、`HW_NOT_CONFIGURED`…）。

## 5. 触屏的访问量（给后端估负载）

- 1 条 WS（订阅 telemetry / events / alarms / progress），2 条 keep-alive HTTP 连接（读、写各一条）。断线退避 0.25 → 5 s 重连。
- 连上时：上面 §1、§3 的 GET 各取一次（约 30 个请求，其中 `/channels/{1..8}/program` 8 个、`/runs/{id}` 最多 20 个）。
- 之后：`/trend` 每 10 s 一次（增量）、`/device/comm` 每 5 s、`/storage` 每 60 s；整定中 `/pid` 每 2 s；其余只在 `revs` 变了时取。
- 写命令全带 `Idempotency-Key`；同一条命令传输失败（连接在收到响应前断开）会用同一个键重发一次。

## 6. 不在本契约里

- 允许 / 拒绝 PC 的控制申请（`POST /control/requests/{id}/grant|deny`，设计文档 §5.4）：触屏这一版还没有申请弹窗，界面做的时候再补。
- `PUT /users`、退出 / 重启服务：触屏「退出程序」只退界面进程，不发请求。
- 急停：触屏没有急停按钮，不调 `/estop`。
