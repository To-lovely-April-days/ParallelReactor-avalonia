**写命令公共管线**（`Api/Endpoints.Write.cs` `CommandAsync`，顺序固定，C++ 必须逐步复刻）：
角色（viewer→403；停止类 = operator **或** estop 位；`/estop` 只看 estop 位）→ 正文 JSON（400）→ 幂等（428/重放/409）→ 动作类判定
（Control 须有效租约：无头 409 NOT_CONTROL_HOLDER、本地模式 409 MODE_LOCAL、作废 409 CONTROL_LEASE_EXPIRED；Stop/Record 免租约）
→ 参数绑定（400）→ 执行 → 结果映射 → 审计事件 `op.<action>`（其 seq = `opEventSeq`）→ WS `opEvent` → 幂等表 Complete。
HW_UNCONFIRMED / OUTCOME_UNKNOWN 的最终结局再记 `op.<action>.result` 并推第二条 opEvent（同 opId）。

**三种"未知"结局**（`Api/Hmi/UiCommandBridge.cs`）：UI 线程 5 s 未开始执行且撤销成功 → 503 UI_THREAD_TIMEOUT（确定未执行）；已开始再等 5 s 无结果 → 504 OUTCOME_UNKNOWN；同步头返回但硬件尾部 2 s 未完成 → 202 + warning HW_UNCONFIRMED。C++ 后端没有 UI 线程，前两种基本消失，但码要保留兼容。

### 1.4 控制权（租约）— `Commands/ControlLease.cs`(574)、`Api/ControlService.cs`、`Api/Hmi/ControlBridge.cs`

- 状态 `local / requested / remote / remoteLost`（`ControlModes`）。申请 → 触屏允许/拒绝（`controlRequestTimeoutSec` 默认 60 s，超时 = 拒绝）；`autoGrantRemote` / `PR_API_AUTOGRANT=1` 当场授权。
- leaseId 128 位随机；**从不进 WS 广播**；只在申请响应或带 Request-Key 的轮询里给。
- 心跳超时 `heartbeatTimeoutSec`（默认 10）→ RemoteLost；宽限 `leaseGraceSec`（默认 60）内同 leaseId 心跳恢复；期满执行 `onRemoteLost`：`keep`（默认，只提示）/`stopHeat`（中止该租约启动的程序 + 停 `StartedBy==该租约` 的通道）/`estop`。
- 本地随时夺回；急停（任何来源）强制回本地。丢失 leaseId 时同令牌 + 同 clientName 再申请可作废旧租约。
- clientName 清洗（去控制/零宽/双向字符，≤64）。
- 计时：线程池 `PeriodicTimer` 每 1 s 推进（不依赖 UI 线程）。所有迁移记 `control.*` 事件并推 WS `control`。

**总线与主站**
- `IModbusMaster`（FC 01/02/03/04/05/06/0F/10）+ `IUrgentModbusMaster.Urgent`（同一串口的紧急视图）— `Hardware/IModbusMaster.cs`。
- `ModbusRtuMaster`（`Hardware/ModbusRtuMaster.cs`）：`System.IO.Ports`，读写超时 **300 ms**，**无自动重试**；每笔事务 `DiscardInBuffer` → 写帧 → 先读 2 字节判异常码 → 读剩余 → 校验地址与 CRC；任何错误关闭串口，下笔事务重开。已排队事务不可取消（防半帧错位）。
- `PriorityGate`（`Hardware/PriorityGate.cs`）：每总线一把，紧急队列优先、同级 FIFO、不打断在途事务（急停帧最多等一笔，正常几十 ms，超时 300–600 ms）。
- `OfflineModbusMaster`：端口未配置 → 每笔抛 IOException，模块显示离线、读数"—"。

### 5.1 步骤（v0.8，9 种；`Contracts/.../Models/StepTypeCodes.cs`、`Models/StepFields.cs`、`Models/StepEngine.cs`）

### 5.2 生命周期（`ViewModels/ProgramViewModel.Run.cs` `ExecuteAsync`，`Models/ProgramRunInfo.cs`）

- 阶段：`preparing → running ⇄ waitingGas → finishing → completed | failed | aborted`（`ChannelProgramStates`）。
- 下发：`PUT program`（冻结为 `StepSnapshot`）→ `POST program/run`：`ProgramRunGuard` 在"打开确认"与"确认"两次重判 → `ResetUptake` → 每步前查取消 → `MarkStepStarted/Completed/Aborted/Failed`。
- 故障类：`StepFaultException`（"停止这一路"）、`GasFaultException`、`ProgFaultException`；气路租约被超压联锁取消 → 失败"气路被超压联锁中止"；急停 / 外部停止 / 退出 → aborted。
- 收尾（finally，**不自动放空**）：停稳压 → 只释放自己代号的气路占用并全关阀 → 停曲线/逼近 → 非急停时停本路加热、关 SVn → 释放搅拌引用 → 停计量 → 通道转 Done → 记事件 + Toast。
- 每通道最近一次运行保留（`_lastRuns`）供 `/channels/{id}/program/run`；会话中运行写入 manifest `programRuns`。
- 通道状态随步骤：升温=heating、充压/置换/放空/气密充气=pressing、保持/静置=wait、反应=react。

### 5.3 多通道调度

- 每通道最多 1 个程序，全机 `MaxConcurrent = 8`。
- **共用气路（总管）**：`GasLease`（占用者 Owner/Task/Participants/Watch、代号 gen、按占用者中止）+ `GasQueue`（先到先得，单调时钟；每通道一张票）；气路步骤 `AcquireGasAsync` 排队，0.5 s 轮询，超过 `ProgramGasWaitMin`（默认 60 min）→ 该步故障。稳压改为周期短租约，脉冲间释放让他人轮流。程序稳压/排队中时泄漏测试与手动阀控按 `GAS_BUSY` 拒绝。
- 阀帧只经 `ValveFrame` 拼整帧下发：气源最多一路、气源与排空不同时开、切换间插全关死区。
- **共用搅拌**：`Models/StirShare.cs` 引用计数，最后释放者停；释放最近登记者后回退到上一位的转速。操作员手动开停不经它。

### 5.4 存储

- HMI：每通道程序**只在内存**（无持久化，重启丢失）；触屏"保存为模板"未实现（`ProgramViewModel.cs:317`）；配方 `Models/Recipe.cs` 为内置数组。
- PC 客户端：`library.json`、`templates.json`、`programs/<设备id>.json`（台账）、`experiments.json`（`doc/控制软件说明.md §6`），HMI 不感知。

## 8. 吸气量 / 容积标定

**吸气量**（`Models/GasUptake.cs` `GasUptakeMeter`，接线在 `ViewModels/MainViewModel.Uptake.cs`）
- n(mmol) = (P表 + 14.6959) · 6894.757 · V(mL)·1e-6 / (8.314462618 · (T℃ + 273.15)) · 1000。
- V气：已标定 → `EffectiveVolume[n] − 溶液体积`；未标定 → `VesselVolume(10) − 溶液 + GasLineVolume(0)`；< 0.5 mL 不计量（记 warn）。
- 每 Tick 累加 `prevN − n`（首尾相消，噪声不累积）；SV 打开（`ValveService.GetSvOpenGen` 计数变化）→ 断基准，SV 关满 2 s 后重取基准（补气不算消耗，`Refills++`）；读数无效跳过但不断基准；体积参数变化重取基准。
- 速率 = 最近 60 s 窗口差分（跨度 ≥10 s 才给），mmol/min。
- 开始：press 步完成 / 抽屉"清零"（`gas-counter/reset`）；停止：end 步 / 程序收尾；新程序 Reset。
- PC 端另有事后统计（最大吸气速率 2 min 窗口）：`Control.Core/Records/RecCompute.cs`。

**容积标定**（`Models/VolumeCalib.cs`，流程 `ViewModels/CalibViewModel.cs`，只允许本地）
- 气体膨胀法：每步 只开惰性气源给总管充气 → 关 → 只开 SVn 放入 → 读稳定压力；Pk = (1−f)·P(k−1) + f·Preg，f = Vm/(Vm+Vg)。
- N 组 (P(k−1), Pk) 线性拟合：斜率 a，比值 r = Vg/Vm = a/(1−a)；只用升压 ≥0.5 psi 的步（≤6 步，≥3 组）；f ∈ [0.01, 0.9]；R² ≥ 0.995。
- 首次两遍：空釜 r1、加水 L mL 后 r2 → Vm = L/(r1−r2)，Veff = r1·Vm（2–2000 mL，且 L < Veff）；之后其他通道一遍：Veff = r·Vm。
- 有等待操作员（加水）的交互阶段（`CalibSnap.WaitingOperator`）。

**泄漏测试判定**（`Models/LeakFit.cs`）：P_corr = P_abs · T_ref / T（K，T_ref = 测量窗起点釜温），最小二乘斜率 ×3600 → psi/h，与阈值比较。

### 10.2 最需小心的部分

1. **线程模型重建**：今天靠"所有可变状态只在 UI 线程"隐式串行化（包括程序 async 流程的续体）。C++ 需要显式单线程事件循环（推荐：一个控制线程 + 每总线 I/O 线程 + HTTP 线程池投递命令），否则守卫"判定与动作在同一次调用中完成"（`doc/命令层设计.md §2.6`）的原子性会丢。
2. **急停快速路径**：锁位 → 三总线并行、紧急优先帧插队 → 锁存 fsync 顺序 → 完整流程 → 每 3 Tick 补发；锁存损坏按锁定；开机恢复。
3. **超温/超压"下发→回读确认→重发→被重开复发"状态机**（`OverTempGuard`、`ActuatorRetry` 的写入序号去重），以及超压时"保持排空阀"的特例。
4. **程序引擎 + 气路共享**：GasLease 代号、GasQueue 单调时钟、稳压短租约脉冲、取消原因判别（超压 vs 急停 vs 手动 vs 外部置停）、收尾顺序、StirShare 回退语义。
5. **写命令管线语义**（幂等按令牌隔离、428/409/重放、opEvent 双推、HW_UNCONFIRMED 尾部）和**租约状态机**（requestKey 一次性、30 s 冷却、grace、onRemoteLost=stopHeat 按 StartedBy 标签）——PC 客户端依赖这些细节。
6. **EventStore seq 连续性与 WS 重同步**（锁内分配 seq 保序、环 5000、gap/resync、1008 断开策略）。
7. **AI-8 怪癖**：Srun 全局闸（15→9655 断电自锁）、Ctn<8 自愈、启动前回读 SP 把关、PID 档位切换按目标温度套用、自整定完成回读存回"发起时的档"。
8. **防过冲逼近 `HeatApproach`**（314 行，判峰/判稳/快慢段）与 16 段曲线插值 + 周期强制重写 SP。
9. **DM2C** 速度模式（不用 JOG 保活）、传动比换算、电流/细分参数写入。
10. **"本地 vs 远程"在新架构下的重新定义**：LVGL 变成客户端后，`CommandSource.Local`（触屏）的特权（急停复位、允许远程申请、容积标定、设置写入、不受 Strict 守卫）需要一种可信的本地身份（如 Unix socket / 回环 + 专用令牌），否则会把这些 LocalOnly 动作暴露到网络。
11. **文件格式兼容**：telemetry CSV 列顺序只能追加、BOM、防公式注入、日文件滚动与 `-1` 另起；settings.json 字段名（含 PID 来历）要能读旧档。
12. **配置差异**：`run.sh` 注释称全部 9600，但代码默认温控 19200、搅拌 38400 且 run.sh 未设 BAUD——现场实际波特率需核实后写进新配置文件。
13. **设计稿已定义但未实现**的项（`progress` WS 消息、`telemetryRateMs`、seqEpoch 递增、HTTPS、HeatTimeout/PressDeviation 报警、程序 revision/If-Match）：重写时决定是否补齐，客户端目前不依赖。
