## 1. 目标和已定的前提

| 项 | 决定 |
|---|---|
| 语言 | C++（后台服务和触屏界面都是） |
| 界面库 | LVGL 9.x |
| 运行平台 | Linux，ARM64（RK3568 / 树莓派一类） |
| 显示 | **X11**（现场服务 `reactor-hmi.service` 是 `After=graphical.target` + `DISPLAY=:0`），LVGL 用 X11 驱动全屏无边框；开发机用 SDL |
| 急停 | **不做急停**（硬件没有急停按钮，软件急停也删掉），最强的停止是「全部停止」，见 §6 |
| 语言 | 第一版中文、英文完整，其余 6 种先显示英文 |
| 程序库 | 触屏和 PC 端**互通**，程序库存在后台服务里，两边读写同一份 |
| 分辨率 | **1280×800**（画布按 1280×720 画的，移植时内容区多出 80 px，见 §8.3） |
| 进程 | 后台服务单独一个进程，界面是另一个进程 |
| 对外协议 | **沿用现有 HTTP + WebSocket JSON（`/api/v1`）**，现有 Avalonia PC 端不改就能连 |
| 界面样式 | 以画布「触屏界面设计」上的定稿为准 |

**要解决的根本问题**：现在的程序没有真正的「后端」，控制循环就是界面线程上的定时器，程序引擎、急停、联锁都写在界面的 ViewModel 里（附录 §3、§9）。界面一卡，控制就跟着卡。新架构把这些全部搬进后台服务，界面只负责显示和发命令。

## 2. 总体架构

```
┌──────────────────────── Linux（ARM64）────────────────────────┐
│                                                               │
│  reactord（后台服务，systemd，开机自启，崩溃自动重启）            │
│  ┌──────────────────────────────────────────────────────────┐ │
│  │ 接口层   HTTP + WS（TCP 8080，给 PC）                       │ │
│  │          HTTP + WS（Unix socket，给本机触屏）               │ │
│  │          鉴权 · 角色 · 租约 · 幂等 · 限流                    │ │
│  ├──────────────────────────────────────────────────────────┤ │
│  │ 命令层   守卫（谁能做、什么状态下能做）→ 执行 → 结果码        │ │
│  ├──────────────────────────────────────────────────────────┤ │
│  │ 控制核心（单一控制线程，独占所有可变状态）                    │ │
│  │   控制循环 · 程序引擎 · 气路调度 · 联锁 · 全部停止 · 报警     │ │
│  │   吸气量 · 泄漏测试 · 容积标定 · 自整定                      │ │
│  ├──────────────────────────────────────────────────────────┤ │
│  │ 设备层   AI-8 温控 · 8AI 压力 · IO16R 阀门 · DM2C 搅拌        │ │
│  │          每条 RS485 一个 I/O 线程 + 紧急优先队列              │ │
│  │          模拟硬件（开发和测试用）                             │ │
│  ├──────────────────────────────────────────────────────────┤ │
│  │ 存储     设置 · 事件 · 遥测 CSV · 会话 · 泄漏结果 · 程序库    │ │
│  └──────────────────────────────────────────────────────────┘ │
│         ▲ Unix socket                                         │
│  reactor-hmi（LVGL 触屏界面，systemd，图形会话起来后启动）        │
│                                                               │
└──────────────────────────────▲────────────────────────────────┘
                               │ TCP 8080 + 令牌
                        PC 端（可多台）
```

**几条原则**

1. **只有 reactord 能碰串口。** 界面和 PC 端只能通过接口发命令。
2. **所有安全判断都在 reactord 里**：超温、超压、模块离线、程序占用通道、气路占用、数值范围。界面上的按钮变灰只是提示，不是安全措施。
3. **界面崩溃、重启、没启动，控制照常运行**：加热、程序、联锁、记录都不受影响。
4. **触屏和 PC 走同一套接口**，区别只在身份（§5）。

## 3. 后台服务 reactord 的模块划分

| 模块 | 职责 | 由哪些现有代码翻译而来 |
|---|---|---|
| `core/` 纯逻辑 | 不碰 I/O、不碰时钟，输入输出都是值，可单测 | `Models/*`：守卫（HeatGuard / GasGuard / ProgramRunGuard）、StepEngine、StepFields、HeatApproach、TempProfile、GasUptake、VolumeCalib、LeakFit、GasLease / GasQueue / ValveFrame、StirShare、OverTempGuard、OverPressureGuard、ValueRules、AlarmLifecycle |

| `ctl/` 控制核心 | 控制线程、控制循环、4 个设备服务、联锁、全部停止、程序引擎、气路序列、泄漏测试、容积标定、自整定、报警表、快照生成 | `Service/*` + `ViewModels/` 里的业务部分（附录 §9 列表） |
| `cmd/` 命令层 | 每个命令的守卫顺序、错误码、中文文案；控制权仲裁和租约 | `Commands/*` |
| `api/` 接口层 | HTTP 路由、WS 中枢、鉴权、CIDR、限流、幂等、历史文件下载 | `Api/*` |
| `store/` 存储 | settings.json、api.json、事件 JSONL + seq、遥测 CSV、会话 manifest、泄漏结果、**程序库（新增，和 PC 互通）** | `Service/SettingsStore` / `EventStore` / `DataLogger` / `TelemetryCsv` / `SessionManifest` |
| `apps/reactord` | 启动、读配置、组装、信号处理、systemd 看门狗 | `Program.cs` + `run.sh` |

## 4. 线程模型

现在的程序靠「所有状态只在界面线程上改」来避免并发问题（附录 §3）。C++ 里没有界面线程，改成**显式的单一控制线程**：

| 线程 | 个数 | 做什么 | 可以碰什么 |
|---|---|---|---|
| **控制线程** | 1 | 事件循环：定时器（控制循环 1.2 s、程序引擎 0.5 / 1 / 2 s 的各种节拍、租约 1 s）、命令队列、设备回包 | **独占全部可变状态**（通道、程序运行、气路租约、报警表、设置的运行副本） |
| 总线 I/O 线程 | 4（每条 RS485 一个） | 按优先级串行收发 Modbus 帧；紧急队列优先；超时 300 ms、不自动重试；结果投递回控制线程 | 只碰自己的串口 |
| 接口线程 | 1～2（asio io_context） | HTTP 解析、鉴权、限流、幂等；读请求直接读快照；写命令打包投递给控制线程，等结果 | 只读不可变快照、事件存储 |
| 存储线程 | 1 | 遥测 CSV、事件 JSONL、会话文件、设置防抖写盘 | 只碰文件 |

**共享方式**
- 控制线程每个周期末生成一份**不可变快照**（`shared_ptr<const Snapshot>`，原子替换），接口线程和 WS 推送只读这份快照。
- 写命令：接口线程把命令放进控制线程的队列，附一个 promise。控制线程在**同一次处理里完成判定和动作**（守卫和执行之间不会插进别的命令，见 `doc/命令层设计.md §2.6`），然后回填结果。
- 事件存储：加锁分配 seq，然后入环、入写盘队列、推 WS，保证顺序。

**程序引擎的写法**：C# 用 async/await，C++17 没有这个，改成**每个通道一个显式状态机**，由控制线程的定时器推进。每种步骤是一个类，有 `enter / tick / exit / abort` 四个入口。好处是暂停、中止、全部停止、超压收尾都是确定的状态迁移，好测。

**全部停止的快速路径**：急停删掉以后，「全部停止」是最强的停止，所以保留原来急停的「不等控制线程」做法，但**不锁存**：
1. 往三条总线的**紧急队列**同时塞停止帧（AI-8 八路 At=4、DM2C 减速停、IO16R 全关）；
2. 再投递给控制线程做完整收尾：中止气路和全部程序、停曲线和逼近、改通道状态、记事件。

控制线程卡住时第 1 步照样能把加热和阀门停下。

## 5. 接口

### 5.1 两个入口，同一套协议

| 入口 | 地址 | 给谁 | 身份 |
|---|---|---|---|
| TCP | `0.0.0.0:8080`（可配） | PC 端 | Bearer 令牌 + CIDR 白名单，角色 viewer / operator / admin + estop 位（附录 §1.1） |
| Unix socket | `/run/reactord/hmi.sock` | 本机触屏 reactor-hmi | 用 `SO_PEERCRED` 核对对端进程的用户（只认 reactor-hmi 的系统用户），身份 = **本地** |

两边都是 HTTP/1.1 + WebSocket，路由、JSON 格式完全一样。这样触屏和 PC 用同一套客户端代码思路，后端也只写一套处理。

### 5.2 「本地」身份的特权

现在只有触屏能做的操作（附录 §1.3「不暴露」、§10.2 第 10 条），新架构里**只在 Unix socket 上开放**，TCP 上一律 404：

- 允许 / 拒绝 PC 的控制申请
- 改设置（`PATCH /settings`）、档位边界、满量程、单位、搅拌驱动器参数
- 容积标定
- 网络（WiFi 扫描 / 连接）、语言、用户与权限
- 导出到 U 盘
- 退出 / 重启服务

本地命令不受「严格守卫」约束，和现在触屏的体验一致。

### 5.3 沿用的部分（PC 端依赖，必须逐字兼容）

- 26 个 GET 端点、32 个写端点、路径、正文、错误码到 HTTP 状态的映射（附录 §1.2、§1.3）。
- 写命令公共流程，顺序固定：角色 → 正文 → 幂等 → 动作类别（控制要租约）→ 参数 → 执行 → 结果 → 审计事件 → WS opEvent（附录 §1.1）。
- 租约状态机：leaseId 不进 WS，requestKey 一次性，30 s 冷却，心跳 10 s，宽限 60 s，onRemoteLost 三种策略（附录 §1.4）。
- WS 消息类型、背压和重同步规则（附录 §1.5）。
- `HW_UNCONFIRMED`、`OUTCOME_UNKNOWN`、`UI_THREAD_TIMEOUT` 这些码保留，新后端基本不会再产生后两种。
- **急停相关的兼容处理**：现有 PC 端有急停按钮，会调 `POST /estop`。新后端保留这个端点，但行为改成「全部停止（含搅拌）」，不锁存、不强制收回控制权；`ESTOP_ACTIVE` 码不再产生；快照里的急停字段恒为 false。这样 PC 端不改也不会报错，以后 PC 端改版时再把按钮去掉。

**验收办法**：现有 PC 端不改代码连上 reactord，所有页面和操作正常；再用脚本把新旧两个后端对同一组请求的响应做对比。

### 5.4 新增的端点（触屏新界面要用的）

| 端点 | 入口 | 用途 | 对应画布页面 |
|---|---|---|---|
| `PATCH /settings` | 本地 | 改设置，带 revision 防覆盖 | 设置 · 通用 / 参数与报警 / 通道与气路 |
| `PUT /pid/bands` | 本地 | 档位边界 | 设置 · 温控 PID |
| `POST /calib`、`GET /calib`、`DELETE /calib/current` | 本地 | 容积标定流程（含「等操作员加水」阶段） | 设置 · 容积标定 |
| `POST /control/requests/{id}/grant\|deny` | 本地 | 允许 / 拒绝远程控制 | 控制申请弹窗 |
| `GET/POST/PUT/DELETE /library/programs`、`/library/templates` | 两边 | **程序库，触屏和 PC 互通**（现在触屏的程序只在内存里，重启就丢；PC 的存在 PC 本地）。带 revision，两边同时改时后保存的一方收到冲突提示 | 程序库 · 我的程序 / 内置模板 |
| `GET /network`、`POST /network/wifi/scan`、`POST /network/wifi/connect` | 本地 | WiFi 扫描、连接（调 NetworkManager） | 设置 · 网络 |
| `PUT /system/language` | 本地 | 界面语言（存设置里，PC 不用） | 语言弹窗 |
| `GET/PUT /users` | 本地 | 用户与权限 | 设置 · 用户与权限 |
| `GET /usb`、`POST /export` | 本地 | U 盘检测、按运行 / 按时间段导出 | 记录 · 导出到 U 盘 / 按时间段导出 |
| `POST /alarms/ack-all` | 两边 | 全部确认 | 报警页「全部确认」 |
| WS `progress` | 两边 | 程序进度（步序、剩余时间），设计稿里有但没实现 | 程序 · 运行中、方案总览 |

新增端点只加不改，PC 端不受影响。PC 端要用互通的程序库，需要改版接入 `/library/*`（在那之前 PC 继续用自己本地的程序库）。

## 6. 安全设计

全部在 reactord 里执行。和现在的差别：**现在大部分规则写在 ViewModel 里，新架构里全部进控制核心**（附录 §4 表格最后一列）。

| 机制 | 新的位置 | 要点 |
|---|---|---|
| ~~急停~~ | **删除** | 硬件没有急停按钮，软件急停也去掉：没有锁存、没有复位、没有设备层 Locked 位。`estop.latch` 不再读写 |
| 全部停止 | 快速路径（任意线程）+ 控制线程收尾 | §4；停全部加热、中止全部程序和气路、关全部阀门、可选停搅拌；**不放空**；不锁存，停完可以正常重新开始 |
| 超温切断 | `ctl/` 每周期 | PV ≥ 上限 → At=4；以回读为确认；未确认每 5 s 重发；被重新打开再切；PV < 上限 − 2 ℃ 解除 |
| 超压联锁 | `ctl/` 每周期 | P ≥ 上限 → 关 SVn 和三路气源（**排空保持**），中止全部气路；可选停加热；P < 上限 × 0.98 解除；通道要人工复位 |
| 模块离线 | `ctl/` | 连续 3 次失败算离线；读数无效、不参与报警判定；不自动停机；气路类操作启动前拒绝 |
| 程序占用通道 | `cmd/` | 跑程序时拒绝手动改加热、阀门、曲线、停用（`CHANNEL_PROGRAM_OWNED` 等码） |
| 阀门整帧 | `core/ValveFrame` | 气源最多开一路；气源和排空不同时开；切换时插一拍全关 |
| 停止前确认 | **客户端** | 「每次停止都要确认」是交互规则，触屏和 PC 各自弹确认框；服务端不要求二次确认（和现在一致） |
| 看门狗 | systemd `WatchdogSec` | 控制线程每周期 `sd_notify(WATCHDOG=1)`；控制线程卡死 → systemd 杀掉重启 → 开机按设备回读恢复 |

**升温超时、压力偏离（已定：补上）**：这两个设置项现在只有设置界面、没有判定代码（附录 §4）。重构时补上，作为**三级警告**（铃铛下冒气泡，不弹窗、不自动停机）：
- 升温超时：加热开始后超过 `HeatTimeout`（默认 20 min）还没进入目标 ±到位范围 → 警告一次；
- 压力偏离：充压完成后、稳压开着时，压力偏离设定超过 `PressDeviation`（默认 8 psi）持续 30 s → 警告；回到范围内自动解除。

**去掉急停之后的影响**（已按你的决定处理，列出来备查）：
- 触屏顶栏右上角的「急停」红钮去掉，时间挪到最右、前面加竖线（照另一台设备的顶栏）；画布上的定稿已改（2026-11-26）。一级报警里「按右上角急停」改成「点主页的全部停止」。
- 停止只剩「全部停止」和单路停止，按原规则每次都要确认。
- 超温切断、超压联锁照常，它们不依赖急停。
- 设备层不再有「锁住后拒绝打开阀门 / 启动加热」这道硬拦截，安全全靠控制核心的守卫和联锁，所以 §9 的联锁测试要更严。

## 7. 存储和文件格式

**原则：旧数据能直接读，PC 端下载的文件格式不变。**

| 文件 | 处理 |
|---|---|
| `settings.json` | 字段名、结构保持不变（含 8×3 档 PID 和来历、体积标定）；读不出时另存备份 |
| `api.json` | 保持不变 |
| 遥测 `telemetry-YYYYMMDD.csv` | 列顺序只能在末尾追加；UTF-8 BOM；防公式注入；表头不同另起 `-1` 文件 |
| 事件 `events/*.jsonl` + `.seq` | 保持不变；seq 跨重启连续 |
| 会话 `sessions/*.csv` + `.json` | 保持不变 |
| 泄漏结果 `leak/*` | 保持不变 |
| **硬件配置（新）** | `hardware.json`：每条总线的端口、波特率、站号、超时，代替现在 `run.sh` 里的环境变量。默认值照 `run.sh`（见下面「波特率」） |
| **程序库（新，和 PC 互通）** | `library/programs/*.json`、`library/templates/*.json`，格式照 PC 端 `library.json` / `templates.json` 的条目，压力存 MPa；首次启动可以从 PC 导入现有程序库 |

**波特率（以 `run.sh` 为准）**：端口和站号照 `run.sh`：

| 模块 | 端口 | 站号 | 波特率 |
|---|---|---|---|
| 温控 AI-8 | `/dev/ttyS5` | 1 | 见下 |
| 搅拌 DM2C | `/dev/ttyS4` | 1 | 见下 |
| 压力 8AI | `/dev/ttyS6` | 1 | 9600 |
| 阀门 IO16R | `/dev/ttyS8` | 1 | 9600 |

要注意一处：`run.sh` 注释写「全部 9600」，但脚本里**没有设置**温控和搅拌的波特率变量，所以现在机器上实际用的是代码默认值：**温控 19200、搅拌 38400**。如果现在这台机器温控和搅拌是通的，说明仪表实际就是 19200 / 38400。`hardware.json` 默认按「现在实际在跑的值」写（19200 / 38400 / 9600 / 9600），上真机第一步先核对一次。

目录：数据 `/var/lib/reactord/`，配置 `/etc/reactord/`；开发时可用参数指到别处。

## 8. 触屏界面 reactor-hmi

### 8.1 结构

```
reactor-hmi
├── net/       连接 reactord（Unix socket）：HTTP 请求、WS 订阅、断线重连、快照缓存
├── model/     把快照转成页面要用的数据（不含任何安全判断）
├── ui/kit/    公共控件：顶栏、页签卡片、圆钮、带灯选项、开关、数值框、
│              数字键盘、文字键盘、L 型弹窗、文件图标、釜体（乙）、曲线图
└── ui/pages/  每个页面一个文件，对应画布的一排
```

**网络线程和 LVGL 线程分开**：LVGL 不是线程安全的，网络线程收到快照后只放进队列，LVGL 主循环每帧取出来刷新界面。

**断线时**：顶栏显示「未连接」，全屏盖一层「正在连接后台服务…」，所有操作按钮不可点。后台恢复后自动重连、重新订阅。

### 8.2 页面对照（画布上的定稿 → LVGL 页面）

### 8.3 1280×800 怎么处理

画布是 1280×720。顶栏（60）和页签卡片（44）高度不变，**多出的 80 px 全部给内容区**：
- 主页 8 张釜卡片每张高 290 → 330，釜和读数可以放大一点；
- 曲线图、记录列表、程序步骤区直接变高；
- 弹窗位置按屏幕居中重新算。

具体每页怎么放，移植前我在画布上补一版 1280×800 的主页和程序页给你确认。

### 8.4 要提前验证的技术点

| 点 | 风险 | 怎么验证 |
|---|---|---|
| 中文字体 | 字库大、渲染慢 | 用 FreeType 加载 Noto Sans CJK（或按用到的字裁一个子集），在 RK3568 上测帧率 |
| 8 个釜的动画 | 同时动画可能掉帧 | 先做一个装置总览的原型上真机测 |
| 曲线图 | `lv_chart` 不支持我们要的多通道、时间轴、阈值带 | 自己写绘制（LVGL 的 canvas / draw API） |
| 8 种语言 | 第一版只做中英完整 | 文案集中放到语言表里，界面不写死文字；其余 6 种缺的条目显示英文，语言弹窗标「未齐」 |
| X11 驱动 | 现场是 X11（`DISPLAY=:0`） | 用 LVGL 的 X11 驱动全屏；开发机用 SDL |

## 10. 构建和部署

**目标板**：Ubuntu 20.04.6 LTS（focal），aarch64，带桌面（X11）。以下版本都按 focal 自带的软件源定，板子上 `apt install` 就能装齐，不用自己编依赖。

| 用途 | 选择 | focal 上的版本 / 装法 | 理由 |
|---|---|---|---|
| 编译器 | GCC 9.4（系统默认） | `build-essential` | 完整支持 C++17 |
| 语言标准 | C++17 | | 不用 C++20，免得要另装 GCC 10 |
| 构建 | CMake | 3.16（`cmake`） | LVGL 9 要求 ≥ 3.12，够用 |
| HTTP / WS | **自己写**（`src/net/`，poll 事件循环） | 无依赖 | 原计划用 Boost.Beast；开发机上没有 Boost，为了电脑和板子用同一套代码、随时能在电脑上跑测试，改成自己写：HTTP/1.1 + WebSocket，TCP 和 Unix socket 两个入口（2026-11-26 改）|
| JSON | nlohmann/json | 随工程带头文件，固定版本 | 开发机和板子版本一致 |
| 日志 | 自己写（`src/common/log`） | 无依赖 | 写 stderr，systemd 收进 journal |
| 测试 | 自己写（`tests/testing.hpp`） | 无依赖 | `TEST / CHECK`，够用 |
| 串口 | 自己封装 termios | 系统自带 | 代码少，便于控制超时 |
| 界面 | LVGL 9.x（源码放进工程）+ FreeType | `libx11-dev` `libfreetype6-dev`；开发机用 `libsdl2-dev` | 板子上用 LVGL 的 X11 驱动 |
| 字体 | **随工程打包**：Inter（数字/英文）+ Noto Sans SC（中文，简体字形） | `assets/fonts/`，编译后拷到程序旁的 `fonts/` | 和画布设计一致；不依赖系统字体（2026-11-26） |

**怎么编**
- **正式打包：Windows 上的 Visual Studio 2022**（「使用 C++ 的 Linux 和嵌入式开发」工作负载 + 远程 Linux）：VS 把源码同步到板子，用板子上的 GCC 编，配置在 `CMakeSettings.json`，步骤见 `deploy/VS2022-编译说明.md`（2026-11-26 用户告知）。
- **日常开发**：在电脑上编，用 SDL 窗口 + 模拟硬件跑，不需要板子。
- **出板子用的程序**：用 `ubuntu:20.04` 的 **arm64 Docker 容器**编（如果开发机是 Apple 芯片的 Mac，arm64 容器是原生速度，不用模拟），编出来的程序和板子上的系统库完全一致，拷过去就能跑。工程里放一个 `Dockerfile` 和一条编译脚本。
- **也可以直接在板子上编**：装上面那几个包，`cmake && make` 即可，适合现场改一点就编。

Ubuntu 20.04 的官方常规维护已在 2025 年结束，对这台不联网升级的工控机影响不大；以后换 22.04 / 24.04 时，上面的依赖都有更新版本，代码不用改。

**部署**
- `reactord.service`：`Restart=always`，`WatchdogSec`，用专用系统用户运行（加入 dialout 组才能开串口），不需要图形环境。
- `reactor-hmi.service`：照现在的 `reactor-hmi.service` 写法（`After=graphical.target`、`User=teamhd`、`DISPLAY=:0`），`Requires=reactord.service`；崩了自动重启。
- 两个程序可以分开升级。

## 12. 开发顺序

| 阶段 | 内容 | 做完的标志 |
|---|---|---|
| M0 | 工程骨架、arm64 容器编译、在板子上跑通一个 LVGL 页面（X11 全屏 1280×800、中文字体）和一条串口收发 | 板子上能显示一个页面、能读到一个模块 |

| M4 | 程序引擎 + 气路调度 + 泄漏测试 + 容积标定 | 9 种步骤在模拟上全部跑通；8 路同时跑气路排队正确 |
