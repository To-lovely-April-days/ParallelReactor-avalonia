# ParallelReactor HMI 对外接口 · 使用说明（P2 只读 + P3 控制权 / 写命令 + P4 会话）

> 协议的唯一依据是《对外通讯接口设计》（`doc/对外通讯接口设计.md`，v0.5；§14.1 / §14.2 列出实现偏差）。本文只讲怎么开通、怎么调。
> 代码：`Api/`（接口层）、`Api/Hmi/`（HMI 适配）、`Commands/ControlLease.cs`（租约状态机）、`Service/EventStore.cs`、`Service/SessionManifest.cs`。§2–§3 是 P2 只读部分，**写接口、控制权与会话见 §5**。

## 1. 开通

### 1.1 配置文件 `api.json`

与 `settings.json` 同目录（Linux：`~/.config/ParallelReactor/api.json`；模拟模式 `PR_SIM=1` 读 **`api-sim.json`**）。目录可用环境变量 `PR_CONFIG_DIR` 覆盖。文件不存在或损坏 → 按默认值运行（`enabled=false`，Kestrel 完全不启动）并记一条事件。

```json
{
  "enabled": true,
  "bind": "0.0.0.0",
  "httpPort": 8080,
  "allowedCidrs": ["192.168.10.0/24"],
  "tokens": [
    { "name": "PC-测试工位1", "sha256": "9428e07c68054de014032f21e0716501aa937714fd31033caf589e66b276e53b", "role": "viewer", "estop": false }
  ],
  "maxClients": 4,
  "serial": "PR8-2026-0001"
}
```

| 字段 | 说明 |
|---|---|
| `enabled` | false（默认）时不启动接口 |
| `bind` / `httpPort` | 默认 `0.0.0.0:8080`。绑定失败（端口被占等）记事件 `system.apiBindFailed`（首次一条，之后每 10 分钟最多一条），每 10 s 重试 |
| `httpsPort` / `certPath` | **P2 未实现**：读取但不生效，配置了记一条 warn 事件。只有 HTTP，令牌明文传输，依赖网段隔离与 `allowedCidrs` |
| `allowedCidrs` | 允许的网段（IPv4 / IPv6 CIDR）。**为空时只允许本机回环地址**；不在白名单内一律 403 `IP_NOT_ALLOWED`（含 `/health`） |
| `tokens[]` | 预共享令牌，只存 SHA-256（小写 / 大写十六进制都可）；`role` = viewer / operator / admin：读取任何角色都可以；**写命令需要 operator 及以上**，`PUT …/pid/{band}` 需要 admin；`estop` = 独立的急停权限位（operator / admin 默认有；给 viewer 配 `true` 可只允许它远程停机） |
| `heartbeatTimeoutSec` / `leaseGraceSec` | 远程控制心跳超时（默认 10 s）/ 宽限（默认 60 s）：超时进入 RemoteLost（设备继续运行），宽限期满租约作废、回到本地 |
| `onRemoteLost` | 宽限期满的动作：`keep`（默认，只记事件 + 提示）/ `stopHeat`（中止该客户端下发的程序、停止它启动的通道）/ `estop`（触发急停，来源「心跳丢失」）；非法值按 keep 并记 warn |
| `autoGrantRemote` | `true` 时远程申请免触屏确认（无人值守 / 验收用，启动时记 warn 事件）；默认 `false`：触屏弹窗「PC-x 申请远程控制 允许 / 拒绝」，`controlRequestTimeoutSec`（默认 60）内未处理 = 拒绝 |
| `writeRateLimitPerSec` | 写命令限流（每令牌每秒，默认 10）；`/estop` 不限流 |
| `maxClients` | WebSocket 并发连接上限（默认 4），超过握手返回 503 `TOO_MANY_CLIENTS` |
| `serial` | 设备序列号，`/device` 原样返回；不配为 null |

生成令牌与哈希（令牌明文只给客户端，`api.json` 只放哈希）：

```bash
TOKEN=$(openssl rand -hex 32); echo "token=$TOKEN"
python3 -c "import hashlib,sys; print(hashlib.sha256(sys.argv[1].encode()).hexdigest())" "$TOKEN"
# 或：echo -n "$TOKEN" | shasum -a 256
```

### 1.2 环境变量（开发 / 验收）

| 变量 | 作用 |
|---|---|
| `PR_API=1` / `PR_API=0` | 强制启用 / 关闭接口（覆盖 `enabled`） |
| `PR_API_PORT=18080` | 覆盖 `httpPort` |
| `PR_API_AUTOGRANT=1` | 等价 `autoGrantRemote: true`（验收便利） |
| `PR_CHANNELS=1-4` | 已安装通道（`/device.installedChannels`、`channels[].installed`），默认 1–8；语法 `1-4`、`1,3,5-8` |
| `PR_CONFIG_DIR` | 配置目录（`settings.json`、`api.json`） |
| `PR_DATA_DIR` | 数据目录（运行记录 / 事件 / 会话 / 泄漏测试文件，接口的历史数据来源） |
| `PR_SIM=1` | 内存模拟硬件（所有响应的 `simulated` 为 true） |
| `PR_HEADLESS=1` | 无头运行（无显示器 / 无 WindowServer 的开发机上跑完整的 VM + 控制循环 + 接口）。只在 **Debug 构建**里存在，Release 发布包不带 |


## 2. REST 只读部分（前缀 `/api/v1`，GET）

所有请求带 `Authorization: Bearer <token>`（`/health` 除外）。响应 `application/json; charset=utf-8`，UTC 时间、camelCase；失败为 `{ "ok": false, "error": { "code", "message", "detail" } }`。只读 GET 直接返回资源本体（不包 `ok / result`）。限流：每令牌 50 次/秒（429 `RATE_LIMITED`），`/preflight` 每令牌 2 次/秒，下载同时最多 2 个（429 `DOWNLOAD_BUSY`）；鉴权失败按客户端 IP 每秒最多 10 次，超过直接 429。

```bash
H='Authorization: Bearer devtoken'; B=http://127.0.0.1:18080/api/v1
curl -s $B/health                       # 无需令牌 {"ok":true,"apiVersion":"1.0","simulated":true,"bootId":"...","serverTime":"..."}
curl -s -H "$H" $B/device               # 型号 / 序列号 / 版本 / 已安装通道 / 硬件配置 / bootId / eventSeqHead
curl -s -H "$H" $B/snapshot             # 最新遥测帧（§6.3）：8 通道 + 全局；第一个 Tick 之前为 503 STARTING
curl -s -H "$H" $B/channels             # { seq, ts, installedChannels, channels[] }
curl -s -H "$H" $B/channels/1           # 单通道详情，总带 profile（曲线全部段）与 approach；9 → 404 CHANNEL_NOT_FOUND
curl -s -H "$H" "$B/events?afterSeq=0&limit=100"   # { seqEpoch, eventSeqHead, afterSeq, count, more, items[] }
curl -s -H "$H" "$B/alarms?state=active"           # 当前界面报警列表副本（state: active / ack / cleared / done）
curl -s -H "$H" $B/settings             # §6.7 形状，带 revision
curl -s -H "$H" $B/program-schema       # 程序步骤 schema：字段、生效范围、枚举码 ↔ 中文 label
curl -s -H "$H" $B/preflight            # 预运行检查（唯一进 UI 线程的读取，纯计算不改界面；5 s 超时 → 503 UI_THREAD_TIMEOUT；限 2 次/秒）
curl -s -H "$H" $B/device/comm          # 四条总线统计 + 控制循环门闸（tick）+ 接口统计（api：clients / droppedTelemetryFrames / droppedEvents / authFailures…）+ 记录器丢行
```

历史与文件（只读；文件名有白名单，`..` / 分隔符一律 404）：

```bash
curl -s -H "$H" "$B/files?type=telemetry"              # type: telemetry | events | sessions | leak
curl -s -H "$H" -o t.csv "$B/files/telemetry/telemetry-20261107.csv"     # 支持 Range / ETag
curl -s -H "$H" -o e.jsonl "$B/files/events/events-20261107.jsonl"
curl -s -H "$H" "$B/telemetry?from=2026-11-06T08:00:00Z&to=2026-11-06T09:00:00Z" -o range.csv   # [from,to) 流式 CSV；from/to 必须带时区；跨表头不同的文件按列名对齐到第一个表头
curl -s -H "$H" $B/leak-tests                           # 泄漏测试列表
curl -s -H "$H" $B/leak-tests/leak-20261106-060000      # summary.json 原文
curl -s -H "$H" -o d.csv $B/leak-tests/leak-20261106-060000/data.csv
curl -s -H "$H" $B/sessions                             # 会话文件列表 + current
curl -s -H "$H" $B/sessions/current                     # 无会话 → 404
```

## 3. WebSocket `/api/v1/ws`

握手带同一个 `Authorization: Bearer` 头（**不支持 `?access_token=`**）。连接后服务端先发 `hello`，紧接着推一帧当前遥测，之后每个 Tick（1.2 s）一帧；事件 / 报警发生时立即推。

```json
// S→C
{ "type":"hello","apiVersion":"1.0","serverTime":"…","clockSynced":null,"bootId":"13e06ddc","simulated":true,
  "seqEpoch":1,"eventSeqHead":8,"telemetrySeqHead":53,"control":{"control":"local","holder":null},"eventRingSize":5000 }
{ "type":"telemetry", … 与 /snapshot 相同 … }
{ "type":"event", … 与 /events 的一条相同 … }
{ "type":"alarm","alarm":{ "id":"3","level":"err","rv":"RV2","channel":2,"title":"超压 · 联锁动作","message":"…","raisedAt":"…","state":"active","clearedAt":null } }
{ "type":"subscribed","topics":["telemetry","events","alarms"],"replayed":8,"eventSeqHead":8 }
{ "type":"resynced","topics":[],"replayed":12,"eventSeqHead":20 }
{ "type":"gap","reason":"gap_too_large","eventSeqHead":29001,"oldestBufferedSeq":19002 }   // 缺口不在 5000 条环内：改用 GET /events 分页补齐，再 GET /snapshot
{ "type":"pong","ts":"…" }
{ "type":"error","code":"BAD_REQUEST","message":"…" }

// C→S
{ "type":"subscribe","topics":["telemetry","events","alarms"],"resumeAfterEventSeq":18100,"seqEpoch":1 }   // 不发 subscribe 默认全订阅
{ "type":"resync","afterSeq":18100 }    // 从环补发（每次最多 1000 条）
{ "type":"ping" }                        // → pong
{ "type":"hb","lease":"<leaseId>" }      // 带当前租约 = 远程心跳（§5）；不带只保活；无效租约回 error
{ "type":"unsubscribe" }
```

背压：每连接遥测队列 50 帧，满则丢最旧（计入 `/device/comm` 的 `api.droppedTelemetryFrames`）；事件队列满（2000）或单帧发送超过 10 s 则以 1008 断开，客户端重连后用 `resumeAfterEventSeq` 续传；服务端中枢事件队列溢出（计入 `api.droppedEvents`）时所有连接同样 1008。事件消息严格按 `seq` 递增到达，记住最大 `seq` 即可。连接 / 断开各记一条事件（同一客户端 10 秒内只记一条）。

.NET 客户端示例：

```csharp
using var ws = new ClientWebSocket();
ws.Options.SetRequestHeader("Authorization", "Bearer " + token);
await ws.ConnectAsync(new Uri("ws://192.168.10.20:8080/api/v1/ws"), ct);
await ws.SendAsync(Encoding.UTF8.GetBytes("""{"type":"subscribe","topics":["telemetry","events","alarms"],"resumeAfterEventSeq":0}"""), WebSocketMessageType.Text, true, ct);
var buf = new byte[256 * 1024];
while (ws.State == WebSocketState.Open)
{
    using var ms = new MemoryStream();
    WebSocketReceiveResult r;
    do { r = await ws.ReceiveAsync(buf, ct); ms.Write(buf, 0, r.Count); } while (!r.EndOfMessage);
    var msg = JsonDocument.Parse(ms.ToArray());   // 按 msg.RootElement.GetProperty("type") 分发
}
```

## 4. 排错

| 现象 | 原因 / 处理 |
|---|---|
| 连不上、`/health` 也没响应 | `enabled=false` 或配置文件路径不对：看事件文件里来源「接口」的「接口已启动」一条，其 `message` 带实际读取的配置文件名（目录见 §1.1）与端口；绑定失败会有「接口绑定失败 · 10 秒后重试」（之后每 10 分钟最多一条，带累计次数） |
| 401 `UNAUTHORIZED` | 没带 `Authorization: Bearer`，或令牌哈希不在 `tokens` 里（哈希要对令牌**明文**算、不含换行；`echo -n`）。事件「接口鉴权失败」同一地址每分钟只记一条，累计数在 `/device/comm.api.authFailures`；「接口未配置任何令牌」说明 `tokens` 为空 |
| 403 `IP_NOT_ALLOWED` | 客户端地址不在 `allowedCidrs`；列表为空只放行本机。注意 NAT / 代理后的来源地址 |
| 503 `STARTING` | HMI 刚启动，第一个控制周期还没跑完，重试即可 |
| 503 `TOO_MANY_CLIENTS` | WS 连接数达到 `maxClients`，先断开旧连接 |
| 503 `UI_THREAD_TIMEOUT` | UI 线程 5 s 内没响应，命令 / 读取已撤销、确定未执行，可重试 |
| 504 `OUTCOME_UNKNOWN` | 命令已进入 UI 线程但 5 s 内没执行完：**不要直接重发**，用同一 `Idempotency-Key` 重发会等待 / 返回最终结果（`op.<action>.result` 事件带同一 opId） |
| 409 `MODE_LOCAL` / `NOT_CONTROL_HOLDER` / `CONTROL_LEASE_EXPIRED` | 本地模式下的控制类写 / 远程模式下没带（或带错）`X-Control-Lease` / 租约已作废（宽限期满、本地切回、急停）：先 `POST /control/request` 拿租约 |
| 428 `PRECONDITION_REQUIRED` | 非幂等 POST 没带 `Idempotency-Key`（`/run`、`program/run`、`program/copy`、`/leak-tests`、`/sessions`、`/sessions/current/markers`、`/channels/copy-config`、`/control/request`） |
| 403 `FORBIDDEN_ROLE` | viewer 令牌写命令、operator 改 PID、无 `estop` 位的令牌 `/estop` |
| 429 | 超过 50 次/秒、`/preflight` 超过 2 次/秒、下载并发超过 2，或同一地址每秒鉴权失败超过 10 次；看 `Retry-After` |
| 遥测帧 `tempC` / `pressurePsi` 为 null | 对应总线离线（`comm.temp / pressure` 为 false），不是 0 |
| `simulated: true` | HMI 以 `PR_SIM=1` 运行，读数不是真实设备 |

## 5. 写接口与控制权（P3）、测试会话（P4）

写命令（POST / PUT / DELETE）响应统一为 `{ "ok", "opId", "status": "confirmed"|"accepted", "result", "warnings", "opEventSeq" }`，失败为 `{ "ok":false, "opId", "error":{ "code","message","detail" }, "opEventSeq" }`（§7.1）。`opId` = 请求头 `Idempotency-Key`，没带时服务端生成；`opEventSeq` 是这条命令的 `op.<action>` 审计事件的 seq，快照的 `eventSeqApplied ≥ opEventSeq` 即表示快照已反映命令的同步部分。

三类写命令（§5.1）：**控制类**（启用 / 启动加热 / 改 SP / 曲线 / 程序 / 泄漏测试 / 开搅拌 / PID …）只有远程模式下的**租约持有者**能做，请求头带 `X-Control-Lease: <leaseId>`；**停止类**（`/estop`、`/stop-all`、通道 stop / disable、heat/stop、profile/stop、`DELETE autotune`、`DELETE program/run`、`DELETE /leak-tests/current`、`PUT /stir {"on":false}`）任何模式都允许、不需要租约；**记录类**（报警确认、会话、打点、申请控制权）任何模式都允许。控制类 / 记录类需要 `operator` 角色；停止类需要 `operator` **或** `estop` 权限位（监视工位可配 `viewer + estop`：能看、能停、不能启动）；`/estop` 只看 `estop` 权限位。`Idempotency-Key` 按令牌隔离：同键只在同一令牌内重放 / 等待。

### 5.1 完整走通（开发机 PR_SIM=1 + autoGrantRemote=true；令牌 `optoken` 为 operator）

```bash
B=http://127.0.0.1:18091/api/v1; H='Authorization: Bearer optoken'; J='Content-Type: application/json'

# 0 本地模式：控制类写 → 409 MODE_LOCAL
curl -s -X POST -H "$H" -H "$J" -d '{"tempC":80}' $B/channels/1/heat/start
# {"ok":false,"opId":"…","error":{"code":"MODE_LOCAL","message":"本地控制中 · 远程只能执行停止类和记录类操作","detail":null},"opEventSeq":8}

# 1 申请控制权（必须带 Idempotency-Key）。autoGrant → 202 granted 直接带 leaseId；否则 202 pending，触屏允许后带 requestKey 轮询 GET /control/requests/{id} 才有 leaseId
#   requestKey 只在这次响应里给一次：WS control 消息不带 leaseId，不带 X-Control-Request-Key 的轮询（同令牌的另一台 PC）只看到结果字样
curl -s -X POST -H "$H" -H "$J" -H "Idempotency-Key: $(uuidgen)" -d '{"clientName":"PC-测试工位1"}' $B/control/request
# {"ok":true,"opId":"…","status":"accepted","result":{"requestId":"a7269bdf8f151c29","result":"granted","expiresAt":null,
#   "leaseId":"4bda5369…","leaseExpiresAt":"2026-11-07T06:10:45Z","heartbeatTimeoutSec":3,"leaseGraceSec":3,"requestKey":"947c26b2…"},"warnings":[],"opEventSeq":11}
L='X-Control-Lease: 4bda5369…'
curl -s -H "$H" -H "X-Control-Request-Key: 947c26b2…" $B/control/requests/a7269bdf8f151c29   # {"result":"pending|granted|denied|expired","leaseId":…}
curl -s -H "$H" $B/control/requests/a7269bdf8f151c29   # 不带凭据：{"result":"granted","leaseId":null,…}
curl -s -H "$H" $B/control                             # {"mode":"remote","holder":"PC-测试工位1","holderToken":"PC-测试工位1","state":"remote",…}
# clientName 会被清洗（控制 / 零宽 / 双向字符去掉、换行折叠成空格、≤ 64 字符）；触屏弹窗与顶栏显示「客户端名 · 令牌 xxx」
# 触屏拒绝 / 申请超时后同令牌 30 s 内再申请 → 429 RATE_LIMITED（autoGrant 不限）

# 2 心跳：每 ≤ heartbeatTimeoutSec/2 一次（REST，或 WS {"type":"hb","lease":"<leaseId>"}）。宽限期内凭同一 leaseId 心跳即恢复；心跳有独立限流分区（10 次/秒/令牌），写命令刷满配额也不会把心跳 429 掉
#   丢了 leaseId（客户端崩溃）：宽限期内用同一令牌 + 同一 clientName 再 POST /control/request → 旧租约作废（control.mode）、直接拿到新租约
curl -s -X POST -H "$H" -H "$L" $B/control/heartbeat
# {"ok":true,"status":"confirmed","result":{"mode":"remote","resumed":false,"leaseExpiresAt":…,"leaseHardExpiresAt":…,"heartbeatTimeoutSec":3},"opEventSeq":0}

# 3 远程模式下没带 / 带错租约 → 409 NOT_CONTROL_HOLDER
curl -s -X POST -H "$H" -H "$J" -d '{"tempC":80}' $B/channels/1/heat/start      # "远程模式下受控写命令须带 X-Control-Lease"

# 4 启用通道（远程严格守卫：启动加热前通道须为 已启用 / 已结束）→ 启动加热（202 accepted，硬件结果看事件）→ 改 SP
for i in 1 2 3; do curl -s -X POST -H "$H" -H "$L" $B/channels/$i/enable; done   # 200 confirmed
curl -s -X POST -H "$H" -H "$L" -H "$J" -d '{"tempC":80}' $B/channels/3/heat/start
# {"ok":true,"status":"accepted","result":{"tempC":80},"warnings":[],"opEventSeq":17}
curl -s -X PUT  -H "$H" -H "$L" -H "$J" -d '{"tempC":90}' $B/channels/3/temperature/setpoint
# {"ok":true,"status":"confirmed","result":{"channel":3,"tempSpC":90,"applied":false,"coalesced":false,"approachReplanned":true},…}
curl -s -H "$H" $B/channels/3   # channel.state=heating startedBy="远程（PC-测试工位1）" tempSpC=90 approach.phase=settle（clientName 与令牌名不同时为「远程（PC-x · 令牌 xxx）」）

# 5 程序：PUT 整体替换（§6.9 形状，sel 字段用枚举码）→ 下发运行（Idempotency-Key 必填，202）。每通道可各跑一个，RV1 / RV2 并行；
#   两个程序都带气路步骤时共享一套气路：后到的在 waitingGas 排队，前者吹扫完再接着做
PROG='{"steps":[{"type":"purge","params":{"gas":"inert","cycles":2,"fill":3,"vent":3}},{"type":"heat","params":{"mode":"fixed","temp":60,"wait":0.1}}]}'
curl -s -X PUT  -H "$H" -H "$L" -H "$J" -d "$PROG" $B/channels/1/program        # {"ok":true,"status":"confirmed","result":{"rv":1,"steps":2},…}
curl -s -X PUT  -H "$H" -H "$L" -H "$J" -d "$PROG" $B/channels/2/program
curl -s -X POST -H "$H" -H "$L" -H "$J" -H "Idempotency-Key: run-rv1-001" -d '{}' $B/channels/1/program/run   # 202 result {"rv":1,"steps":2}
curl -s -X POST -H "$H" -H "$L" -H "$J" -H "Idempotency-Key: run-rv2-001" -d '{}' $B/channels/2/program/run
curl -s -H "$H" $B/snapshot | jq '.programs'    # {"running":2,"channels":[1,2],"gasHolder":2,"waitingGas":[1],"summary":"正在运行：RV1 RV2"} → 十几秒后 gasHolder=1,waitingGas=[]
# 同键重发（断线重试）：原命令仍在执行 → 等 ≤ 5 s；仍未完成 → 409 IDEMPOTENCY_IN_PROGRESS（条目保留，之后再重发仍是重放，不会执行第二次）
# 越界示例：temp 999 → 422 PARAM_OUT_OF_RANGE，detail {"step":1,"field":"temp","value":999,"min":0,"max":300}
curl -s -X DELETE -H "$H" $B/channels/1/program/run    # 中止（停止类，免租约）

# 6 会话（记录类，免租约；Idempotency-Key 必填）→ 打点 → 当前会话（manifest）→ 带 sessionId 下发程序
curl -s -X POST -H "$H" -H "$J" -H "Idempotency-Key: sess-001" -d '{"testId":"TP-017","note":"P3 验收"}' $B/sessions
# {"ok":true,"status":"confirmed","result":{"id":"TP-017-20261107-162035","testId":"TP-017","startedAt":…,"startEventSeq":26,"file":"TP-017-20261107-162035.csv"},…}
curl -s -X POST -H "$H" -H "$J" -H "Idempotency-Key: mk-001" -d '{"text":"开始升温"}' $B/sessions/current/markers
# {"ok":true,"result":{"id":1,"text":"开始升温","ts":…,"seq":29,"sessionId":"TP-017-20261107-162035"},…}；同键重发 → 同一响应 + 头 Idempotent-Replay: true
curl -s -X POST -H "$H" -H "$L" -H "$J" -H "Idempotency-Key: run-rv4-001" -d '{"sessionId":"TP-017-20261107-162035"}' $B/channels/4/program/run
curl -s -H "$H" $B/sessions/current
# {"active":true,"id":"TP-017-20261107-162035","testId":"TP-017","file":"…csv","manifest":{…,"markers":[{"id":1,…}],"programRuns":[{"rv":4,"startedAt":…,"startedBy":"远程（PC-测试工位1）"}],"leakTests":[]},"files":["sessions/….json"]}
curl -s -X POST -H "$H" -H "$J" -H "Idempotency-Key: sess-002" -d '{"testId":"TP-018"}' $B/sessions   # 409 SESSION_ACTIVE

# 7 释放控制权 → 本地；结束会话（只有创建者令牌或触屏，否则 403 SESSION_NOT_OWNER）
curl -s -X POST -H "$H" -H "$L" $B/control/release      # {"ok":true,"result":{"mode":"local"},…}
curl -s -X DELETE -H "$H" $B/sessions/current           # {"ok":true,"result":{"id":"TP-017-…","endedAt":…},…}
curl -s -H "$H" $B/sessions/TP-017-20261107-162035     # manifest state=ended + files[csv,json]
curl -s -H "$H" -o s.json $B/files/sessions/TP-017-20261107-162035.json

# 8 急停：两种模式都允许，需要 estop 权限位（operator / admin 默认有，"estop": false 可收回），独立限流分区 5 次/秒/令牌；始终 202，快照 estop.active 由下一 Tick 反映；控制权强制回本地、租约作废
curl -s -X POST -H "$H" -H "$J" -d '{"note":"压力异常"}' $B/estop     # {"ok":true,"status":"accepted","result":{"source":"远程（PC-测试工位1）"},…}
curl -s -H "$H" $B/snapshot | jq '{mode, estop}'   # mode.control="local"，estop.active=true，heat/stir/valves="ok"
```

停心跳的表现：最后一次心跳 / 带租约命令之后 `heartbeatTimeoutSec` 秒进入 RemoteLost（事件 `control.lost`，WS `control` event=lost，触屏提示「远程连接丢失，设备继续运行」，设备不变），再过 `leaseGraceSec` 秒租约作废、回到本地（`control.expired`，按 `onRemoteLost` 处理）；之后带旧租约的写 → 409 `MODE_LOCAL`（本地模式先于租约判断），重新授权后旧租约 → 409 `CONTROL_LEASE_EXPIRED`。

## 6. 已知限制

- 多程序并行（v0.5）：每通道可各跑一个程序；程序状态读 `channels[i].program` 与 `programs`，顶层 `program` 已废弃（过渡一个版本）。运行记录 CSV 末尾追加 8 列 `RVx_程序步`（「序号/阶段」，如 `3/running`、`2/waitingGas`），旧表头文件会按 DataLogger 规则另起新文件。气路规则见设计稿 §7.12：程序之间排队共享；有程序在稳压（脉冲间隙）或排队等待时，泄漏测试 / 手动阀控仍按 `GAS_BUSY` 拒绝（「RVx 程序 · 稳压进行中 …」）；其他通道的超温报警不再阻塞 / 中止程序的气路步骤，超压未解除仍一律阻塞。

- 只有 HTTP（`httpsPort / certPath` 不生效）。P3 / P4 未做的：本地主动选客户端授权、程序 `revision` / `If-Match`、`GET /channels/{id}/program`、`PATCH /sessions/{id}`、会话 `export.zip`、`temp.spWritten` 事件（详见设计稿 §14.2）。
- 现有 VM 事件的 `kind` 仍由来源 / 标题推导（见设计稿 §6.4）；`control.*` / `op.*` 为显式 kind，`source` 为 `remote` 并带 `client / opId`；`seqEpoch` 恒 1。
- 历史接口只有文件级与时间段 CSV；行号续传（`afterRow`）、长表、降采样、导出包依赖 P0 契约 K5–K8。
- `/alarms` 是界面报警列表（本次运行）的副本，不是按 §6.5 的报警生命周期模型。
- 性能数字来自开发机模拟运行（P2：3 个 WS 客户端 60 s，Tick 中位数 1.203 s、P99 1.207 s、丢帧 0；P3 走通（第二轮，端口 18093）：2 个 WS 客户端 + 全部写命令 + 4 个程序并行，全程 P99 1.208 s / 最大 1.211 s（n=65），走通窗口 P99 1.205 s（n=21）、丢帧 0）；ARM 面板实测待 P5。
