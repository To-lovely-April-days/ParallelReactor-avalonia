# ParallelReactor HMI 对外只读接口 · 使用说明（P2）

> 协议的唯一依据是《对外通讯接口设计》（`doc/对外通讯接口设计.md`，v0.3，§14.1 列出实现偏差）。本文只讲怎么开通、怎么调。
> 代码：`Api/`（接口层）、`Api/Hmi/`（HMI 适配）、`Service/EventStore.cs`（带 seq 的事件存储）。P2 **只读**：没有任何写命令。

## 1. 开通

### 1.1 配置文件 `api.json`

与 `settings.json` 同目录（Linux：`~/.config/ParallelReactor/api.json`；模拟模式 `PR_SIM=1` 读 **`api-sim.json`**）。目录可用环境变量 `PR_CONFIG_DIR` 覆盖。文件不存在或损坏 → 按默认值运行（`enabled=false`，Kestrel 完全不启动）并记一条事件。

```json
{
  "enabled": true,
  "bind": "0.0.0.0",
  "httpPort": 8080,
  "allowedCidrs": ["192.168.10.0/24"],
  "tokens": [
    { "name": "PC-测试工位1", "sha256": "9428e07c68054de014032f21e0716501aa937714fd31033caf589e66b276e53b", "role": "viewer", "estop": false }
  ],
  "maxClients": 4,
  "serial": "PR8-2026-0001"
}
```

| 字段 | 说明 |
|---|---|
| `enabled` | false（默认）时不启动接口 |
| `bind` / `httpPort` | 默认 `0.0.0.0:8080`。绑定失败（端口被占等）记事件 `system.apiBindFailed`（首次一条，之后每 10 分钟最多一条），每 10 s 重试 |
| `httpsPort` / `certPath` | **P2 未实现**：读取但不生效，配置了记一条 warn 事件。只有 HTTP，令牌明文传输，依赖网段隔离与 `allowedCidrs` |
| `allowedCidrs` | 允许的网段（IPv4 / IPv6 CIDR）。**为空时只允许本机回环地址**；不在白名单内一律 403 `IP_NOT_ALLOWED`（含 `/health`） |
| `tokens[]` | 预共享令牌，只存 SHA-256（小写 / 大写十六进制都可）；`role` = viewer / operator / admin（P2 只读，任何角色都可读）；`estop` 为 P3 用的急停权限位 |
| `maxClients` | WebSocket 并发连接上限（默认 4），超过握手返回 503 `TOO_MANY_CLIENTS` |
| `serial` | 设备序列号，`/device` 原样返回；不配为 null |

生成令牌与哈希（令牌明文只给客户端，`api.json` 只放哈希）：

```bash
TOKEN=$(openssl rand -hex 32); echo "token=$TOKEN"
python3 -c "import hashlib,sys; print(hashlib.sha256(sys.argv[1].encode()).hexdigest())" "$TOKEN"
# 或：echo -n "$TOKEN" | shasum -a 256
```

### 1.2 环境变量（开发 / 验收）

| 变量 | 作用 |
|---|---|
| `PR_API=1` / `PR_API=0` | 强制启用 / 关闭接口（覆盖 `enabled`） |
| `PR_API_PORT=18080` | 覆盖 `httpPort` |
| `PR_CHANNELS=1-4` | 已安装通道（`/device.installedChannels`、`channels[].installed`），默认 1–8；语法 `1-4`、`1,3,5-8` |
| `PR_CONFIG_DIR` | 配置目录（`settings.json`、`api.json`） |
| `PR_DATA_DIR` | 数据目录（运行记录 / 事件 / 会话 / 泄漏测试文件，接口的历史数据来源） |
| `PR_SIM=1` | 内存模拟硬件（所有响应的 `simulated` 为 true） |
| `PR_HEADLESS=1` | 无头运行（无显示器 / 无 WindowServer 的开发机上跑完整的 VM + 控制循环 + 接口）。只在 **Debug 构建**里存在，Release 发布包不带 |

开发机验收用的一条命令（数据与配置都放到临时目录）：

```bash
S=/tmp/pr-api; mkdir -p $S/config $S/data
HOME=$S/home PR_CONFIG_DIR=$S/config PR_DATA_DIR=$S/data PR_HEADLESS=1 PR_SIM=1 PR_API=1 PR_API_PORT=18080 ./bin/Debug/net8.0/ParallelReactor &
```

## 2. REST（前缀 `/api/v1`，全部 GET）

所有请求带 `Authorization: Bearer <token>`（`/health` 除外）。响应 `application/json; charset=utf-8`，UTC 时间、camelCase；失败为 `{ "ok": false, "error": { "code", "message", "detail" } }`。只读 GET 直接返回资源本体（不包 `ok / result`）。限流：每令牌 50 次/秒（429 `RATE_LIMITED`），`/preflight` 每令牌 2 次/秒，下载同时最多 2 个（429 `DOWNLOAD_BUSY`）；鉴权失败按客户端 IP 每秒最多 10 次，超过直接 429。

```bash
H='Authorization: Bearer devtoken'; B=http://127.0.0.1:18080/api/v1
curl -s $B/health                       # 无需令牌 {"ok":true,"apiVersion":"1.0","simulated":true,"bootId":"...","serverTime":"..."}
curl -s -H "$H" $B/device               # 型号 / 序列号 / 版本 / 已安装通道 / 硬件配置 / bootId / eventSeqHead
curl -s -H "$H" $B/snapshot             # 最新遥测帧（§6.3）：8 通道 + 全局；第一个 Tick 之前为 503 STARTING
curl -s -H "$H" $B/channels             # { seq, ts, installedChannels, channels[] }
curl -s -H "$H" $B/channels/1           # 单通道详情，总带 profile（曲线全部段）与 approach；9 → 404 CHANNEL_NOT_FOUND
curl -s -H "$H" "$B/events?afterSeq=0&limit=100"   # { seqEpoch, eventSeqHead, afterSeq, count, more, items[] }
curl -s -H "$H" "$B/alarms?state=active"           # 当前界面报警列表副本（state: active / ack / cleared / done）
curl -s -H "$H" $B/settings             # §6.7 形状，带 revision
curl -s -H "$H" $B/program-schema       # 程序步骤 schema：字段、生效范围、枚举码 ↔ 中文 label
curl -s -H "$H" $B/preflight            # 预运行检查（唯一进 UI 线程的读取，纯计算不改界面；5 s 超时 → 503 UI_THREAD_TIMEOUT；限 2 次/秒）
curl -s -H "$H" $B/device/comm          # 四条总线统计 + 控制循环门闸（tick）+ 接口统计（api：clients / droppedTelemetryFrames / droppedEvents / authFailures…）+ 记录器丢行
```

历史与文件（只读；文件名有白名单，`..` / 分隔符一律 404）：

```bash
curl -s -H "$H" "$B/files?type=telemetry"              # type: telemetry | events | sessions | leak
curl -s -H "$H" -o t.csv "$B/files/telemetry/telemetry-20261107.csv"     # 支持 Range / ETag
curl -s -H "$H" -o e.jsonl "$B/files/events/events-20261107.jsonl"
curl -s -H "$H" "$B/telemetry?from=2026-11-06T08:00:00Z&to=2026-11-06T09:00:00Z" -o range.csv   # [from,to) 流式 CSV；from/to 必须带时区；跨表头不同的文件按列名对齐到第一个表头
curl -s -H "$H" $B/leak-tests                           # 泄漏测试列表
curl -s -H "$H" $B/leak-tests/leak-20261106-060000      # summary.json 原文
curl -s -H "$H" -o d.csv $B/leak-tests/leak-20261106-060000/data.csv
curl -s -H "$H" $B/sessions                             # 会话文件列表 + current
curl -s -H "$H" $B/sessions/current                     # 无会话 → 404
```

## 3. WebSocket `/api/v1/ws`

握手带同一个 `Authorization: Bearer` 头（**不支持 `?access_token=`**）。连接后服务端先发 `hello`，紧接着推一帧当前遥测，之后每个 Tick（1.2 s）一帧；事件 / 报警发生时立即推。

```json
// S→C
{ "type":"hello","apiVersion":"1.0","serverTime":"…","clockSynced":null,"bootId":"13e06ddc","simulated":true,
  "seqEpoch":1,"eventSeqHead":8,"telemetrySeqHead":53,"control":{"control":"local","holder":null},"eventRingSize":5000 }
{ "type":"telemetry", … 与 /snapshot 相同 … }
{ "type":"event", … 与 /events 的一条相同 … }
{ "type":"alarm","alarm":{ "id":"3","level":"err","rv":"RV2","channel":2,"title":"超压 · 联锁动作","message":"…","raisedAt":"…","state":"active","clearedAt":null } }
{ "type":"subscribed","topics":["telemetry","events","alarms"],"replayed":8,"eventSeqHead":8 }
{ "type":"resynced","topics":[],"replayed":12,"eventSeqHead":20 }
{ "type":"gap","reason":"gap_too_large","eventSeqHead":29001,"oldestBufferedSeq":19002 }   // 缺口不在 5000 条环内：改用 GET /events 分页补齐，再 GET /snapshot
{ "type":"pong","ts":"…" }
{ "type":"error","code":"BAD_REQUEST","message":"…" }

// C→S
{ "type":"subscribe","topics":["telemetry","events","alarms"],"resumeAfterEventSeq":18100,"seqEpoch":1 }   // 不发 subscribe 默认全订阅
{ "type":"resync","afterSeq":18100 }    // 从环补发（每次最多 1000 条）
{ "type":"ping" }                        // → pong
{ "type":"hb" }                          // 保活，P2 无租约语义
{ "type":"unsubscribe" }
```

背压：每连接遥测队列 50 帧，满则丢最旧（计入 `/device/comm` 的 `api.droppedTelemetryFrames`）；事件队列满（2000）或单帧发送超过 10 s 则以 1008 断开，客户端重连后用 `resumeAfterEventSeq` 续传；服务端中枢事件队列溢出（计入 `api.droppedEvents`）时所有连接同样 1008。事件消息严格按 `seq` 递增到达，记住最大 `seq` 即可。连接 / 断开各记一条事件（同一客户端 10 秒内只记一条）。

.NET 客户端示例：

```csharp
using var ws = new ClientWebSocket();
ws.Options.SetRequestHeader("Authorization", "Bearer " + token);
await ws.ConnectAsync(new Uri("ws://192.168.10.20:8080/api/v1/ws"), ct);
await ws.SendAsync(Encoding.UTF8.GetBytes("""{"type":"subscribe","topics":["telemetry","events","alarms"],"resumeAfterEventSeq":0}"""), WebSocketMessageType.Text, true, ct);
var buf = new byte[256 * 1024];
while (ws.State == WebSocketState.Open)
{
    using var ms = new MemoryStream();
    WebSocketReceiveResult r;
    do { r = await ws.ReceiveAsync(buf, ct); ms.Write(buf, 0, r.Count); } while (!r.EndOfMessage);
    var msg = JsonDocument.Parse(ms.ToArray());   // 按 msg.RootElement.GetProperty("type") 分发
}
```

## 4. 排错

| 现象 | 原因 / 处理 |
|---|---|
| 连不上、`/health` 也没响应 | `enabled=false` 或配置文件路径不对：看事件文件里来源「接口」的「接口已启动」一条，其 `message` 带实际读取的配置文件名（目录见 §1.1）与端口；绑定失败会有「接口绑定失败 · 10 秒后重试」（之后每 10 分钟最多一条，带累计次数） |
| 401 `UNAUTHORIZED` | 没带 `Authorization: Bearer`，或令牌哈希不在 `tokens` 里（哈希要对令牌**明文**算、不含换行；`echo -n`）。事件「接口鉴权失败」同一地址每分钟只记一条，累计数在 `/device/comm.api.authFailures`；「接口未配置任何令牌」说明 `tokens` 为空 |
| 403 `IP_NOT_ALLOWED` | 客户端地址不在 `allowedCidrs`；列表为空只放行本机。注意 NAT / 代理后的来源地址 |
| 503 `STARTING` | HMI 刚启动，第一个控制周期还没跑完，重试即可 |
| 503 `TOO_MANY_CLIENTS` | WS 连接数达到 `maxClients`，先断开旧连接 |
| 503 `UI_THREAD_TIMEOUT`（`/preflight`） | UI 线程 5 s 内没响应，本次读取已撤销，可重试 |
| 429 | 超过 50 次/秒、`/preflight` 超过 2 次/秒、下载并发超过 2，或同一地址每秒鉴权失败超过 10 次；看 `Retry-After` |
| 遥测帧 `tempC` / `pressurePsi` 为 null | 对应总线离线（`comm.temp / pressure` 为 false），不是 0 |
| `simulated: true` | HMI 以 `PR_SIM=1` 运行，读数不是真实设备 |

## 5. 已知限制（P2）

- 只读；写命令、控制权、租约、心跳在 P3。只有 HTTP（`httpsPort / certPath` 不生效）。
- 事件 `kind` 由来源 / 标题推导（见设计稿 §6.4），`source` 恒 `system`；`seqEpoch` 恒 1。
- 历史接口只有文件级与时间段 CSV；行号续传（`afterRow`）、长表、降采样、导出包依赖 P0 契约 K5–K8。
- `/alarms` 是界面报警列表（本次运行）的副本，不是按 §6.5 的报警生命周期模型。
- 性能数字来自开发机模拟运行（3 个 WS 客户端 60 s：Tick 中位数 1.203 s、P99 1.207 s、丢帧 0）；ARM 面板实测待 P5。
