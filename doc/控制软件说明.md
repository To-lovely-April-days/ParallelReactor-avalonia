## 1. 用途与组成

PC 控制软件是触屏 HMI 的**远程客户端**：通过 HMI 对外接口（REST + WebSocket）同时看多台设备的实时状态（每台 4 / 8 / 16 路）、编辑并下发程序（单路或条件矩阵）、记录与对比会话、处理报警，
并内置 **RV1–RV4 摸底性能测试模块**（按 `test-plan/RV1-4摸底性能测试方案.md` 编码的测试项，自动采集 + 人工录入 + 报告）和泄漏测试。

硬件按用户确认的事实写（界面、程序、演示数据都照这个）：

- 釜是 10 mL 的小釜；压力一律是**表压**。
- **一台电机经齿轮带动全部釜的搅拌**：界面上的转速是**釜里的转速**，上限 450 rpm；所以没有「单釜搅拌」，停止一路不停搅拌。
- 三路气源只叫 **惰性气体 / 气体 A / 气体 B**，接什么气由工艺决定，软件里不写气体种类。
- **吸气量（mmol）由设备（HMI）按压降计算**，PC 只显示（快照 `gasConsumed` / `gasRate`）；釜容积、管路死体积、标定只在触屏上做，PC 只读。
- 停止一律先确认（全部停止、急停、停止通道、停止程序、取消自整定；例外见 §4.10 与 §8）。
- 型号表（`Control.Core/Models/models.json`）里的型号参数是**示例、参数为假设**（状态栏右端写「示例型号 · 参数为假设」），等真实规格。

## 2. 构建与运行

需要 .NET 8 SDK（8.0.4xx）。

```bash
cd ParallelReactor-avalonia-fusion
dotnet build ParallelReactor.sln -c Debug          # 全部工程
dotnet run --project Control/ParallelReactor.Control   # 启动 PC 控制软件（自绘标题栏，默认 1440×900；不设最小尺寸，窄于 1366 或矮于 768 时外框等比缩小）
dotnet test Control/tests/ParallelReactor.Control.Tests      # PC 端单元测试（不引用 App）
dotnet test Control/tests/ParallelReactor.Control.App.Tests  # App 的视图模型、页面、对话框与实时数据源（引用 App）
dotnet test ParallelReactor.sln -c Debug                     # 两个 PC 测试工程一起跑（HMI 的 tests/ParallelReactor.Tests 不在解决方案里，另跑）
```

本机看界面不需要设备：Debug 构建用演示数据启动（不连接任何设备，不写配置文件）：

```bash
PR_CONTROL_DEMO=1 dotnet run --project Control/ParallelReactor.Control -c Debug
PR_CONTROL_DEMO=1 PR_CONTROL_ROUTE='prog?dev=1&pgm=one' dotnet run --project Control/ParallelReactor.Control -c Debug   # 起始页面与参数（§7）
```

演示窗口旁边有「演示控制」工具窗口（控制权、断线、报警、急停、设备组合、冻结、重置）。

发布（示例，Windows x64 自包含）：

```bash
dotnet publish Control/ParallelReactor.Control -c Release -r win-x64 --self-contained -p:PublishSingleFile=true -o out/control-win
```

Release 构建不含无头 / 截图平台（`Avalonia.Headless` 仅 Debug 引用），也没有演示模式。

触屏 HMI 侧需要先打开接口：配置文件 `api.json`（或模拟 `api-sim.json`）里 `enabled=true`，并发放令牌（见《接口使用说明.md》§2）。本机联调可用模拟 HMI：

```bash
PR_SIM=1 PR_HEADLESS=1 PR_API=1 PR_API_PORT=18080 dotnet run --project ParallelReactor.csproj
```

### 2.1 Windows 注意事项

产品目标是 Windows，但融合版是在 macOS 上开发和截图的。下面几样**只在 Windows 上编译过，没有在 Windows 实机上运行过**，交付前要在 Windows 上看一遍：

- **运行中阻止睡眠**：`SetThreadExecutionState(ES_CONTINUOUS | ES_SYSTEM_REQUIRED)`，在 UI 线程上调（只阻止系统睡眠，屏幕照常可以关），`Services/Unattended/SleepInhibitors.cs`。状态栏「运行中 · 已阻止睡眠」只在系统真的接受了申请时出现。
- **报警声音**：winmm `PlaySound("SystemExclamation", SND_ALIAS | SND_ASYNC)`（Win10/11 一声柔和的叮），没有时系统默认提示音；不用「严重停止」声和控制台蜂鸣（用户觉得吓人，2026-11-19）（`Services/Unattended/AlarmSounds.cs`）。
- **字体**：Windows 的字体栈是 `Segoe UI, fonts:Cjk#Microsoft YaHei UI, fonts:Cjk#Microsoft YaHei`（`Theme/UiFonts.cs`）。西文和数字用 Segoe UI（有真 600），中文用微软雅黑。
  **中文粗体**（2026-11-18 用户截图：粗体中文发虚）：设计里的粗体是 600，微软雅黑只有 300 / 400 / 700，600 会落到常规体再被「模拟加粗」，小字号下糊成一团。
  中文经字体集合 `fonts:Cjk`（`Theme/CjkFontCollection.cs`）取：501–699 的请求改成雅黑真正的 Bold（700），和浏览器在 Windows 上显示样稿的做法一样；Linux 的 Noto Sans CJK 同理。
  所以 Windows 上中文粗体会比西文的 600 稍重一点。macOS 用苹方（有真 600），不经过它。截图审计都是 macOS 上用 Inter + 苹方（和系统字体栈各一遍）做的，Windows 上的字形要在实机上看。
- **缩放 125 % / 150 %**：Windows 上 Avalonia 按显示器 DPI 缩放，窗口的排版尺寸 = 物理像素 ÷ 缩放。1920×1080 屏幕最大化时，125 % 约 1536×864（窄屏版式：< 1600，设备面板收成竖条），
  150 % 约 1280×720（比 1366×768 小，外框按 `min(1, 宽/1366, 高/768)` 整体缩小，约 0.94），见 `Shell/DockLayout.FrameFor`。这两个排版尺寸可以用 `PR_CONTROL_SHOT_SIZE=1536x864` / `1280x720` 无头渲染来核对版面。
  注意 `PR_CONTROL_UI_SCALE` 只是在启动前把值写进 `AVALONIA_GLOBAL_SCALE_FACTOR`（已设了就不覆盖，`Program.cs`）；Avalonia 11.1 里只有 Linux X11 后端读这个变量，Windows、macOS 和无头平台都不认，
  所以用它渲染出来的仍是 100 %。Windows 实机上的 125 % / 150 % 还没有看过。

## 3. 连接设备、令牌与控制权

### 3.1 连接（M3：多台设备）

同时连多台：每台设备一个接口地址、一个访问令牌、一个控制权（样稿「添加设备」的副标题）。设备列表存在 `devices.json`（§3.4），顺序就是设备管理、设备面板、工具条设备下拉和总览里的顺序。

- **添加设备…**（设备面板灰带的「+」、设置 › 设备连接的「添加设备」、设备管理底栏「添加设备…」）：地址、端口、访问令牌（可显示 / 隐藏）、「记住令牌」（D7，见 §3.4；样稿没有这一栏）、
  别名（输入时就地校验：不能为空、最多 8 个汉字或 16 个字母、不能和别的设备重名，默认第一个没用过的「k号机」）、型号（真机从 `/device` 读，只读；演示是「型号（原型演示）」下拉）、
  启动时「自动连接」（要求勾了「记住令牌」，没勾时带原因不能勾）。样稿里令牌下面那句「在设备触屏「设置 → 远程接口」查看」去掉了：HMI 只存令牌的哈希，触屏上看不到令牌。
  **测试连接** = 先 `GET /health`（不带令牌，只看地址和端口通不通），再 `GET /device`（带令牌：验证令牌、读型号），结果写在底栏左边：「✓ 连接成功 · 读取到 HT-PR8」/「⚠ 连接失败：401 UNAUTHORIZED：…」；
  不建 WebSocket、不申请控制权、不写任何东西。**添加并连接** = 登记（立即写 `devices.json`）、选中新设备、提示「已添加 4号机 · 正在连接 192.168.1.50:8080」，然后在后台连接
  （设备马上出现在列表里，从未连上的设备写「正在连接…」「未连接」；连不上时设备留着，提示一次「4号机 · 连接失败：…」，状态「连接失败 · 2 s 后重试」并倒计时自动重试，见下面的「重连」）。
- **启动**：并行连接勾了「启动时自动连接」**且令牌已经存在本机**的设备（D7：没存令牌的不自动连接）；其余设备「已断开」，在设备管理里点「连接」（要先在「编辑设置」里填令牌）。
  设置 › 常规的全局开关「启动时自动连接」关着时，启动时哪台都不连（各台自己的勾照旧记着，`DeviceRegistry.StartAsync`）。
- **设备管理…**（设备面板灰带的「设备管理 · 重新连接」圆钮）：一张表 别名 · 型号 · SN · 地址 · 状态 · 控制权 · 自动连接 · 操作（断开 / 连接、编辑、移除），每秒刷新；没连上过的设备 SN 取上次连上时记下的。
  真机上「自动连接」那一格要求记住了令牌、令牌也在本机：没勾「记住令牌」时带原因「先勾选「记住令牌」：启动时自动连接要用本机保存的令牌」，
  勾了却没有令牌（记住的读不出来、还没输入）时不打勾、带原因「令牌未保存 · 在「编辑设置」里输入」（M3 复核）。
- **编辑设置…**（设备管理每行的「编辑」、设置 › 设备连接每行的「编辑」）：同一张表单，预填这台的地址、端口、令牌、别名、自动连接；型号只读。改了地址 / 端口 / 令牌且正连着时：先释放本机的控制权（或取消申请），断开，按新地址重新连接
  （对话框里先提示「地址或端口改变后会断开并按新地址重新连接；本机的控制权会先释放。」，只换了令牌时「令牌改变后会断开并用新令牌重新连接…」）；令牌留空 = 不改。换了令牌时，学到的令牌权限（§3.2）作废。
  「保存」存好就关，释放、断开、按新设置的第一次连接都在后台做（结果照常提示；M3 复核：以前对话框要等最长约 13 s）。勾了「记住令牌」而本机还没有这台的令牌时要先填令牌（「请输入访问令牌」）。
- **改别名** / **移除…** / **断开连接…**（设备管理：编辑设置里改别名、每行的「移除」「断开 / 连接」）：别名只改本机（不发给 HMI）；移除前、断开前，本机持有的控制权先释放、正在申请的先取消（本机持有或正在申请时先确认）。
  设备上的程序与数据不受影响，之后可以重新添加。
- **本机客户端名**全局一个（触屏弹窗与审计里显示的名字，深蓝条左边的工位名、菜单栏右端「本机」；HMI 认的控制权持有者也是它）。默认「PC-」+ 这台电脑的计算机名（M3 复核：以前每台都是 `PC-测试工位1`，
  触屏分不清是谁，两台都用默认名时本机会把另一台 PC 的控制权当成自己的）：第一次运行时就写进 `devices.json`；v1 迁移时客户端名还是旧默认 `PC-测试工位1` 的也换成这个（提示一次）。
  在两处改（真机；演示数据改不了）：点深蓝条上的工位名（打开「本机客户端名」对话框），或设置 › 常规的「本机客户端名」（工具条「保存」时写入）。一栏输入，不能为空、最多 64 个字符
  （按 HMI 的规则去掉控制 / 零宽字符），保存后写进 `devices.json`；已经连着的设备在下次连接时改用新名字（HMI 认的持有者照旧是建连接时的名字）。启动时也可以用 `PR_CONTROL_CLIENT` 覆盖。

**重连（M3 的重连监督，`Services/LiveDeviceSource`，每台设备各自一份）**：连接分四种状态（样稿 `conn.state`）——
- **已断开**：还没开始连（没勾自动连接、没有令牌）或用户点了「断开连接」；按钮「连接」。没有令牌时「连接」提示「1号机 · 请输入访问令牌」（先「编辑设置」填令牌）。
- **正在连接… / 正在重连…**：一次连接尝试正在进行（REST 起步 `GET /device` + `/control` + `/snapshot`，或 REST 已通、WebSocket 在握手 / 等 `hello`）。
- **已连接**：WebSocket 收到 `hello`（实时数据在流）。只是 REST 通了、WebSocket 连不上**不算**已连接（例如 HMI 的 WebSocket 连接数已满，见下面的 503）。
- **断线、倒计时**：在等下一次尝试 —— 从未连上的设备「连接失败 · 5 s 后重试」，连上过的「连接中断 · 重连中 5 s」（设备面板第二行「连接中断 · 数据停在 10:11:40」，主页的断线横条见 §4.3）。
  两种等待：首次连接（REST 起步）失败 → 本机自己倒计时重试，间隔 2 → 4 → 8 → 10 s（之后一直 10 s，`LiveDeviceSource.RetryMin / RetryMax`）；
  连上之后 WebSocket 断了或握手被拒 → Client 按 0.5 → 10 s 退避重连，倒计时取它的 `NextRetryAt`，尝试的那一刻显示「正在重连…」。

「立即重连」（主页断线横条、设备管理的「连接」、申请控制权对话框）打断任一种等待、马上再试。失败原因记在设备上（提示里写原因），
同一轮里每种原因只提示一次：「4号机 · 连接失败：网络错误：Connection refused (192.168.1.41:8080)」；连上过的设备断线时网络层的原因不提示（徽标已经写着「连接中断」），
握手被拒的照样提示 —— 例如 HMI 每台最多 4 个 WebSocket 客户端（R19），第 5 个得到 503：「2号机 · 连接失败：WebSocket 连接数已达上限 · 请关闭该设备上的其他客户端（HTTP 503 TOO_MANY_CLIENTS）」
（这几句原因不是样稿的文字，取自 Client 的 `WsConnectException` / 旧界面的 `Describe`）。连上之后清掉原因与重试计数。
**HMI 重启**（`bootId` 变了：同一条连接上 WebSocket 的 `hello`，或者断线期间重启、重新连上时 `/device` 的 `bootId` 不同）：提示「1号机 · 设备 HMI 已重启 · 曲线缓冲已清空」，
重新读 `/device`（序列号 / 型号 / 已安装通道可能变了）、`/settings`（量程）、当前报警（整个替换）和最近的事件（事件按「序号纪元:序号」区分，重启后序号从头计不会撞号），
本机下发过的程序（程序台账 `programs/<设备 id>.json`，§6：含以前几次运行时下发、从台账文件读回来的）全部作废（「启动」回到启用 + 加热，「全部运行」要先重新下发，D6）。
多台设备各自监督、互不影响；Client 的事件经 UI 线程的同步上下文投递，每台设备把一批事件合并成一次刷新，`FleetVm` 再合并一次（R10）。

**停止类在断线时还能不能发**（`LiveDeviceSource.StopReachable`，M3 复核）：要有 REST 确实通的**正面证据** —— REST 起步刚完成、WebSocket 收到 `hello`、WebSocket 握手被 HTTP 拒绝
（503 / 401…：主机答话了）、探测 `GET /health` 有响应、命令送达；最近一次证据是网络层失败（WebSocket 连不上：拒绝连接 / 找不到主机 / 超时；探测失败；命令网络错误 / 超时）时就不算。
WebSocket 断了（连上过）或在退避时，每 3 s 探测一次 `GET /health`（单次 ≤ 3 s）：拔线 / 主机不回包时 WebSocket 的握手可能挂到系统的 TCP 超时（20–75 s），探测更早知道。
所以主机真的不通时只剩 none 类（急停 / 全部停止对话框里这台灰、写「连接中断 · 无法发送」，运行胶囊的全部停止 / 急停在全部设备都这样时带原因「没有已连接的设备」）；
REST 通了而 WebSocket 不通（例如 503）时，连从未连上的设备也能发停止类。

连接、控制权、急停、报警在外框里显示在：设备面板每台一行（左侧状态色条、远程 / 锁、「运行 6/8 · 报警 1 · 记录中」，断线「连接中断 · 数据停在 …」，急停红字）、
工具条「控制权：」小块、菜单栏「报警」徽标与报警摘要按钮、主页断线横条、状态栏（已连接 k/n 台、远程控制 k 台、记录 k/n 台、报警 / 提醒 / 未确认），见 §4。

### 3.2 令牌角色

| 角色 | 能做什么 |
|---|---|
| `viewer` | 只读：看状态、曲线、事件、文件 |
| `operator` | 申请控制权后可写；`estop=true` 的令牌可发急停 |
| `admin` | 同 operator，另可用管理端点 |

HMI 的规则（`Api/Endpoints.Write.cs`）：控制类写命令、申请 / 释放控制权、心跳、确认报警、会话要 operator 及以上；停止类要 operator **或**急停权限位；`/estop` 只看急停权限位。
接口还没有「我是什么角色」的端点（A3），所以本机在**第一个 `403 FORBIDDEN_ROLE` 之后学到**并按设备缓存（Core 的 `TokenRole`，换令牌时作废），之后守卫直接禁用并写明原因、不再发给设备：
读请求（`GET`）不会因为角色被拒，不学；只要 admin 的 PID 写入被拒（「该操作需要 admin 角色」）说明不了 operator 的权限，也不学；令牌的角色写在 HMI 的配置里、要重启 HMI 才生效，
所以 **HMI 重启（bootId 变化）后学到的作废**，下一个 403 再学（M3 复核）。
控制类 / 记录类被拒 → 只读令牌（控制类、申请控制权、确认报警、会话禁用：「1号机的令牌只能读取 · 需要 operator 令牌」）；停止类被拒 → 只读且没有急停权限位（停止类也禁用：
「1号机的令牌只能读取 · 停止需要 operator 令牌或急停权限」，急停「1号机的令牌没有急停权限」）；急停被拒 → 没有急停权限位（只禁用急停）。没学到的一律不禁用
（停止类、急停宁可发出去被拒，也不能被本机猜错拦下）。这三句样稿里没有，写法照 HMI 自己的 403 消息。
急停 / 全部停止对话框同样按学到的权限排除设备（§4.10）；工具条「申请控制」的原因也按它写。

### 3.3 控制权（租约）与触屏的协作

控制权的状态写在：工具条「控制权：」后面的**小块**（远程控制中 = 品牌蓝浅底；其余带锁；设备断线时换成连接状态；完整文字在悬停提示里）+ 一个行内按钮
（远程 / 宽限 =「释放」，申请中 =「取消申请」，本地只读 / 其他客户端 =「申请控制」主要按钮）、设备面板那一行的「远程」小块或锁、状态栏「远程控制 k 台」，
以及申请控制权对话框。下面的例子是 1号机、本机客户端名 `PC-测试工位1`；文中的「短徽标」就是工具条小块上的字。

1. **本地模式**（默认）：触屏自己控制，PC 只能看。PC 的受控写命令会收到 `409 MODE_LOCAL`。
2. PC 点 **申请控制**（工具条，先在设备下拉里选这台）先打开「申请控制权 · 1号机」对话框（样稿 `lease:k`）：说明请求会显示在 1号机触屏上、只影响这一台、
   停止类不需要控制权；「发送申请」→ 对话框留着，换成倒计时环（剩余秒数）+ 三步（已发送请求 / 等待现场确认 / 远程控制中），底栏「取消申请」「后台等待」；确认之后对话框里是「1号机 远程控制中」+「释放控制权」「完成」。
   触屏弹出「允许 / 拒绝」（`autoGrantRemote=true` 时直接授权）。
   等待期间（`/control` 的 `requestTimeoutSec`，默认 60 s）短徽标 `申请中 45 s`（倒计时；完整文字 `申请中 · 45 s`），悬停「等待设备触屏允许 · …」，
   行内按钮「取消申请」。倒计时按 HMI 给的到期时刻（`POST /control/request` 的 `expiresAt`），用 WebSocket `hello` 的服务端时间修正两边的时钟偏差。
   结果用 toast 说（样稿的写法）：「1号机触屏已确认 · 远程控制中」或「1号机控制权申请超时 · 触屏未确认」；HMI 设了自动授权（`autoGrant`）时没有人在触屏上确认，写「1号机已获得控制权 · 远程控制中」（M3 复核）。
   触屏点了「拒绝」时 HMI 对这个令牌冷却 30 s：toast 与「申请控制权」的原因都写「1号机触屏已拒绝申请 · 28 s 后可再申请」（倒计时；样稿没有拒绝，这句沿用「… s 后重试」的写法），冷却过了才能再申请。
   申请**超时**时 HMI 同样冷却 30 s（从它的到期时刻起算），HMI 回 429 时原因也不确定：「申请控制权」写中性的「1号机申请刚被拒绝或超时 · 20 s 后可再申请」（M3 复核：以前超时后能点、第一下得到 429）。
   申请被 409 NOT_CONTROL_HOLDER 拒绝时提示 HMI 自己的话「1号机 · 当前控制权属于「X」」（不再是写命令那句「请先申请远程控制」）。申请控制权对话框的倒计时环满格 = HMI 的 `requestTimeoutSec`（默认 60）。
3. 允许后 PC 持有**租约**：工具条小块 `远程控制中` + 行内「释放」，设备面板「远程」，状态栏「远程控制 1 台」；软件自动按 `heartbeatTimeoutSec/2` 发心跳（优先 WS `hb`，WS 不通时 REST）。此时触屏的手动操作被锁定，但触屏的**停止类**按钮与「切回本地」随时可用。
   租约在别的客户端手里时（第 5 种状态）短徽标 `其他客户端 PC-xx`（带锁），完整文字 `远程控制中（其他客户端 PC-xx）`，控制类按钮和「申请控制权」的原因也这样写；
   别的客户端的申请正在等触屏处理时（`GET /control` 的 pending 不是本机），「申请控制权」带原因「1号机已有待处理的远程申请（PC-xx）」（HMI 会以 409 拒绝；写法照 HMI 的消息）。
   **本机旧租约**（M3 复核）：HMI 说控制权在本机客户端名手里、本机这条连接却没有持有（上次运行崩溃 / 强退留下的，心跳还没超时）—— 短徽标 `本机旧租约`（同第 5 种的样子），
   完整文字 `远程控制中（本机旧租约）`；HMI 还在 remote 时「申请控制权」带原因「1号机远程控制中（本机旧租约） · 心跳超时后可重新申请」，心跳超时进入 remoteLost 之后可以申请
   （HMI 让同一令牌 + 客户端名的新申请作废旧租约）。
4. 心跳中断（网线 / 休眠）→ 触屏进入 `remoteLost`。本机从 WS `control` 消息、心跳响应或 `GET /control` 得知以后：短徽标 `宽限 18 s`（提示里是完整文字 `控制权心跳中断 · 宽限 18 s`）+ 行内「释放」，
   toast「1号机 · 控制权连接丢失 · 宽限期内自动恢复」。设备同时断线时工具条小块写连接状态，宽限的倒计时在申请控制权对话框里。宽限期内恢复心跳即继续（toast「控制权已恢复」），超过宽限期租约作废（触屏按 `onRemoteLost` 配置：keep / stopHeat / estop）。
   宽限的倒计时 = Client 记下的丢失时刻 + `leaseGraceSec`（重连后才从 `GET /control` 得知已丢失时，按 HMI 的硬到期反推）。宽限期满租约作废：toast「1号机宽限期结束 · 控制权已交回触屏」（样稿），
   回到本地只读；**M3 起软件不再自动重新申请**（Client 的 `AutoReacquireLease = false`：样稿里交回触屏之后要不要再申请由用户决定；旧界面会自动重申请并 toast「控制权宽限期满 · 正在重新申请」，
   要恢复旧做法改 `LiveDeviceSource.Connection.cs` 的 `NewOptions` 一行）。连续两次心跳没送到、HMI 还没报 `remoteLost` 时，申请控制权对话框的「心跳正常」换成「心跳异常」
   （「PC-测试工位1 · 心跳异常」；样稿没有这一档）。网线断开时 WebSocket 会在 10 s 内转为重连（第 5 条），设备显示 `连接中断 · 重连中 N s`。
5. WebSocket 10 s 收不到 pong（拔线 / HMI 冻结）→ 软件主动撕掉连接并按 0.5 → 10 s 退避重连：等待时 `连接中断 · 重连中 N s`（工具条小块与设备面板写 `连接中断`，主页出现断线横条），尝试时 `正在重连…`（§3.1「重连」）；
   重连 / HMI 重启后若 `GET /control` 显示设备已回到本地而本机之前持有租约，toast「1号机 · 重连后设备已回到本地模式 · 控制权失效」（别人持有时「1号机 · 重连后控制权已失效」），**不**自动重新申请。
   HMI 重启（bootId 变化）时曲线缓冲清空、重读 `/device` 与 `/settings` 并 toast 提示（§3.1）。
6. 触屏「切回本地」或急停 → 租约失效（`takenBack` / `invalidated`），软件**不**自动重申请：toast「1号机 · 触屏已收回控制权」或「1号机 · 急停：控制权已失效」，短徽标回到 `本地只读`（悬停「本机只能查看1号机」），
   行内主要按钮「申请控制」。心跳 / 写命令被 409 拒绝也会 toast 说明原因（「心跳被拒 · 控制权失效（…）」「写命令被拒 · 控制权失效（…）」）。
7. PC 点 **释放控制权**、断开连接或关闭窗口 → 先中止运行中的性能测试（停止类收尾）、释放租约，触屏回到本地模式。停止类命令走独立通道，不会排在正在重试的受控写后面。

不需要控制权的操作（停止类，只要连接正常就能发）：**急停**（运行胶囊右端唯一的红色「急停」，打开多选的急停对话框：已连接的默认全选）、全部停止、停止通道、停止加热、
停用通道、中止程序、停止搅拌（本机只读时共用搅拌开关是禁用的，见 §4.3）、取消自整定、中止泄漏测试、报警确认、会话 / 标记。停止先确认的范围见 §4.10。控制类操作在没有控制权、急停中或断线时不可用，原因写在按钮上（悬停提示、点击 toast 原因），
执行前还会再查一次（界面状态可能已经过期）。「取消申请」时界面立即回到本地只读（toast「1号机 · 已取消控制权申请 · 若触屏已批准将自动释放」—— 后半句是 PORT-PLAN R7 要求写明的），
后台照样查这条申请直到有结果（Client 的 `CancelRequestAsync`：HMI 没有取消申请的端点）；若触屏之后才批准，软件立即 `POST /control/release`（不进入远程控制、不发心跳），
toast「1号机 · 触屏在取消后批准了申请 · 已自动释放」（释放一直失败时「… · 自动释放失败，请在触屏收回控制权」）。断开 / 移除时若还有已取消、在等结果的申请，WebSocket 先停，
REST 留给这个后台守卫（最多 3 min）再释放连接。**退出时**本机的申请（或已取消、还在等结果的申请）还在某台的触屏上：先在窗口里问「退出控制软件？」（M3 复核，R7）——
「等结果再退出」先取消申请，等到每条都有结局（批准的立即释放、拒绝、超时）或过了 HMI 的到期时刻再 5 s（最多 80 s，说明里倒计时）再退出；「仍然退出」照常退出（3 s 预算里等一下）；
关掉对话框 = 不退出。关窗、系统的退出（⌘Q / Alt+F4）都先问。

**只是 WebSocket 断了、在自己重连时**（第 5 条：心跳超时、`1008` 慢消费者都会这样），界面写「连接中断 · 重连中 N s」/「正在重连…」，控制类和申请控制权照样不可用；
**REST 确实还通时**（§3.1 末「停止类在断线时还能不能发」：要有证据），真正的停止类照样可用：急停、全部停止、停止、停用、停止加热、中止程序、停止搅拌 —— 尽力发送，送不到时 toast 失败原因
（送不到 = 网络错误，这台随即只剩 none 类）；运行胶囊和急停 / 全部停止对话框也算这台（守卫的 `GuardFacts.StopReachable`）。会话 / 打标记 / 确认报警（样稿也算 safe，但不是停止）等 WebSocket 恢复再做。
主机真的不通、用户点了「断开连接」、首次连接失败之后（没有连接对象）才只剩重连 / 移除这类操作（M3 复核：以前只要连上过就一直算能发，主机断电了也一样）。

**全部停止与搅拌（一个开关，用户 2026-11-09 已确认：连搅拌一起停）**：「全部停止」发 `POST /stop-all {stopStir}`，`stopStir` 只看 Core 的 `ControlOptions.StopAllStopsStirring`
（`Control/ParallelReactor.Control.Core/ControlOptions.cs`，全软件只有这一行）。默认 `true`（与旧界面相同）：中止程序、停止加热、关闭进气、停止搅拌，
实时设备发 `stopStir:true`，演示数据里共用搅拌也停。全部停止对话框「对气路做什么」表的「搅拌」一行跟着这个开关写「停止」/「不变」（`Shell/Dialogs/StopDialogs.cs` 的 `StopTexts`），
发送后的提示和单台的结果末尾加「 · 搅拌一并停止」（文字在 Core 的 `StopAllText`）。
把那一行改成 `false` 就是样稿第一版的做法（搅拌保持当前状态；HMI 自己的 `/stop-all` 默认也不停搅拌）。测试两种取值都覆盖，改开关不用改测试。
急停另外立即切断并锁定，复位只能在触屏；单独停搅拌用主页共用资源面板（或气路图 / 卡片 / 棒图灰带）上的搅拌开关。
全部釜由一台电机经齿轮带动，所以「停止通道」不停搅拌（表里写「不变 · 电机全部釜共用，其它路还在用」）。

### 3.4 本机配置与令牌的保存（devices.json，D7）

- **devices.json**（M3，替代 v1 的 `control.json`；位置见 §6）：`clientName`、`timelineMinutes`（pc-v3 时间轴留下的字段，照旧读写，新界面不用）、`tokenStore`、
  本机设置 `"pc"` 一节（`dataDir`、`pressureUnit`、`autoConnect`、`alarmSound`、`preventSleep`、`backfill`，见 §4.9）和设备列表（`id`、`alias`、`host`、`port`、`rememberToken`、`autoConnect`、
  `lastSerial`、`lastModel`），数组顺序 = 设备顺序。写入是原子的（同目录临时文件写完再改名替换）；读的时候容错（注释、多余的逗号、字段大小写、类型不对的字段用默认值、没有地址的项跳过、
  重复的 Id 重新生成、不合规 / 重复的别名换成没用过的「k号机」、端口越界用 8080；整个文件坏了时从空列表开始，第一次保存前留一份 `devices.json.bad`）。
- **迁移**：只有 v1 的 `control.json` 时，启动时把它变成「1号机」（地址、端口、客户端名、记住的令牌、自动连接）写进 `devices.json`，然后把 `control.json` 里的明文令牌抹掉（其余字段留着）。
- **令牌只在勾了「记住令牌」时落盘**，没勾的只在内存里（下次启动要重新输入）；「启动时自动连接」要求令牌已经存了。
  - **Windows**：DPAPI 加密（当前用户、本机；`CryptProtectData`），密文写在 `devices.json` 这台设备的 `token` 字段（前缀 `dpapi:`）。只有同一个 Windows 用户在同一台电脑上能解开；换电脑 / 换用户时当作没记住。
  - **macOS / Linux**：**不加密**。令牌以明文写在 `devices.json` 旁边的 `tokens.json`，文件权限 0600（只有本用户可读写，先以 0600 新建临时文件再改名替换）。
    这台电脑的管理员、以及能以本用户身份运行程序的人都能读到 —— 共用账户的电脑上不要勾「记住令牌」。
- 截图 / 演示（设置了 `PR_CONTROL_SHOT` 或 `PR_CONTROL_DEMO`）时**不写任何配置文件**（迁移照样在内存里做；`drafts.json`、程序库 `library.json`、实验方案 `experiments.json` 同样不读不写）。
- 设置 › 常规的「导出配置」写 `<数据目录>/export/pc-config-<时刻>.json`（本机客户端名、本机设置、设备列表，**不含令牌**）；「导入配置」只读回本机设置和客户端名，不导入设备列表。
- 运行中保存 `devices.json` 失败（只读目录、磁盘满…）时 toast「配置保存失败：…」（M3 复核：以前只记在加载说明里，改动看起来成功了、下次启动却没了）。
- `clientName` 没写（或清洗后为空）时用这台电脑的默认名（「PC-」+ 计算机名，§3.1）。

### 4.2 报警弹窗（模态）

- 头：「RV1」+ 状态 + 上一路 / 下一路；「1号机 · HT-PR8 · 程序「…」/ 第 3/4 步 恒温反应 · 剩 27 min」；本地只读 / 急停 / 断线说明条。

### 4.3.1 曲线升温（检查器 + 曲线窗口，2026-11-21）

在主页选中一路，检查器「温度控制」的**升温方式**可以切「定值 / 曲线」。程序在跑、正在加热或曲线在走的通道不能切换，按钮上写原因。

- **曲线、没在走**：摘要（共几段、总时长、最高温度、预计几点走完、各段一行）+「编辑曲线」「启动曲线」。
- **曲线窗口**（「编辑曲线」）：
  - 左边改段：每段填目标温度和用时，右边自动算速率；目标和上一段相同就是保温；最多 16 段，至少 1 段。
  - 升得比 5 °C/min 快、或者有降温段（只能自然冷却）时给琥珀色提示，不拦。
  - 右边预览图：从当前实测温度画到走完。
  - 「同时用到」：勾选几路用同一条曲线；程序在跑、报警、停用、正在加热的通道不能选并写原因。
  - 底栏：取消 / 保存 /「保存并启动（n 路）」。启动不确认。
- **曲线在走**：检查器显示第几段、本段剩多久、分段进度条、给定和实测；「查看曲线」打开只读的窗口（图上有「现在」和实测温度）。**运行中不能改段**（触屏的规则）。

### 4.4 程序页（截图 `程序-1920.png`、`程序-bar-1920.png`）

一次看一台设备。左边程序库（按型号 / 全部型号、搜索；每行标签「运行 N 路」「N 处待改」「草稿」、步数 · 约时长 · 型号、修改时刻 · 人），右边分段 **单路程序 / 条件矩阵**（不给参数时默认条件矩阵）。工具条按模式换：
单路 = 程序（新建程序、保存、复制为新程序、存为模板）· 文件（导入、导出：HMI 程序 JSON）· 运行（预运行检查、下发并运行、停止程序）；矩阵 = 方案（按模板重建、保存方案）· 文件（导入 CSV、导出 CSV）· 运行（预运行检查、下发并运行）。

- **单路程序**：步骤是**有类型的**，按程序步骤 v0.8（`research/fusion-port/notes/STEPS-SPEC.md`）共 9 种：**气密检查 · 置换 · 搅拌 · 升温 · 充压 · 保持 · 反应 · 放空 · 结束**（`Control.Core/Programs/Editor/StepSchema.cs`、`StepDefaults.cs`）。没有降温步骤：要等凉了再放空，在放空前加「保持 · 温度 ≤ x」。
  参数面板的字段、单位、范围、默认值来自设备的 `GET /program-schema`（取不到时本机按同一张表生成），只显示用得到的字段（visibleWhen：例如保持的目标温度只在「温度 ≥ / ≤」时有、反应的「停止速率 / 持续」只在吸气停止开着时有）。
  - 气密检查：惰性气体充到试验压力（默认 3.0 MPa）→ 稳定 → 保压，按压降速率判定；允许压降默认取设置的泄漏率阈值，按「压力单位/h」显示。
  - 置换：气体（惰性 / A / B）充到 → 放到，重复 N 次，可先吹总管；次数 0 = 只吹总管（旧的「吹扫」）。
  - 搅拌：设定釜转速（0 – 转速上限，默认 400），**立即进入下一步**，转速一直保持；整台一台电机。
  - 升温：定值 / 曲线（最多 16 段）；升温速率、到位范围、到位后平衡、最长等待、超时处理。
  - 充压：气体（含惰性）、目标压力、允许偏差、之后稳压与补气阈值、最长充气。
  - 保持：时间到 / 温度 ≥ / 温度 ≤ / 压力 ≥ / 压力 ≤；按条件时有最长等待与超时处理。
  - 反应：最长时间、最短时间、吸气量达到、吸气停止（速率 + 持续）；先到者结束。设备给的结束原因在已结束程序的状态行里写出（「反应结束：吸气停止（…）」）。
  - 放空：放到、最长时间、之后惰性置换几次、置换充到。
  - **结束**：没有参数，**固定在最后**（不能删、不能挪，别的步骤也不能挪到它后面）；「添加步骤」只有前 8 种，新步骤插在结束之前。
  步骤列表每行：序号、类型、名字、两项摘要、待改、估计时长（STEPS-SPEC §5：按条件结束的保持写「约」、反应写「≤」、不占时间的写「立即」）。在跑的程序锁住（「复制为新程序」再改）。预计温度 / 压力上下两张图（不用双轴）。
  待改项（琥珀，拦下发）与提示（灰底，不拦）列在步骤下面。**新建程序是空的**：只有固定在最后的「结束」，用「添加步骤」加入（插在选中的一步后面、「结束」前面）；加氢筛选等模板在程序库里另有。**编辑步骤**：右键一步 → 上移 / 下移 / 删除这一步（不能做时灰掉，悬停写原因）；左键按住一步上下拖动，松开处出现蓝色插入线、松开即移到那里；选中一步按 Delete 键删除；「结束」不能拖、不能删，别的步骤也放不到它后面；运行中的程序锁住，先「复制为新程序」再改；
  程序库第一次打开（没有旧草稿时）是空的，内置的流程在模板库里（§4.4.1）。
  下发面板：通道小块（选全部空闲、清空）、**溶液体积 0.1 mL 必填**（↑ / ↓ ±0.1）、预运行检查、下发并运行。
- **旧格式的程序**（吹扫、等待、带「搅拌时长」的搅拌、带「方式 / 先降温至」的结束、按 endBy 的反应）：程序库、草稿、导入的 HMI 程序 JSON、条件矩阵方案读进来就按 STEPS-SPEC §3 转换（Contracts 的 `StepMigration`，同 HMI），
  超出新范围的旧值收紧到范围内（同 HMI 的 PUT）。编辑器顶上一条琥珀提示「**已从旧格式转换，请检查**」并逐条列出收紧的值；没改也能「保存」，保存后按新格式写回、提示条消失。记录页「用这组参数再做一次」载入的是程序库里（已转换）的程序，提示先检查。
- **参数范围**：温度 ≤ min(TMaxSp, 超温 − 1)（升温目标 ≥ 35）；**压力**（气密试验压力、置换充到、充压目标、置换充到等）≤ min(PMaxSp, 超压报警 × 0.9 − 0.1 psi)，再不超过 34 bar。0.9 × 超压这条通常更低：HMI 默认超压报警 510 psi 时上限 458.9 psi ≈ **31.6 bar**（≈ 3.16 MPa）。
  转速 = 釜转速 ≤ 转速上限（默认 450）。压力在界面上按显示单位输入（MPa 两位小数并写「≈ … psi」、bar 一位、psi 整数；压降速率 MPa/h 四位、bar/h 三位、psi/h 一位），存 MPa，下发时换成 psi（一位小数，压降两位）。
  字段之间：置换的「放到」要比「充到」低至少 1 psi；反应的最短时间不超过最长时间。
- **条件矩阵**：列 = 通道（参加勾、识别色、状态 + 几点结束 / 空闲 / 已停用），16 路分 RV1–8 / RV9–16；样品行；溶液体积行（必填）；每步的每路参数（升温目标 / 充压目标 / 反应最长时间，「统一」/「等差」）和共用参数（斜纹底 + 为什么共用）；
  **搅拌转速不能按路变化**（一台电机经齿轮带全部釜）：转速是共用的一行，写明「一台电机带全部釜 · 转速不能按路变化」。压力列按设置的压力单位。
  粗体 = 改过模板值，琥珀 = 超范围；表尾预计用时（含升压排队）；右侧检查（按值分组）、各路预计温度、最短 / 最长、升压顺序说明；下发：会话名、记录开关、预运行检查、下发并运行（每路一个程序，之后开始会话）。
- **预运行检查**（两种模式同一个对话框）：本机检查（溶液体积、范围、气路占用等）+ 真机另取 `GET /preflight`（温控、压力 · 超压监视、阀门、搅拌器），取到前写「正在读取」。
  另有程序步骤 v0.8 的下发前检查（STEPS-SPEC §4，`Core/Programs/Editor/ProgramChecks.cs`，结论同 HMI 的运行前检查）：
  **不通过** = 超出范围；结束不在最后或不止一个；先充压后升温、估算的压力超过上限；同一批启动的几路第一个搅拌的转速不一致（写明哪几路，只有 PC 检查）。
  **提醒** = 反应前面没有充压（吸气量不计量）；先充压后升温（写估算：目标绝压 × (T 目标 + 273.15) / (T 充压时 + 273.15) − 大气压）；没有放空（结束时釜里可能带压）；别的在跑的程序也在用搅拌、转速不同。没问题的项不列。
- **下发并运行**的顺序（`Pages/Programs/ProgramSender.cs`）：每路 守卫 → 溶液体积不同时先写 `PUT /channels/{id}/volume`（程序跑起来以后 HMI 不让改）→ 下发程序（`PUT /channels/{id}/program` + 程序台账）→ 运行。某路失败不影响其它路，最后一条汇总提示。
- **停止程序**（工具条）= 打开第一个勾选通道的停止确认框；多路一起停用全部停止。
- 存储：程序库 `library.json`（配置目录）、条件矩阵和每次下发的记录 `experiments.json`（数据目录），§6。第一次打开时把旧程序页的 `drafts.json` 草稿迁移成草稿程序（旧格式同时转换）。样品名 / 实验方案只在 PC 上（设备没有这些字段）。

### 4.4.1 模板库（2026-11-23，设计稿 `research/fusion-port/tpl-design` 方向 A）

模板和程序分开：**模板是新建程序时的起点，不是程序** —— 不能下发、不能直接改；用它新建出来的是一份独立的程序，之后和模板无关。

- **两类模板。** 内置模板随软件提供（加氢筛选 · 只做气密 · 惰性气氛加热 · 吸气量验证），不能改名、不能删，软件升级时跟着更新；
  「我的模板」由自己的程序存进去，存在本机，可以改名、删除。模板只保存步骤和参数，不含样品名、通道、溶液体积；按型号区分（只列当前设备型号的）。
- **新建程序。** 工具条「新建程序」打开窗口：左边选「空白程序」或一个模板，右边预览每一步和关键参数，底栏填程序名，点「创建程序」。
  程序名默认跟着所选的模板（程序库里已有同名的加序号）；手改过之后不再跟着变。创建出来的程序是草稿、未保存，自动切到单路程序。
  选中「我的模板」时右上有「改名」「删除」（都是就地操作，删除要再点一次确认）。
- **存为模板。** 选中一个程序，工具条「存为模板」（或在程序库里右键）：填模板名称（不能空、不能和已有模板重名）和说明（可以不填）。以后再改这个程序，模板不跟着变。
- **程序库为空**（新装的软件）：中间显示「还没有程序」和两个入口「从模板新建」「空白程序」。
- **删除程序。** 程序库里右键「删除程序…」，先确认；正在运行的程序不能删。已经下发到设备上的不受影响。
- **已经在用的电脑。** `library.json` 原样读：之前自动放进去的三个内置程序留着，当作自己的程序，不需要的可以右键删除。
- 存储：我的模板 `templates.json`（配置目录，§6）；内置模板在代码里（`ProgramTemplates.BuiltIn`）。截图 / 演示时不读也不写。
- 条件矩阵里说的「模板」（「按模板重建」）指的是所选的那个程序，不是模板库。

**无人值守的真实行为**：

- **防睡眠**：设置开 + 有设备在运行 → 申请，否则释放；失败 60 s 后再试（Core `Unattended/SleepGuard`）。Windows `SetThreadExecutionState`，macOS 起 `caffeinate -i -w <本进程>`（本程序崩了它自己退），其它系统不支持。演示 / 无头 / 截图用模拟实现（不调系统，状态栏照样写）。
- **补拉**：断线时记下曲线最后一个读数的时刻；重连且设置开着 → 后台 `GET /telemetry?from&to`（最多 240 min）→ 合并进本机曲线缓存（已有读数优先）。只补温度 / 压力 / 吸气量（CSV 里有的），不补加热输出、设定值、转速。
- **报警声音**：未确认、未解除的报警级报警（不含急停那条）新出现时马上响，之后每 30 s 一次，全部确认后停。Windows winmm `PlaySound("SystemExclamation")`（柔和的一声），macOS `afplay` 系统声音（Glass，没有时 Ping / Tink）。泄漏测试失败只记「提醒」（人在跟前、屏幕上有原因），不响；阀门 / 压力模块通讯故障照样按报警。演示 / 无头 / 截图不出声。

  - **几台同时**：只展开一张：点过的 > 等人操作的 > 设备号小的；其余是胶囊，堆在它上面。
- **状态栏**：收起了的活动各一项「1号机 · 泄漏测试 · 平衡 · 16 %」（等人操作琥珀），点它展开；窄屏缩成「1号机 泄漏测试 16 %」。
- **全局标记**：设备栏活动行（§4.1）、共用资源的气路占用 / 手动阀控 / 搅拌故障、运行表 / 卡片 / 棒图的覆盖（§4.3）、急停分项的报警弹窗（§4.2）。最近事件照常从设备事件来。
- 演示：地址参数 `act=leak-run|leak-done|leak-fail|leak-abort|calib-wait|stack`、`actfold=1`、`axopen=k`、`axabort=1`、`stirfault=1`、`manual=1`、`estoppart=1`、`tune=1`（§9）；
  演示数据里性能测试页的「开始泄漏测试」会真的开始一次演示测试（每秒倒计时，做完按全部通过结束），「中止」先确认再中止。

## 5. 性能测试流程

页面见 §4.7（截图 `性能测试-1920.png`）。测试计划只适用 HT-PR8（`PerfPageVm.PlanApplies`）；别的型号整块写「没有对应的测试计划」，泄漏测试照样能用。
测试对象 = 工具条设备下拉选的那台实时设备，开始之后锁定那台。

### 5.1 测试项清单（左侧「测试项 · 首台摸底」）

方案来自 `Control/ParallelReactor.PerfTest/Plans/rv1-4-baseline.json`（26 项：§0 R0 前置检查表、阶段 1 F1–F6、阶段 2 S1–S3、阶段 3 P1–P4、阶段 4 T0 / T1 / T2 / T4 / T5、阶段 5 C2-a；T3 / C1 / C2-b / LT1 / M1 / LT2 为二期，灰显不可选），末尾附加 `smoke.json` 的两项「快速自检」（T0Q 升温 60 ℃ 记录 30 s、S1Q 搅拌 300 rpm 10 s）用于联调与截图。`PR_CONTROL_PLAN=<json 路径>` 可换用外部方案文件。
搅拌的转速点按**釜里的转速**（上限 450 rpm，一台电机经齿轮带动全部釜）改过（F8，只改了方案 JSON，引擎没动）：S1 档位 100 / 200 / 300 / 350 / 400 / 450（先升后降 12 档）；
S2 改名「上限内失步检查」，300 → 450 每次 +25、核对上限 ≥ 450；S3 0 → 450 → 0；T4 0 / 300 / 450；C2-a / C2-b 400 rpm；F6 的 n_max 录入上限 450；转速表读数上限 600。

按阶段分组，每行：完成 / 跳过 / 当前图标 · 勾选 · 编号 · 名字 · 时长；上面「摸底 / 泄漏」分段、「全选」「清空」、测试通道小块和「已选 N 项 · 约 X min」。

**测试通道**：RV1–RV4 小块可选（默认全选），RV5–RV8 按方案 §0.3 禁用；设备 `installedChannels` 不含的通道同样禁用。

### 5.2 运行

前提：已连接且**持有控制权**（否则 Toast 提示）。**§0.4 门禁**：勾选了任何带热 / 带压项（含加热、自整定、程序运行、泄漏测试命令）而本次会话里 R0 前置检查表还没通过时，软件会自动把 R0 加到最前面并提示；引擎侧同样拒绝——R0 未入选 / 未通过（含被跳过）的运行里这些项一律「跳过」，前置项被跳过的后续项也跳过。工具条 **开始测试** 后：

- 引擎（`PerfRunner`）在后台线程顺序执行所选项；运行开始时 `POST /sessions`（testId = 运行编号 `PT-yyyyMMdd-HHmmss`），每项 / 每轮 / 每条命令前 `POST /sessions/current/markers`，结束时 `DELETE /sessions/current` 并下载触屏侧会话 CSV——触屏自己的记录文件因此也带上标记。已有活动会话时弹出确认（结束它 / 本次不建会话）。
- 右上「进度 · 会话 …」+ 状态标签：总进度条、已用 / 预计还要、当前一步的卡片（人工录入 / 手动确认检查表 + 两人签字 / 安全暂停，卡上「确认并继续」「跳过」）、实时（搅拌 + 各路压力 / 温度）、说明；右下「结果」。
  旧样式页面的实时曲线去掉了（样稿没有）。
- 工具条：**开始测试 ↔ 暂停 / 继续**（运行中随时可按，只在安全暂停等待应答时禁用；暂停在步与步之间或记录间隙生效，暂停时长不计入步骤）、**跳过本步**、**中止**（中止程序 → 取消自整定 → 停止加热 → 中止泄漏测试 → 停止搅拌，结束会话，照常出报告；**不**急停）｜**生成报告**、**打开文件夹**。急停始终在运行胶囊上，不经引擎；方案 F4 由引擎下发的软件急停是预期内的，不会触发安全暂停，F4-10 复位后 F4-11 自动重新申请控制权。

### 5.3 提示（等待操作员）

| 步骤种类 | 界面 | 操作 |
|---|---|---|
| 手动确认（Instruction） | 「手动确认」卡：标题 + 现场操作说明 + 备注框 | 确认并继续；跳过 = 未确认（按方案 `onFail` 处理） |
| 检查表（Checklist，如 R0 的 13 项） | 同上 + 逐项复选框（+ 两人签字框） | 全部勾选（并签字）后 确认并继续；未勾全会提示 |
| 人工录入（ManualEntry） | 「人工录入」卡：仪器名、提示文字、每个读数一格（多次 / 多通道，下标 #1 #2 / RV1 #1） | 填完后 确认并继续 或在框内回车；越界 / 非数字即时提示，引擎侧校验失败会把原因写回卡上并要求重填 |
| 安全暂停 | 安全暂停卡：报警 / 急停 / 控制权丢失 / 压力模块离线 / 其他模块离线 > 30 s / PV > SP+15 ℃ + 方案建议 | 确认后继续 = 继续；中止 = 停止并出报告；绝不自动继续。等待录入 / 确认期间到达的安全事件立即弹卡，不必先提交录入。通讯模块离线按方案 §0.1-11 先自动执行停止类收尾（停加热 / 搅拌 / 程序 / 自整定 / 泄漏测试）再询问 |

### 5.4 报告

运行结束（完成或中止）后引擎立刻生成 `report.html`。工具条 **生成报告** 重新生成报告（HTML + 汇总 CSV）并用系统默认浏览器打开 `report.html`；页面右下「结果」是汇总表。报告：报告编号 · 通道 · 项数 · 模拟标记，总用时；表格每项一行（结论 / 判定）+ 每个指标一行（设定 / 标准、实测、误差）。判定列默认「—（摸底）」，仅方案给出硬性判据的项才显示 合格 / 不合格。报告头的环境记录（§0.5）来自 R0-5 的录入；基线表的「规格草案」只在独立轮次 n ≥ 6 时给出（ISO 16269-6 容差区间 k 因子，同日 4 通道不算独立样本），否则只报 x̄ / s / 最差；每项标明「本次编码重复 N 轮」，方案要求的 n 不足时由多次运行离线合并。曲线与 CSV 里的「转速」是设定值（驱动器无转速反馈）。**打开文件夹** 打开运行目录（`<数据目录>/perf/<运行编号>/`，§6）。模拟运行（HMI `PR_SIM`）的报告顶部有红字「模拟运行，数据无效」。

### 5.5 泄漏测试

左上分段切到「泄漏」（地址参数 `ptm=leak`）：参数取设备设置 `leakTest.*`（只读）；阶段按快照 `leakTest.stage` 标当前（v0.8.1 起；以前比对中文的 `phase`，永远落在「充压」），
进度一律按 0–100（以前 ≤ 1 时乘 100）；最近一次全部通过时绿色提示「全部通过 · 泄漏率都低于阈值」；通道默认此刻空闲的（运行 / 加热 / 报警 / 停用的带原因）。
工具条「开始泄漏测试」= `POST /leak-tests`（要控制权）、「中止」= 先确认，再 `DELETE /leak-tests/current`（停止类，不要控制权；HMI 全关阀，**不泄压**）、「导出结果」CSV 到 `<数据目录>/export/`。
结果 = `GET /leak-tests` 最新一次 → `GET /leak-tests/{runId}`（HMI 的汇总：每路状态、判定压降 psi/h、起止压力 psig）。判据用设备设置的泄漏率阈值（HMI 出厂 2 psi/h），记录页保压类的判据读同一个值。
压降和泄漏率一律 psi/h（+ kPa/h），不跟压力显示单位走（§4.9）。

## 8. 已知限制

**接口与设备**

1. 接口不开放（v0.7 起阀门已开放，见 §4.3）：设置修改（TMaxSp、RpmMax、报警阈值、档位分界、onRemoteLost …）、急停复位、容积标定。PC 上这些都只读，写「触屏操作」。性能测试方案里这类步骤在 PC 端是「手动确认」+ `GET /settings` 复核。
2. 接口没有「程序下一步」命令，也没有取消控制权申请的端点：本机「取消申请」后若触屏仍批准，软件立即释放。
3. 设备不记程序名、操作员：记录页里已结束的会话没有程序名（「用这组参数再做一次」带原因）。建议 HMI 在会话 manifest 里记程序名。
4. 不是本机下发的程序：运行表靠 `GET /channels/{id}/program/run` 取步骤；取不到时步骤进度和预计结束写「—」。
5. 自整定：接口没有整定开始时刻，页面打开前就在整定的那一路「已用」从第一次看到时算起；新旧 PID 对比只留在内存里（离开这一节就没了，设备事件里有记录）；整定曲线来自本机曲线缓存（断线期间没有点，补拉不补加热输出）。
6. 主机名、磁盘空间接口没有（设备信息写 SN，数据存储不画磁盘）。
7. HMI 的 StepDef 声明升压目标 0–493.1 psi（34 bar）；实际上限再受 PMaxSp 与 0.9 × 超压报警约束（§4.4），超出的程序在程序库里是「待改」。

**本机**

8. 曲线缓存（主页、曲线页、报警前后小趋势、进行中的会话）最多 240 min、10 s 一格；更早的数据在记录页按会话下载。补拉只补回 240 min 内的温度 / 压力 / 吸气量。
9. 停止类操作都先确认（§4.10）。确认框里写的「做什么」按 HMI 现在的行为写；HMI 行为变了要同步改 `StopTexts`。
10. 共用搅拌开关在本机只读（没有控制权）时禁用，虽然停搅拌在 HMI 那边算停止类、不需要控制权（F8 的决定）。全部停止照样会停搅拌。
11. 压力单位：设备发来的报警 / 事件句子、导出的 CSV、保压 / 泄漏率（psi/h）不跟显示单位（§4.9）。温度单位只有 °C。
12. 「自定义…」时间段（曲线页、报警页、记录页）、曲线页「复制图片」、记录页 PDF 报告、深蓝条「工具」（通讯日志、诊断包）还没做，点了只提示。
13. 演示数据里的防睡眠是模拟的（状态栏照样写「已阻止睡眠」）；Linux 不支持防睡眠（不写这一项）。
14. 令牌「记住」时（默认不记）：Windows 用 DPAPI 加密；macOS / Linux **明文**写在 `tokens.json`（权限 0600）—— 见 §3.4。
15. 「全部停止」连搅拌一起停（`stopStir:true`，用户 2026-11-09 确认）。开关是 Core 的 `ControlOptions.StopAllStopsStirring`，改一行即可（§3.3）。
16. 控制权不自动重新申请（§3.3 第 4、5 条）：性能测试跑着时若宽限期满丢了控制权，后面的受控命令会被拒（停止类照常），要重新申请后再跑。
    首次连接失败的重试不封顶次数（10 s 一次，直到连上、断开或移除）；令牌错了（401）也照样重试。
17. `HW_UNCONFIRMED`（命令已下发但硬件未在时限内确认）只提示、不自动重发，请核对读数 / 快照后再操作。
18. 型号表是示例、参数为假设；演示里 2号机（HT-PR4）、3号机（HT-PR16）的气路和样稿不同。
19. Windows 上的防睡眠、报警声音、微软雅黑字体、125 % / 150 % 缩放都还没在实机上看过（§2.1）。

**性能测试**

20. 报告「判定」列：方案明确摸底不做合格判定，默认全部「—（摸底）」；哪些判据升级为硬性需产品确认。
21. ETA 按方案 `estimatedMinutes` 线性估算，不是精确剩余时长。
22. 模拟 HMI（`PR_SIM`）下泄漏测试可能被拒、压力恒定、温度缓慢跟随，P 组 / WaitStable 只能验证流程与超时路径；报告标 `simulated`。
23. 应用内只显示结果汇总表；完整报告（基线表、SVG 曲线、附录）用浏览器打开 `report.html`。
24. 方案编码的重复次数少于方案要求（P1 1 循环 11 点、P3 每级 1 轮、S1 1 循环、S3 每档 1 轮、T0/T1/T2 按档 1 轮）：报告每项标出本次轮数，P1 的 e_ij / 回差 / s_pooled / 线性拟合、P3 的大气压 / 温度补偿与 L_n / L_rel 换算、S3 的 1 h 温升留给离线合并或二期。
25. 合成自检项（T0Q / S1Q，`smoke.json`）显式关闭了 §0.4 门禁（`requiresPrecheck:false`），只用于联调 / 截图；正式方案项不得关闭。
26. 转速点按釜转速（≤ 450）改过（§5.1）；曲线与 CSV 里的「转速」是设定值（驱动器无转速反馈）。

**开发时要注意的（Avalonia 11.1）**

27. 无头截图在 Linux 需安装 Noto CJK 字体；macOS 用苹方兜底。
28. 外框的宽窄屏样式写在 `ShellView.axaml` 里，选择器都带外框视图的类型（如 `Grid#Root.narrow vs|RibbonView Button.rb`）。不要写不带类型的 `#名字` 选择器：会误中别处同名的元素（F2 复核时 `Border#Box` 误中了步骤条件框）。
29. 同一个 TextBlock 里字重不同的几段中文都走字体回退时，后一段会沿用前一段回退到的字体实例；字重变化之后的中文 Run 显式用 `UiFontCjk`（`Theme/UiFonts.cs`）。
    TextTrimming.CharacterEllipsis 在一行有好几段字体时省略得过早，用 `pr:TextFit.CharacterEllipsis`。被排成 0 × 0 藏起来的文字再显示时要重新测量（`Controls/TextRelayout`）。

## 9. 截图 / 自动化模式

**演示截图**（不需要 HMI）：`Control/tools/shots.sh [输出目录] [尺寸 …]` 先构建一次 Debug，再按尺寸各起一个无头进程
（`PR_CONTROL_HEADLESS=1 PR_CONTROL_DEMO=1 PR_CONTROL_SHOT=<输出目录> PR_CONTROL_SHOT_SIZE=WxH`），先跑审计自检、再按截图计划截图 + 审计 + 与参照图对照；
macOS 上再用系统字体栈（西文更窄）把每张截图审计一遍（`alt-font/`，`PR_SHOTS_ALT_FONT=none` 关闭）。默认尺寸 1920x1080、1366x768（外框与页面）+ 1920x6400、1600x7600、1366x7600（组件陈列页 `gallery`）。
配置和数据目录默认放在输出目录下；任何审计非空或进程失败时以非 0 退出。

```bash
S=<临时目录>/shots
PR_CONTROL_CONFIG=$S/cfg PR_CONTROL_DATA=$S/data bash Control/tools/shots.sh $S             # 全部
PR_CONTROL_SHOT_NAMES=home,page-set-pid bash Control/tools/shots.sh $S 1920x1080 1366x768   # 只拍某几张
```

截图计划在 `Shot/ShotPlan.cs`（`Fusion`）+ 各阶段的分文件（`ShotPlan.F4.cs` … `ShotPlan.F8.cs`、`ShotPlan.Unit.cs`、`ShotPlan.Pid.cs`，以 `Part` 开头的 `Spec[]` 字段按名字收集）。
