## 1. 用途与组成

PC 控制软件是触屏 HMI 的**远程客户端**：通过 HMI 对外接口（REST + WebSocket）读取 8 通道的实时状态、下发程序与命令、记录会话，并内置 **RV1–RV4 摸底性能测试模块**（按 `test-plan/RV1-4摸底性能测试方案.md` 编码的测试项，自动采集 + 人工录入 + 报告）。

## 2. 构建与运行

需要 .NET 8 SDK（8.0.4xx）。

```bash
cd ParallelReactor-avalonia
dotnet build ParallelReactor.sln -c Debug          # 全部工程
dotnet run --project Control/ParallelReactor.Control   # 启动 PC 控制软件（桌面窗口，默认 1440×900；不设最小尺寸，窄于 1366×768 时外框等比缩小）
dotnet test Control/tests/ParallelReactor.Control.Tests      # PC 端单元测试：Contracts / Client / PerfTest / Core / 色板与字号检查（不引用 App）
dotnet test Control/tests/ParallelReactor.Control.App.Tests  # App 的视图模型、对话框与实时数据源（引用 App）
dotnet test ParallelReactor.sln -c Debug                     # 两个测试工程一起跑（解决方案里只有这两个测试工程）
```

发布（示例，Windows x64 自包含）：

```bash
dotnet publish Control/ParallelReactor.Control -c Release -r win-x64 --self-contained -p:PublishSingleFile=true -o out/control-win
```

Release 构建不含无头 / 截图平台（`Avalonia.Headless` 仅 Debug 引用）。

触屏 HMI 侧需要先打开接口：配置文件 `api.json`（或模拟 `api-sim.json`）里 `enabled=true`，并发放令牌（见《接口使用说明.md》§2）。本机联调可用模拟 HMI：

```bash
PR_SIM=1 PR_HEADLESS=1 PR_API=1 PR_API_PORT=18080 dotnet run --project ParallelReactor.csproj
```

## 3. 连接设备、令牌与控制权

### 3.1 连接（M3：多台设备）

同时连多台：每台设备一个接口地址、一个访问令牌、一个控制权（样稿「添加设备」的副标题）。设备列表存在 `devices.json`（§3.4），顺序就是设备管理、资源管理器、总览里的顺序。

- **添加设备…**（菜单「设备」、资源管理器标题栏「添加」、设备管理底栏「添加设备…」）：地址、端口、访问令牌（可显示 / 隐藏）、「记住令牌」（D7，见 §3.4；样稿没有这一栏）、
  别名（输入时就地校验：不能为空、最多 8 个汉字或 16 个字母、不能和别的设备重名，默认第一个没用过的「k号机」）、型号（真机从 `/device` 读，只读；演示是「型号（原型演示）」下拉）、
  启动时「自动连接」（要求勾了「记住令牌」，没勾时带原因不能勾）。样稿里令牌下面那句「在设备触屏「设置 → 远程接口」查看」去掉了：HMI 只存令牌的哈希，触屏上看不到令牌。
  **测试连接** = 先 `GET /health`（不带令牌，只看地址和端口通不通），再 `GET /device`（带令牌：验证令牌、读型号），结果写在底栏左边：「✓ 连接成功 · 读取到 HT-PR8」/「⚠ 连接失败：401 UNAUTHORIZED：…」；
  不建 WebSocket、不申请控制权、不写任何东西。**添加并连接** = 登记（立即写 `devices.json`）、选中新设备、提示「已添加 4号机 · 正在连接 192.168.1.50:8080」，然后在后台连接
  （设备马上出现在列表里，从未连上的设备写「正在连接…」「未连接」；连不上时设备留着，提示一次「4号机 · 连接失败：…」，状态「连接失败 · 2 s 后重试」并倒计时自动重试，见下面的「重连」）。
- **启动**：并行连接勾了「启动时自动连接」**且令牌已经存在本机**的设备（D7：没存令牌的不自动连接）；其余设备「已断开」，在设备管理里点「连接」（要先在「编辑设置」里填令牌）。
- **设备管理…**（菜单「设备」）：一张表 别名 · 型号 · SN · 地址 · 状态 · 控制权 · 自动连接 · 操作（断开 / 连接、编辑、移除），每秒刷新；没连上过的设备 SN 取上次连上时记下的。
  真机上「自动连接」那一格要求记住了令牌、令牌也在本机：没勾「记住令牌」时带原因「先勾选「记住令牌」：启动时自动连接要用本机保存的令牌」，
  勾了却没有令牌（记住的读不出来、还没输入）时不打勾、带原因「令牌未保存 · 在「编辑设置」里输入」（M3 复核）。
- **编辑设置…**（设备菜单、设备管理）：同一张表单，预填这台的地址、端口、令牌、别名、自动连接；型号只读。改了地址 / 端口 / 令牌且正连着时：先释放本机的控制权（或取消申请），断开，按新地址重新连接
  （对话框里先提示「地址或端口改变后会断开并按新地址重新连接；本机的控制权会先释放。」，只换了令牌时「令牌改变后会断开并用新令牌重新连接…」）；令牌留空 = 不改。换了令牌时，学到的令牌权限（§3.2）作废。
  「保存」存好就关，释放、断开、按新设置的第一次连接都在后台做（结果照常提示；M3 复核：以前对话框要等最长约 13 s）。勾了「记住令牌」而本机还没有这台的令牌时要先填令牌（「请输入访问令牌」）。
- **重命名…** / **移除…** / **断开连接…**（设备菜单、设备管理）：重命名只改本机（不发给 HMI）；移除前、断开前，本机持有的控制权先释放、正在申请的先取消（本机持有或正在申请时先确认）。
  设备上的程序与数据不受影响，之后可以重新添加。
- **本机客户端名**全局一个（触屏弹窗与审计里显示的名字，菜单栏右端「本机：…」；HMI 认的控制权持有者也是它）。默认「PC-」+ 这台电脑的计算机名（M3 复核：以前每台都是 `PC-测试工位1`，
  触屏分不清是谁，两台都用默认名时本机会把另一台 PC 的控制权当成自己的）：第一次运行时就写进 `devices.json`；v1 迁移时客户端名还是旧默认 `PC-测试工位1` 的也换成这个（提示一次）。
  样稿说「在 设置 中修改」，设置页在第二阶段 —— 之前在**设备 › 本机客户端名…**里改（真机；添加设备的说明也照实写这个入口，演示照样稿）：一栏输入，不能为空、最多 64 个字符
  （按 HMI 的规则去掉控制 / 零宽字符），保存后写进 `devices.json`；已经连着的设备在下次连接时改用新名字（HMI 认的持有者照旧是建连接时的名字）。启动时也可以用 `PR_CONTROL_CLIENT` 覆盖。

**重连（M3 的重连监督，`Services/LiveDeviceSource`，每台设备各自一份）**：连接分四种状态（样稿 `conn.state`）——
- **已断开**：还没开始连（没勾自动连接、没有令牌）或用户点了「断开连接」；按钮「连接」。没有令牌时「连接」提示「1号机 · 请输入访问令牌」（先「编辑设置」填令牌）。
- **正在连接… / 正在重连…**：一次连接尝试正在进行（REST 起步 `GET /device` + `/control` + `/snapshot`，或 REST 已通、WebSocket 在握手 / 等 `hello`）。
- **已连接**：WebSocket 收到 `hello`（实时数据在流）。只是 REST 通了、WebSocket 连不上**不算**已连接（例如 HMI 的 WebSocket 连接数已满，见下面的 503）。
- **断线、倒计时**：在等下一次尝试 —— 从未连上的设备「连接失败 · 5 s 后重试」，连上过的「连接中断 · 重连中 5 s」（资源管理器细节条「重连中 5 s · 数据停在 10:11:40」）。
  两种等待：首次连接（REST 起步）失败 → 本机自己倒计时重试，间隔 2 → 4 → 8 → 10 s（之后一直 10 s，`LiveDeviceSource.RetryMin / RetryMax`）；
  连上之后 WebSocket 断了或握手被拒 → Client 按 0.5 → 10 s 退避重连，倒计时取它的 `NextRetryAt`，尝试的那一刻显示「正在重连…」。

「立即重连」（设备菜单、检查器、设备管理的「连接」、申请控制权对话框）打断任一种等待、马上再试。失败原因记在设备上（资源管理器设备头的悬停提示多一行原因），
同一轮里每种原因只提示一次：「4号机 · 连接失败：网络错误：Connection refused (192.168.1.41:8080)」；连上过的设备断线时网络层的原因不提示（徽标已经写着「连接中断」），
握手被拒的照样提示 —— 例如 HMI 每台最多 4 个 WebSocket 客户端（R19），第 5 个得到 503：「2号机 · 连接失败：WebSocket 连接数已达上限 · 请关闭该设备上的其他客户端（HTTP 503 TOO_MANY_CLIENTS）」
（这几句原因不是样稿的文字，取自 Client 的 `WsConnectException` / 旧界面的 `Describe`）。连上之后清掉原因与重试计数。
**HMI 重启**（`bootId` 变了：同一条连接上 WebSocket 的 `hello`，或者断线期间重启、重新连上时 `/device` 的 `bootId` 不同）：提示「1号机 · 设备 HMI 已重启 · 曲线缓冲已清空」，
重新读 `/device`（序列号 / 型号 / 已安装通道可能变了）、`/settings`（量程）、当前报警（整个替换）和最近的事件（事件按「序号纪元:序号」区分，重启后序号从头计不会撞号），
本机下发过的程序（程序台账，§4.8：含以前几次运行时下发、从台账文件读回来的）全部作废（「启动」回到启用 + 加热，「全部运行」要先重新下发，D6）。
多台设备各自监督、互不影响；Client 的事件经 UI 线程的同步上下文投递，每台设备把一批事件合并成一次刷新，`FleetVm` 再合并一次（R10）。

**停止类在断线时还能不能发**（`LiveDeviceSource.StopReachable`，M3 复核）：要有 REST 确实通的**正面证据** —— REST 起步刚完成、WebSocket 收到 `hello`、WebSocket 握手被 HTTP 拒绝
（503 / 401…：主机答话了）、探测 `GET /health` 有响应、命令送达；最近一次证据是网络层失败（WebSocket 连不上：拒绝连接 / 找不到主机 / 超时；探测失败；命令网络错误 / 超时）时就不算。
WebSocket 断了（连上过）或在退避时，每 3 s 探测一次 `GET /health`（单次 ≤ 3 s）：拔线 / 主机不回包时 WebSocket 的握手可能挂到系统的 TCP 超时（20–75 s），探测更早知道。
所以主机真的不通时只剩 none 类（同样稿：急停 / 全部停止对话框里这台灰、写「连接中断 · 无法发送」，全局停止格在全部设备都这样时「没有已连接的设备」）；
REST 通了而 WebSocket 不通（例如 503）时，连从未连上的设备也能发停止类（检查器写「尚未收到数据 · 停止类操作随时可用」）。

连接、控制权、急停、报警都显示在新外壳里：资源管理器的设备头（短控制权徽标、报警标记、运行 k/n；断线时连接徽标 + 「重连中 … · 数据停在 …」）、
页签（断线图标 / 错误报警红点）、状态栏（已连接 k/n 台、远程控制 k 台、报警 / 提醒、会话）。

### 3.2 令牌角色

| 角色 | 能做什么 |
|---|---|
| `viewer` | 只读：看状态、曲线、事件、文件 |
| `operator` | 申请控制权后可写；`estop=true` 的令牌可发急停 |
| `admin` | 同 operator，另可用管理端点 |

HMI 的规则（`Api/Endpoints.Write.cs`）：控制类写命令、申请 / 释放控制权、心跳、确认报警、会话要 operator 及以上；停止类要 operator **或**急停权限位；`/estop` 只看急停权限位。
接口还没有「我是什么角色」的端点（A3），所以本机在**第一个 `403 FORBIDDEN_ROLE` 之后学到**并按设备缓存（Core 的 `TokenRole`，换令牌时作废），之后守卫直接禁用并写明原因、不再发给设备：
读请求（`GET`）不会因为角色被拒，不学；只要 admin 的 PID 写入被拒（「该操作需要 admin 角色」）说明不了 operator 的权限，也不学；令牌的角色写在 HMI 的配置里、要重启 HMI 才生效，
所以 **HMI 重启（bootId 变化）后学到的作废**，下一个 403 再学（M3 复核）。
控制类 / 记录类被拒 → 只读令牌（控制类、申请控制权、确认报警、会话禁用：「1号机的令牌只能读取 · 需要 operator 令牌」）；停止类被拒 → 只读且没有急停权限位（停止类也禁用：
「1号机的令牌只能读取 · 停止需要 operator 令牌或急停权限」，急停「1号机的令牌没有急停权限」）；急停被拒 → 没有急停权限位（只禁用急停）。没学到的一律不禁用
（停止类、急停宁可发出去被拒，也不能被本机猜错拦下）。这三句样稿里没有，写法照 HMI 自己的 403 消息。

### 3.3 控制权（租约）与触屏的协作

控制权的状态在新外壳里写在三处：资源管理器设备头的**短徽标**（完整文字在提示里；设备断线时这里换成连接徽标）、时间轴组头（完整文字）、
检查器的**控制权卡**（徽标 + 一到两行说明 + 唯一的操作）。下面的例子是 1号机、本机客户端名 `PC-测试工位1`。

1. **本地模式**（默认）：触屏自己控制，PC 只能看。PC 的受控写命令会收到 `409 MODE_LOCAL`。
2. PC 点 **申请控制权**（检查器控制权卡的「申请控制权」、设备菜单「申请控制权…」、总览分区「⋯」）先打开「申请控制权 · 1号机」对话框（样稿 `lease:k`）：说明请求会显示在 1号机触屏上、只影响这一台、
   停止类不需要控制权；「发送申请」→ 对话框留着，换成倒计时环（剩余秒数）+ 三步（已发送请求 / 等待现场确认 / 远程控制中），底栏「取消申请」「后台等待」；确认之后对话框里是「1号机 远程控制中」+「释放控制权」「完成」。
   触屏弹出「允许 / 拒绝」（`autoGrantRemote=true` 时直接授权）。
   等待期间（`/control` 的 `requestTimeoutSec`，默认 60 s）短徽标 `申请中 45 s`（倒计时；完整文字 `申请中 · 45 s`），控制权卡的说明「等待1号机触屏确认 · 超时自动取消」「确认前只能查看；停止类操作随时可用」，
   下面整行「取消申请」。倒计时按 HMI 给的到期时刻（`POST /control/request` 的 `expiresAt`），用 WebSocket `hello` 的服务端时间修正两边的时钟偏差。
   结果用 toast 说（样稿的写法）：「1号机触屏已确认 · 远程控制中」或「1号机控制权申请超时 · 触屏未确认」；HMI 设了自动授权（`autoGrant`）时没有人在触屏上确认，写「1号机已获得控制权 · 远程控制中」（M3 复核）。
   触屏点了「拒绝」时 HMI 对这个令牌冷却 30 s：toast 与「申请控制权」的原因都写「1号机触屏已拒绝申请 · 28 s 后可再申请」（倒计时；样稿没有拒绝，这句沿用「… s 后重试」的写法），冷却过了才能再申请。
   申请**超时**时 HMI 同样冷却 30 s（从它的到期时刻起算），HMI 回 429 时原因也不确定：「申请控制权」写中性的「1号机申请刚被拒绝或超时 · 20 s 后可再申请」（M3 复核：以前超时后能点、第一下得到 429）。
   申请被 409 NOT_CONTROL_HOLDER 拒绝时提示 HMI 自己的话「1号机 · 当前控制权属于「X」」（不再是写命令那句「请先申请远程控制」）。申请控制权对话框的倒计时环满格 = HMI 的 `requestTimeoutSec`（默认 60）。
3. 允许后 PC 持有**租约**：短徽标 `远程控制`（完整文字 `远程控制中`），控制权卡的说明「PC-测试工位1 · 心跳正常」+ 行内「释放」，状态栏「远程控制 1 台」；软件自动按 `heartbeatTimeoutSec/2` 发心跳（优先 WS `hb`，WS 不通时 REST）。此时触屏的手动操作被锁定，但触屏的**停止类**按钮与「切回本地」随时可用。
   租约在别的客户端手里时（第 5 种状态，M3 有自己的徽标：灰底 + 人形图标）短徽标 `其他客户端 PC-xx`，完整文字 `远程控制中（其他客户端 PC-xx）`，控制类按钮和「申请控制权」的原因也这样写；
   别的客户端的申请正在等触屏处理时（`GET /control` 的 pending 不是本机），「申请控制权」带原因「1号机已有待处理的远程申请（PC-xx）」（HMI 会以 409 拒绝；写法照 HMI 的消息）。
   **本机旧租约**（M3 复核）：HMI 说控制权在本机客户端名手里、本机这条连接却没有持有（上次运行崩溃 / 强退留下的，心跳还没超时）—— 短徽标 `本机旧租约`（同第 5 种的样子），
   完整文字 `远程控制中（本机旧租约）`；HMI 还在 remote 时「申请控制权」带原因「1号机远程控制中（本机旧租约） · 心跳超时后可重新申请」，心跳超时进入 remoteLost 之后可以申请
   （HMI 让同一令牌 + 客户端名的新申请作废旧租约）。
4. 心跳中断（网线 / 休眠）→ 触屏进入 `remoteLost`。本机从 WS `control` 消息、心跳响应或 `GET /control` 得知以后：短徽标 `宽限 18 s`，控制权卡的徽标 `心跳中断`（提示里是完整文字 `控制权心跳中断 · 宽限 18 s`），
   说明「宽限 18 s · 心跳恢复后继续」「超时交回触屏」+「释放」，状态栏「宽限中 1 台」，toast「1号机 · 控制权连接丢失 · 宽限期内自动恢复」。设备同时断线时，资源管理器多一条细节条「控制权宽限 18 s · 超时交回触屏」，时间轴组头写 `控制权宽限 18 s`，
   控制权卡说明的第二行也是「控制权宽限 18 s · 超时交回触屏」。宽限期内恢复心跳即继续（toast「控制权已恢复」），超过宽限期租约作废（触屏按 `onRemoteLost` 配置：keep / stopHeat / estop）。
   宽限的倒计时 = Client 记下的丢失时刻 + `leaseGraceSec`（重连后才从 `GET /control` 得知已丢失时，按 HMI 的硬到期反推）。宽限期满租约作废：toast「1号机宽限期结束 · 控制权已交回触屏」（样稿），
   回到本地只读；**M3 起软件不再自动重新申请**（Client 的 `AutoReacquireLease = false`：样稿里交回触屏之后要不要再申请由用户决定；旧界面会自动重申请并 toast「控制权宽限期满 · 正在重新申请」，
   要恢复旧做法改 `LiveDeviceSource.Connection.cs` 的 `NewOptions` 一行）。连续两次心跳没送到、HMI 还没报 `remoteLost` 时，控制权卡和申请控制权对话框的「心跳正常」换成旧界面的「心跳异常」
   （「PC-测试工位1 · 心跳异常」；样稿没有这一档）。网线断开时 WebSocket 会在 10 s 内转为重连（第 5 条），设备显示 `连接中断 · 重连中 N s`。
5. WebSocket 10 s 收不到 pong（拔线 / HMI 冻结）→ 软件主动撕掉连接并按 0.5 → 10 s 退避重连：等待时 `连接中断 · 重连中 N s`（设备头的连接徽标 `连接中断`），尝试时 `正在重连…`（§3.1「重连」）；
   重连 / HMI 重启后若 `GET /control` 显示设备已回到本地而本机之前持有租约，toast「1号机 · 重连后设备已回到本地模式 · 控制权失效」（别人持有时「1号机 · 重连后控制权已失效」），**不**自动重新申请。
   HMI 重启（bootId 变化）时曲线缓冲清空、重读 `/device` 与 `/settings` 并 toast 提示（§3.1）。
6. 触屏「切回本地」或急停 → 租约失效（`takenBack` / `invalidated`），软件**不**自动重申请：toast「1号机 · 触屏已收回控制权」或「1号机 · 急停：控制权已失效」，短徽标回到 `本地只读`（完整文字 `本地 · 只读`），
   控制权卡的说明「本机只读 · 启动、设定等需要控制权」「停止类操作随时可用」+ 整行主要按钮「申请控制权」。心跳 / 写命令被 409 拒绝也会 toast 说明原因（「心跳被拒 · 控制权失效（…）」「写命令被拒 · 控制权失效（…）」）。
7. PC 点 **释放控制权**、断开连接或关闭窗口 → 先中止运行中的性能测试（停止类收尾）、释放租约，触屏回到本地模式。停止类命令走独立通道，不会排在正在重试的受控写后面。

不需要控制权的操作（停止类，只要连接正常就能发）：**急停**（页签栏右上唯一的红色「急停」或设备菜单「急停 1号机…」，打开多选的急停对话框：已连接的默认全选 / 只预选这一台）、全部停止、停止加热、
停用通道、中止程序、停止搅拌、报警确认、会话 / 标记。控制类操作在没有控制权、急停中或断线时不可用，原因写在按钮上（锁图标提示、点击 toast 原因），
执行前还会再查一次（界面状态可能已经过期）。「取消申请」时界面立即回到本地只读（toast「1号机 · 已取消控制权申请 · 若触屏已批准将自动释放」—— 后半句是 PORT-PLAN R7 要求写明的），
后台照样查这条申请直到有结果（Client 的 `CancelRequestAsync`：HMI 没有取消申请的端点）；若触屏之后才批准，软件立即 `POST /control/release`（不进入远程控制、不发心跳），
toast「1号机 · 触屏在取消后批准了申请 · 已自动释放」（释放一直失败时「… · 自动释放失败，请在触屏收回控制权」）。断开 / 移除时若还有已取消、在等结果的申请，WebSocket 先停，
REST 留给这个后台守卫（最多 3 min）再释放连接。**退出时**本机的申请（或已取消、还在等结果的申请）还在某台的触屏上：先在窗口里问「退出控制软件？」（M3 复核，R7）——
「等结果再退出」先取消申请，等到每条都有结局（批准的立即释放、拒绝、超时）或过了 HMI 的到期时刻再 5 s（最多 80 s，说明里倒计时）再退出；「仍然退出」照常退出（3 s 预算里等一下）；
关掉对话框 = 不退出。关窗、文件 › 退出、系统的退出（⌘Q）都先问。

**只是 WebSocket 断了、在自己重连时**（第 5 条：心跳超时、`1008` 慢消费者都会这样），界面写「连接中断 · 重连中 N s」/「正在重连…」，控制类和申请控制权照样不可用；
**REST 确实还通时**（§3.1 末「停止类在断线时还能不能发」：要有证据），真正的停止类照样可用：急停、全部停止、停止、停用、停止加热、中止程序、停止搅拌 —— 尽力发送，送不到时 toast 失败原因
（送不到 = 网络错误，这台随即只剩 none 类）；全局停止格和急停 / 全部停止对话框也算这台（守卫的 `GuardFacts.StopReachable`）。会话 / 打标记 / 确认报警（样稿也算 safe，但不是停止）等 WebSocket 恢复再做。
主机真的不通、用户点了「断开连接」、首次连接失败之后（没有连接对象）才只剩重连 / 移除这类操作（M3 复核：以前只要连上过就一直算能发，主机断电了也一样）。

**全部停止与搅拌（一个开关，用户 2026-11-09 已确认：连搅拌一起停）**：「全部停止」发 `POST /stop-all {stopStir}`，`stopStir` 只看 Core 的 `ControlOptions.StopAllStopsStirring`
（`Control/ParallelReactor.Control.Core/ControlOptions.cs`，全软件只有这一行）。默认 `true`（与旧界面相同）：中止程序、停止加热、关闭进气、停止搅拌，
实时设备发 `stopStir:true`，演示数据里共用搅拌和各釜搅拌也停。全部停止对话框的副标题是「停止所选设备上全部反应釜：中止程序、停止加热、关闭进气、停止搅拌」，
说明的最后一句是「搅拌也会一并停止；需要立即切断并锁定请用急停。」，发送后的提示和单台的结果末尾加「 · 搅拌一并停止」（文字在 Core 的 `StopAllText`，样稿已同步）。
把那一行改成 `false` 就是样稿第一版的做法（搅拌保持当前状态；HMI 自己的 `/stop-all` 默认也不停搅拌）。测试两种取值都覆盖，改开关不用改测试。
急停另外立即切断并锁定，复位只能在触屏；单独停搅拌用检查器「共用搅拌」的「停止搅拌」。

### 3.4 本机配置与令牌的保存（devices.json，D7）

- **devices.json**（M3，替代 v1 的 `control.json`；位置见 §6）：`clientName`、`timelineMinutes`、`tokenStore` 和设备列表（`id`、`alias`、`host`、`port`、`rememberToken`、`autoConnect`、
  `lastSerial`、`lastModel`），数组顺序 = 设备顺序。写入是原子的（同目录临时文件写完再改名替换）；读的时候容错（注释、多余的逗号、字段大小写、类型不对的字段用默认值、没有地址的项跳过、
  重复的 Id 重新生成、不合规 / 重复的别名换成没用过的「k号机」、端口越界用 8080；整个文件坏了时从空列表开始，第一次保存前留一份 `devices.json.bad`）。
- **迁移**：只有 v1 的 `control.json` 时，启动时把它变成「1号机」（地址、端口、客户端名、记住的令牌、自动连接）写进 `devices.json`，然后把 `control.json` 里的明文令牌抹掉（其余字段留着）。
- **令牌只在勾了「记住令牌」时落盘**，没勾的只在内存里（下次启动要重新输入）；「启动时自动连接」要求令牌已经存了。
  - **Windows**：DPAPI 加密（当前用户、本机；`CryptProtectData`），密文写在 `devices.json` 这台设备的 `token` 字段（前缀 `dpapi:`）。只有同一个 Windows 用户在同一台电脑上能解开；换电脑 / 换用户时当作没记住。
  - **macOS / Linux**：**不加密**。令牌以明文写在 `devices.json` 旁边的 `tokens.json`，文件权限 0600（只有本用户可读写，先以 0600 新建临时文件再改名替换）。
    这台电脑的管理员、以及能以本用户身份运行程序的人都能读到 —— 共用账户的电脑上不要勾「记住令牌」。
- 截图 / 演示（设置了 `PR_CONTROL_SHOT` 或 `PR_CONTROL_DEMO`）时**不写任何配置文件**（迁移照样在内存里做；程序草稿 `drafts.json` 同样不写 —— M3 复核：以前交互演示会写）。
- 运行中保存 `devices.json` 失败（只读目录、磁盘满…）时 toast「配置保存失败：…」（M3 复核：以前只记在加载说明里，改动看起来成功了、下次启动却没了）。
- `clientName` 没写（或清洗后为空）时用这台电脑的默认名（「PC-」+ 计算机名，§3.1）。

## 5. 性能测试流程

### 5.1 测试项清单（左侧面板）

方案来自 `Control/ParallelReactor.PerfTest/Plans/rv1-4-baseline.json`（26 项：§0 R0 前置检查表、阶段 1 F1–F6、阶段 2 S1–S3、阶段 3 P1–P4、阶段 4 T0 / T1 / T2 / T4 / T5、阶段 5 C2-a；T3 / C1 / C2-b / LT1 / M1 / LT2 为二期，灰显不可选），末尾附加 `smoke.json` 的两项「快速自检」（T0Q 升温 60 ℃ 记录 30 s、S1Q 搅拌 300 rpm 10 s）用于联调与截图。`PR_CONTROL_PLAN=<json 路径>` 可换用外部方案文件。

每行：复选框 · `ID 名称` · 右侧小字（自动 · N min / 手动确认 / 转速表读数 …，来自方案 `hint`）；鼠标悬停显示出处 / 目的 / 仪器 / 预计时长 / 前置项。标题右侧「全选」「清空」。面包屑显示 `已选 N 项 · 约 X min`。

**测试通道**：RV1–RV4 芯片可选（默认全选），RV5–RV8 按方案 §0.3 禁用；设备 `installedChannels` 不含的通道同样禁用。

### 5.2 运行

前提：已连接且**持有控制权**（否则 Toast 提示）。**§0.4 门禁**：勾选了任何带热 / 带压项（含加热、自整定、程序运行、泄漏测试命令）而本次会话里 R0 前置检查表还没通过时，软件会自动把 R0 加到最前面并提示；引擎侧同样拒绝——R0 未入选 / 未通过（含被跳过）的运行里这些项一律「跳过」，前置项被跳过的后续项也跳过。检查器 **开始测试** 后：

- 引擎（`PerfRunner`）在后台线程顺序执行所选项；运行开始时 `POST /sessions`（testId = 运行编号 `PT-yyyyMMdd-HHmmss`），每项 / 每轮 / 每条命令前 `POST /sessions/current/markers`，结束时 `DELETE /sessions/current` 并下载触屏侧会话 CSV——触屏自己的记录文件因此也带上标记。已有活动会话时弹出确认（结束它 / 本次不建会话）。
- **测试进度**面板：总进度条 + `总进度 k / n · %`、`预计剩余`、`已用时`；项行（`1. ID 名称 · 通道 · 提示`）与当前项的步骤子行（命令 / 记录 / 等待稳定 / 仪器读数 / 手动确认 / 计算 …，当前步带倒计时）；四张卡：当前步骤（阶段文字、步骤 k/n、倒计时 / 稳定计时 / 等待录入）、人工录入、搅拌电机实际转速、首个目标通道温度 / 压力实时值；底部事件行（开始 / 等待 / 录入 / 安全事件）。
- **实时曲线**：首个目标通道温度 · 压力 · 全局转速（rpm 原值），左轴 0–200 ℃，右轴 0–1000。
- 检查器按钮：**开始测试 ↔ 暂停 / 继续**（运行中随时可按，只在安全暂停等待应答时禁用；暂停在步与步之间或记录间隙生效，暂停时长不计入步骤）、**确认 / 继续**、**跳过本步**、**中止**（中止程序 → 取消自整定 → 停止加热 → 中止泄漏测试 → 停止搅拌，结束会话，照常出报告；**不**急停）、**生成报告**、**下载报告**、**下载原始数据**、**返回测试项**。急停始终在菜单栏，不经引擎；方案 F4 由引擎下发的软件急停是预期内的，不会触发安全暂停，F4-10 复位后 F4-11 自动重新申请控制权。

### 5.3 提示（等待操作员）

| 步骤种类 | 界面 | 操作 |
|---|---|---|
| 手动确认（Instruction） | 「手动确认」卡：标题 + 现场操作说明 + 备注框 | 确认 / 继续；跳过本步 = 未确认（按方案 `onFail` 处理） |
| 检查表（Checklist，如 R0 的 13 项） | 同上 + 逐项复选框（+ 两人签字框） | 全部勾选（并签字）后 确认 / 继续；未勾全会提示 |
| 人工录入（ManualEntry） | 「人工录入」卡变绿边：仪器名、提示文字、每个读数一个 44 px 框（多次 / 多通道换行，下标 #1 #2 / RV1 #1）；文字型字段在下方卡 | 填完后 确认 / 继续 或在框内回车；越界 / 非数字即时提示，引擎侧校验失败会把原因写回卡上并要求重填 |
| 安全暂停 | 红边卡：报警 / 急停 / 控制权丢失 / 压力模块离线 / 其他模块离线 > 30 s / PV > SP+15 ℃ + 方案建议 | 确认 / 继续 = 继续；中止 = 停止并出报告；绝不自动继续。等待录入 / 确认期间到达的安全事件立即弹卡，不必先提交录入。通讯模块离线按方案 §0.1-11 先自动执行停止类收尾（停加热 / 搅拌 / 程序 / 自整定 / 泄漏测试）再询问 |

### 5.4 报告

运行结束（完成或中止）后引擎立刻生成 `report.html`。点 **生成报告** 切换到报告视图：报告编号 · 通道 · 项数 · 模拟标记，总用时；表格每项一行（结论 / 判定）+ 每个指标一行（设定 / 标准、实测、误差）。判定列默认「—（摸底）」，仅方案给出硬性判据的项才显示 合格 / 不合格。报告头的环境记录（§0.5）来自 R0-5 的录入；基线表的「规格草案」只在独立轮次 n ≥ 6 时给出（ISO 16269-6 容差区间 k 因子，同日 4 通道不算独立样本），否则只报 x̄ / s / 最差；每项标明「本次编码重复 N 轮」，方案要求的 n 不足时由多次运行离线合并。曲线与 CSV 里的「转速」是设定值（驱动器无转速反馈）。**打开报告** / **下载报告** 用系统默认浏览器打开 `report.html`；**打开文件夹** / **下载原始数据** 打开运行目录。模拟运行（HMI `PR_SIM`）的报告顶部有红字「模拟运行，数据无效」。

## 8. 已知限制

1. 接口不开放阀门手动控制、进气 / 排空、设置修改（TMaxSp、RpmMax、逼近 Δ、加减速、报警阈值）、急停复位、PID 读取：方案里这些步骤在 PC 端是「手动确认」（触屏操作）+ `GET /settings` 复核，清单右侧如实标「触屏操作 + …」。
2. 接口没有「程序下一步」命令（新时间轴不再有跳步按钮）。HMI 没有取消控制权申请的端点：本机「取消申请」后若触屏仍批准，软件立即释放。
3. 报告「判定」列：方案明确摸底不做合格判定，默认全部「—（摸底）」；哪些判据升级为硬性需产品确认。
4. 性能测试 ETA 按方案 `estimatedMinutes` 线性估算，不是精确剩余时长。
5. 模拟 HMI（`PR_SIM`）下泄漏测试可能被拒、压力恒定、温度缓慢跟随，P 组 / WaitStable 只能验证流程与超时路径；报告标 `simulated`。
6. 令牌「记住」时（默认不记）：Windows 用 DPAPI 加密；macOS / Linux **明文**写在 `tokens.json`（权限 0600）—— 见 §3.4。
7. 报告在应用内只显示汇总表；完整报告（基线表、SVG 曲线、附录）用浏览器打开 `report.html`。
8. 无头截图在 Linux 需安装 Noto CJK 字体；macOS 用 PingFang SC 兜底。
9. 方案编码的重复次数少于方案要求（P1 1 循环 11 点、P3 每级 1 轮、S1 1 循环、S3 每档 1 轮、T0/T1/T2 按档 1 轮）：报告每项标出本次轮数，P1 的 e_ij / 回差 / s_pooled / 线性拟合、P3 的大气压 / 温度补偿与 L_n / L_rel 换算、S3 的 1 h 温升留给离线合并或二期。
10. `HW_UNCONFIRMED`（命令已下发但硬件未在时限内确认）只提示、不自动重发，请核对属性卡 / 快照后再操作。
11. 合成自检项（T0Q / S1Q，`smoke.json`）显式关闭了 §0.4 门禁（`requiresPrecheck:false`），只用于联调 / 截图；正式方案项不得关闭。
12. 多台设备（M3）：程序页与性能测试页（旧样式）作用于第一台连上的实时设备（设备管理里的顺序），M7 加设备选择。实时设备的程序名 / 步骤 / 剩余时间来自程序台账（M5，§4.8）：本机下发、而且严格对得上时才显示，否则只显示 HMI 给的第 k/n 步。
    首次连接失败的重试不封顶次数（10 s 一次，直到连上、断开或移除）；令牌错了（401）也照样重试 —— HMI 只对同一地址每秒超过 10 次的鉴权失败回 429，10 s 一次不受影响，原因写在提示与设备头的悬停提示里。
