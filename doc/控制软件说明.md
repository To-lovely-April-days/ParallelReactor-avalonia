## 1. 用途与组成

PC 控制软件是触屏 HMI 的**远程客户端**：通过 HMI 对外接口（REST + WebSocket）读取 8 通道的实时状态、下发程序与命令、记录会话，并内置 **RV1–RV4 摸底性能测试模块**（按 `test-plan/RV1-4摸底性能测试方案.md` 编码的测试项，自动采集 + 人工录入 + 报告）。

解决方案（`ParallelReactor.sln`）中与 PC 端相关的工程：

| 工程 | 类型 | 内容 |
|---|---|---|
| `Contracts/ParallelReactor.Contracts` | net8.0 类库 | HMI 与 PC 共用的线上类型（`TelemetrySnapshot`、全部 REST / WS DTO、`ApiJsonContext` 源生成、错误码表、`OpCodes`、`EventRecord`、`SessionManifest`、`StepType`） |
| `Control/ParallelReactor.Client` | net8.0 类库（纯 BCL） | `ReactorApiClient`（全部端点）、`ControlLeaseClient`（租约 / 心跳状态机）、`TelemetryWsClient`（订阅 / 重连 / 重同步）、`ReactorConnection` 门面、`TelemetryStore` |
| `Control/ParallelReactor.PerfTest` | net8.0 类库 | 测试方案模型与 JSON（`Plans/rv1-4-baseline.json`、`Plans/smoke.json`）、`PerfRunner` 引擎、指标计算、`report.html` / CSV / JSON 产出 |
| `Control/ParallelReactor.Control` | Avalonia 桌面程序 | 主界面（系统视图 + 性能测试视图）、截图模式 |
| `Control/tests/ParallelReactor.Control.Tests` | xunit | Contracts 往返、Client 状态机、PerfTest 引擎 / 报告 / 方案校验 |
| `Control/tools/ClientSmoke` | 控制台 | 对真 HMI 的接口走通工具 |

## 2. 构建与运行

需要 .NET 8 SDK（8.0.4xx）。

```bash
cd ParallelReactor-avalonia
dotnet build ParallelReactor.sln -c Debug          # 全部工程
dotnet run --project Control/ParallelReactor.Control   # 启动 PC 控制软件（桌面窗口，默认 1440×900，最小 1080×600）
dotnet test Control/tests/ParallelReactor.Control.Tests  # PC 端单元测试
```

发布（示例，Windows x64 自包含）：

```bash
dotnet publish Control/ParallelReactor.Control -c Release -r win-x64 --self-contained -p:PublishSingleFile=true -o out/control-win
```

Release 构建不含无头 / 截图平台（`Avalonia.Headless` 仅 Debug 引用）。

触屏 HMI 侧需要先打开接口：配置文件 `api.json`（或模拟 `api-sim.json`）里 `enabled=true`，并发放令牌（见《接口使用说明.md》§2）。本机联调可用模拟 HMI：

```bash
PR_SIM=1 PR_HEADLESS=1 PR_API=1 PR_API_PORT=18080 dotnet run --project ParallelReactor.csproj
```

## 3. 连接设备、令牌与控制权

### 3.1 连接

菜单 **连接**（或 文件 › 连接设备…、侧栏齿轮）打开「连接设备」对话框：地址、端口、访问令牌（Bearer）、客户端名（触屏弹窗与审计里显示的名字，默认 `PC-测试工位1`）。「记住令牌」默认关闭——配置文件只存地址 / 端口 / 客户端名，不存令牌。

连接成功后菜单栏右侧显示设备（型号 · 序列号 · HMI 版本 · 模拟标记）、连接状态（`已连接 · host:port`，WS 断开时显示重连 / 重同步）和**控制权徽标**。

### 3.2 令牌角色

| 角色 | 能做什么 |
|---|---|
| `viewer` | 只读：看状态、曲线、事件、文件 |
| `operator` | 申请控制权后可写；`estop=true` 的令牌可发急停 |
| `admin` | 同 operator，另可用管理端点 |

### 3.3 控制权（租约）与触屏的协作

1. **本地模式**（默认）：触屏自己控制，PC 只能看。PC 的受控写命令会收到 `409 MODE_LOCAL`。
2. PC 点 **申请控制权**（检查器 / 徽标 / 文件菜单）→ 触屏弹出「允许 / 拒绝」（`autoGrantRemote=true` 时直接授权）。徽标显示 `● 申请中 · 等待触屏确认 · 剩余 N s`（60 s 超时）。
3. 允许后 PC 持有**租约**：徽标 `● 远程控制中 · <客户端名>`；软件自动按 `heartbeatTimeoutSec/2` 发心跳（优先 WS `hb`，WS 不通时 REST）。此时触屏的手动操作被锁定，但触屏的**停止类**按钮与「切回本地」随时可用。
4. 心跳中断（网线 / 休眠）→ 触屏进入 `remoteLost`，徽标 `● 连接丢失 · 宽限 N s`；宽限期内恢复心跳即继续，超过宽限期租约作废（触屏按 `onRemoteLost` 配置：keep / stopHeat / estop）。租约过期后软件会用同令牌 + 同客户端名自动重新申请一次。连续两次心跳失败徽标显示 `● 远程控制中 · 心跳异常`。
5. WebSocket 10 s 收不到 pong（拔线 / HMI 冻结）→ 软件主动撕掉连接并按 0.5 → 10 s 退避重连，状态文字 `重连中…`；重连 / HMI 重启后若 `GET /control` 显示设备已回到本地而本机之前持有租约，Toast「重连后设备已回到本地模式 · 控制权失效，正在重新申请」并自动重申请（触屏为 `autoGrantRemote=false` 时会再次弹窗）。HMI 重启（bootId 变化）时曲线缓冲清空并 Toast 提示。
6. 触屏「切回本地」或急停 → 租约失效（`takenBack` / `invalidated`），软件**不**自动重申请，徽标回到 `● 本地`；心跳 / 写命令被 409 拒绝也会 Toast 说明原因。
7. PC 点 **释放控制权**、断开连接或关闭窗口 → 先中止运行中的性能测试（停止类收尾）、释放租约，触屏回到本地模式。停止类命令走独立通道，不会排在正在重试的受控写后面。

不需要控制权的操作：**急停**（菜单栏红字 / 检查器，带确认框）、停止加热、停用通道、中止程序、停止搅拌、全部停止、报警确认、会话 / 标记。

### 4.3 系统视图

- **程序编辑器**（左）：面包屑 `系统视图 › RVn › 程序名`；每步一张卡（加热器 / 进气阀 SV 或排空阀 / 搅拌电机（全局 RV1–RV8））；「编辑程序」后设定值可改，Esc 取消；「下发程序」= `PUT /channels/{id}/program`；草稿存本机 `drafts.json`。
- **属性查看器**（右上）：温度 PV、压力（psi · MPa）、温度 SP（含定值 / 曲线、逼近阶段）、全局转速、加热输出 %、进气阀 / 排空阀。读数有效时右侧 4 px 绿边；模块离线灰显。
- **曲线**（右下）：温度 · 压力 · 转速 ÷ 2，X 轴按数据跨度自动取 1 / 2 / 5 / 10 / 20 / 40 / 88 min 档。
- **检查器**（最右）：编辑程序 / 下发程序 / 导出；通道操作（启用 / 停用、启动加热 (℃) / 停止加热、设定 SP、搅拌 开 / 停 (rpm)、运行 / 中止程序、全部停止）；控制权（申请 / 释放）；急停。需要控制权的按钮在未持有时禁用。
- **反应釜列表 + 时间轴**（底部）：每行状态文字（停用 / 已启用 / 升温中 / … / 未安装）、24V 母线；只有有程序（运行中 / 已结束）的行才画进度条（白段 = 剩余、绿段 = 已完成步比例、等气路紫灰段），条按程序开始时刻落在时间轴上，刚启动的程序至少 60 px 宽，头部时间标签与条用同一坐标系；行尾操作：启动 / 停止、停止、下一步（接口未提供，提示）、打开程序、下发草稿。

## 5. 性能测试流程

### 5.1 测试项清单（左侧面板）

方案来自 `Control/ParallelReactor.PerfTest/Plans/rv1-4-baseline.json`（26 项：§0 R0 前置检查表、阶段 1 F1–F6、阶段 2 S1–S3、阶段 3 P1–P4、阶段 4 T0 / T1 / T2 / T4 / T5、阶段 5 C2-a；T3 / C1 / C2-b / LT1 / M1 / LT2 为二期，灰显不可选），末尾附加 `smoke.json` 的两项「快速自检」（T0Q 升温 60 ℃ 记录 30 s、S1Q 搅拌 300 rpm 10 s）用于联调与截图。`PR_CONTROL_PLAN=<json 路径>` 可换用外部方案文件。

每行：复选框 · `ID 名称` · 右侧小字（自动 · N min / 手动确认 / 转速表读数 …，来自方案 `hint`）；鼠标悬停显示出处 / 目的 / 仪器 / 预计时长 / 前置项。标题右侧「全选」「清空」。面包屑显示 `已选 N 项 · 约 X min`。

**测试通道**：RV1–RV4 芯片可选（默认全选），RV5–RV8 按方案 §0.3 禁用；设备 `installedChannels` 不含的通道同样禁用。

### 5.2 运行

前提：已连接且**持有控制权**（否则 Toast 提示）。**§0.4 门禁**：勾选了任何带热 / 带压项（含加热、自整定、程序运行、泄漏测试命令）而本次会话里 R0 前置检查表还没通过时，软件会自动把 R0 加到最前面并提示；引擎侧同样拒绝——R0 未入选 / 未通过（含被跳过）的运行里这些项一律「跳过」，前置项被跳过的后续项也跳过。检查器 **开始测试** 后：

- 引擎（`PerfRunner`）在后台线程顺序执行所选项；运行开始时 `POST /sessions`（testId = 运行编号 `PT-yyyyMMdd-HHmmss`），每项 / 每轮 / 每条命令前 `POST /sessions/current/markers`，结束时 `DELETE /sessions/current` 并下载触屏侧会话 CSV——触屏自己的记录文件因此也带上标记。已有活动会话时弹出确认（结束它 / 本次不建会话）。
- **测试进度**面板：总进度条 + `总进度 k / n · %`、`预计剩余`、`已用时`；项行（`1. ID 名称 · 通道 · 提示`）与当前项的步骤子行（命令 / 记录 / 等待稳定 / 仪器读数 / 手动确认 / 计算 …，当前步带倒计时）；四张卡：当前步骤（阶段文字、步骤 k/n、倒计时 / 稳定计时 / 等待录入）、人工录入、搅拌电机实际转速、首个目标通道温度 / 压力实时值；底部事件行（开始 / 等待 / 录入 / 安全事件）。
- **实时曲线**：首个目标通道温度 · 压力 · 全局转速（rpm 原值），左轴 0–200 ℃，右轴 0–1000。
- 检查器按钮：**开始测试 ↔ 暂停 / 继续**（运行中随时可按，只在安全暂停等待应答时禁用；暂停在步与步之间或记录间隙生效，暂停时长不计入步骤）、**确认 / 继续**、**跳过本步**、**中止**（中止程序 → 取消自整定 → 停止加热 → 中止泄漏测试 → 停止搅拌，结束会话，照常出报告；**不**急停）、**生成报告**、**下载报告**、**下载原始数据**、**返回测试项**。急停始终在菜单栏，不经引擎；方案 F4 由引擎下发的软件急停是预期内的，不会触发安全暂停，F4-10 复位后 F4-11 自动重新申请控制权。

### 5.3 提示（等待操作员）

| 步骤种类 | 界面 | 操作 |
|---|---|---|
| 手动确认（Instruction） | 「手动确认」卡：标题 + 现场操作说明 + 备注框 | 确认 / 继续；跳过本步 = 未确认（按方案 `onFail` 处理） |
| 检查表（Checklist，如 R0 的 13 项） | 同上 + 逐项复选框（+ 两人签字框） | 全部勾选（并签字）后 确认 / 继续；未勾全会提示 |
| 人工录入（ManualEntry） | 「人工录入」卡变绿边：仪器名、提示文字、每个读数一个 44 px 框（多次 / 多通道换行，下标 #1 #2 / RV1 #1）；文字型字段在下方卡 | 填完后 确认 / 继续 或在框内回车；越界 / 非数字即时提示，引擎侧校验失败会把原因写回卡上并要求重填 |
| 安全暂停 | 红边卡：报警 / 急停 / 控制权丢失 / 压力模块离线 / 其他模块离线 > 30 s / PV > SP+15 ℃ + 方案建议 | 确认 / 继续 = 继续；中止 = 停止并出报告；绝不自动继续。等待录入 / 确认期间到达的安全事件立即弹卡，不必先提交录入。通讯模块离线按方案 §0.1-11 先自动执行停止类收尾（停加热 / 搅拌 / 程序 / 自整定 / 泄漏测试）再询问 |

### 5.4 报告

运行结束（完成或中止）后引擎立刻生成 `report.html`。点 **生成报告** 切换到报告视图：报告编号 · 通道 · 项数 · 模拟标记，总用时；表格每项一行（结论 / 判定）+ 每个指标一行（设定 / 标准、实测、误差）。判定列默认「—（摸底）」，仅方案给出硬性判据的项才显示 合格 / 不合格。报告头的环境记录（§0.5）来自 R0-5 的录入；基线表的「规格草案」只在独立轮次 n ≥ 6 时给出（ISO 16269-6 容差区间 k 因子，同日 4 通道不算独立样本），否则只报 x̄ / s / 最差；每项标明「本次编码重复 N 轮」，方案要求的 n 不足时由多次运行离线合并。曲线与 CSV 里的「转速」是设定值（驱动器无转速反馈）。**打开报告** / **下载报告** 用系统默认浏览器打开 `report.html`；**打开文件夹** / **下载原始数据** 打开运行目录。模拟运行（HMI `PR_SIM`）的报告顶部有红字「模拟运行，数据无效」。

## 6. 文件去向

| 文件 | 位置 |
|---|---|
| PC 端配置 `control.json`（地址 / 端口 / 客户端名 / 是否记住令牌 / 时间轴窗口） | `PR_CONTROL_CONFIG`，否则 macOS `~/Library/Application Support/ParallelReactor.Control/`，Windows `%APPDATA%\ParallelReactor.Control\`，Linux `~/.config/ParallelReactor.Control/` |
| 程序草稿 `drafts.json` | 同上目录 |
| 系统视图「导出」（程序 JSON + 当前 RV 遥测 CSV） | `PR_CONTROL_DATA/export/`，默认 `~/Documents/ParallelReactor/export/` |
| 性能测试运行目录 | `PR_CONTROL_DATA/perf/<运行编号>/`，默认 `~/Documents/ParallelReactor/perf/<运行编号>/` |

运行目录内容：`report.html`（自包含报告）、`result.json`（全部项 / 步骤 / 指标 / 命令 opId）、`summary.csv`、`raw/telemetry.csv`（每帧每通道一行）、`manual-entries.csv`、`events.csv`、`settings-snapshot.json`（开场 `GET /settings`）、`hmi/<会话>.csv`（触屏侧会话文件副本）。

PC 端永远不写触屏 HMI 的 `ParallelReactor` 目录。

## 8. 已知限制

1. 接口不开放阀门手动控制、进气 / 排空、设置修改（TMaxSp、RpmMax、逼近 Δ、加减速、报警阈值）、急停复位、PID 读取：方案里这些步骤在 PC 端是「手动确认」（触屏操作）+ `GET /settings` 复核，清单右侧如实标「触屏操作 + …」。
2. 接口没有「程序下一步」命令，时间轴的跳步按钮只做提示。
3. 报告「判定」列：方案明确摸底不做合格判定，默认全部「—（摸底）」；哪些判据升级为硬性需产品确认。
4. 性能测试 ETA 按方案 `estimatedMinutes` 线性估算，不是精确剩余时长。
5. 模拟 HMI（`PR_SIM`）下泄漏测试可能被拒、压力恒定、温度缓慢跟随，P 组 / WaitStable 只能验证流程与超时路径；报告标 `simulated`。
6. 令牌「记住」时以明文写入 `control.json`（默认不记；文件权限 0600）。
9. 方案编码的重复次数少于方案要求（P1 1 循环 11 点、P3 每级 1 轮、S1 1 循环、S3 每档 1 轮、T0/T1/T2 按档 1 轮）：报告每项标出本次轮数，P1 的 e_ij / 回差 / s_pooled / 线性拟合、P3 的大气压 / 温度补偿与 L_n / L_rel 换算、S3 的 1 h 温升留给离线合并或二期。
10. `HW_UNCONFIRMED`（命令已下发但硬件未在时限内确认）只提示、不自动重发，请核对属性卡 / 快照后再操作。
11. 合成自检项（T0Q / S1Q，`smoke.json`）显式关闭了 §0.4 门禁（`requiresPrecheck:false`），只用于联调 / 截图；正式方案项不得关闭。
7. 报告在应用内只显示汇总表；完整报告（基线表、SVG 曲线、附录）用浏览器打开 `report.html`。
8. 无头截图在 Linux 需安装 Noto CJK 字体；macOS 用 PingFang SC 兜底。

## 9. 截图 / 自动化模式

```bash
export PATH=$HOME/.dotnet:$PATH DOTNET_ROOT=$HOME/.dotnet
# 1) 模拟 HMI（autoGrantRemote=true 免触屏确认）
PR_SIM=1 PR_HEADLESS=1 PR_API=1 PR_API_PORT=18103 dotnet run --project ParallelReactor.csproj &
# 2) PC 端截图
PR_CONTROL_HEADLESS=1 PR_CONTROL_SHOT=/tmp/shots PR_CONTROL_DATA=/tmp/pcdata \
PR_CONTROL_URL=http://127.0.0.1:18103 PR_CONTROL_TOKEN=<operator 令牌> PR_CONTROL_SCENARIO=perf \
dotnet run --project Control/ParallelReactor.Control -c Debug
```

| 场景 | 动作 | 产出 |
|---|---|---|
| `main` | 连接 → 申请控制权 → 启用 RV1–4 → RV1 60 ℃ / RV2 80 ℃ → 搅拌 300 → RV3 / RV4 下发并运行 3 步程序 → 等 16 帧 → 截图 → 收尾（中止程序、停加热、停搅拌、释放） | `main-*.png` 7 张 |
| `perf` | 连接 → 控制权 → 性能测试视图 → 勾 S1Q + RV1 → `perf-checklist.png` → 开始 → Hold 中 `perf-running.png` → 等待录入 `perf-prompt.png` → 自动填 300 → 结束 `perf-finished.png` | 4 张 + 运行目录 |
| `perf-report` | 同上但勾 T0Q + S1Q（≈ 1 min）→ 全自动应答 → 报告视图 `perf-report.png`，并把 `report.html` 复制到截图目录 | 1 张 + `report.html` |

新界面（pc-v3 移植）的演示截图不需要 HMI：`Control/tools/shots.sh [输出目录] [尺寸 …]` 先构建一次 Debug（连同 Core / Client / Contracts，干净的检出也能跑），
再按尺寸（默认 1920x5100 1600x3900 1366x3900）各起一个无头进程，先跑审计自检、再按截图计划截图 + 审计 + 与样稿对照；macOS 上再用系统字体栈
（西文更窄，`PR_SHOTS_ALT_FONT` 可改，`none` 关闭）把每张截图审计一遍（`alt-font/`）。开跑前删掉上一次留下的审计结果、`error*.txt`、`shot*.log`，
最后列出所有非空的审计结果；配置与数据目录默认放在输出目录下，任何审计非空、进程失败或 `~/Library/Application Support` 里出现 ParallelReactor 目录时以非 0 退出。
审计（`Shot/ShotAudit.cs`）查字号（含输入框、自绘文字）、字重、画成方块的字、省略 / 丢行 / 溢出 / 裁切、读数被截断、步骤条被挤扁、
重叠（文字、控件、图标）、封闭色板（含 Run 的颜色）和横向滚动；`PR_CONTROL_AUDIT_SELFTEST=1` 逐类种下问题核对审计本身。
界面上的报警 / 说明句子用 `Theme/UiText.Keep`（不乱断行，并按当前字体选连接符：Avalonia 11.1 下 Inter 遇到 U+2060 会把后面的中文画成方块）。
令牌 / 图标由 `Control/tools/gen-tokens.py`、`gen-icons.py` 从样稿生成（`--check` 只核对不写）。

每个场景在截图目录写 `shot.log`（每条命令的 HTTP 状态码、opId、帧数、报告路径）。
